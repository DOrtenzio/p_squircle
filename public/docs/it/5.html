5.1 Da LWE a MLWE: la motivazione

LWE classico e il suo costo

Nel file 04 abbiamo visto LWE standard: dati \(m\) campioni \((\mathbf{a}_i, b_i)\) con \(\mathbf{a}_i \in \mathbb{Z}_q^n\) e \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), trovare \(\mathbf{s}\). Il problema è difficile, ma ha un costo pratico alto:

  • La chiave pubblica (la matrice \(A \in \mathbb{Z}_q^{m \times n}\)) ha dimensione \(O(n^2)\): per \(n = 1024\) e \(q = 3329\) sarebbero oltre 2 MB.
  • La moltiplicazione matrice-vettore \(A \cdot \mathbf{s}\) costa \(O(n^2)\) moltiplicazioni.

RLWE: troppo rigido

Ring-LWE porta le operazioni nell'anello \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Un singolo polinomio \(a \in R_q\) sostituisce l'intera matrice, riducendo la chiave pubblica a \(O(n)\).

Ma RLWE ha una struttura algebrica molto specifica che alcuni ricercatori considerano potenzialmente sfruttabile (anche se nessun attacco pratico è noto al 2024).

MLWE: il compromesso ottimale

Module-LWE generalizza entrambi usando una matrice \(k \times k\) di polinomi in \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Per \(k = 1\): si riduce a RLWE
  • Per \(k \to \infty\) (polinomi di grado 0): si riduce a LWE classico

Il parametro \(k\) permette di calibrare sicurezza e performance indipendentemente da \(n\).

Variante Chiave pubblica Sicurezza Flessibilità
LWE \(O(n^2)\) alta bassa
RLWE \(O(n)\) media bassa
MLWE \(O(k \cdot n)\) regolabile con \(k\) alta

5.2 Definizione formale di MLWE

Spazio di lavoro

Fissati i parametri:

  • \(n = 256\): grado del polinomio ciclotomico
  • \(q = 3329\): modulo primo
  • \(k \in \{2, 3, 4\}\): dimensione del modulo
  • \(\chi\): distribuzione del rumore (distribuzione binomiale centrata \(B_\eta\))

L'anello di base è \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Distribuzione MLWE

Sia \(\mathbf{s} \in R_q^k\) un vettore segreto di polinomi, ciascuno con coefficienti campionati da \(\chi\).

Una istanza MLWE è una coppia:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{dove} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

con \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Problema decisionale MLWE

Input: \((\mathbf{A}, \mathbf{t})\) dove:

  • sia \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (distribuzione MLWE), oppure
  • sia \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) uniforme

Obiettivo: distinguere i due casi con vantaggio non trascurabile.

Problema di ricerca MLWE

Input: \((\mathbf{A}, \mathbf{t})\) con \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Obiettivo: trovare \(\mathbf{s}\).

La riduzione di Regev (adattata a MLWE) dimostra che il problema di ricerca è computazionalmente equivalente al problema decisionale, e che entrambi sono almeno difficili quanto GapSVP su reticoli in alta dimensione.

5.3 La distribuzione del rumore in ML-KEM

Distribuzione binomiale centrata \(B_\eta\)

In ML-KEM il rumore non è gaussiano ma binomiale centrata. Per campionare un singolo coefficiente da \(B_\eta\):

  1. Campiona \(2\eta\) bit uniformi: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Restituisci \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

Il risultato è un intero in \([-\eta, \eta]\).

Distribuzione di probabilità per η = 2:

Valore Probabilità
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Perché non gaussiana vera?

La gaussiana discreta è teoricamente ottimale, ma campionarla in modo constant-time (resistente a timing attacks) è complesso. La binomiale centrata:

  • ha supporto finito → nessun caso estremo
  • si campiona con sole operazioni su bit → trivialmente constant-time
  • è indistinguibile statisticamente dalla gaussiana per gli attacchi noti

Campionamento in ML-KEM (funzione SamplePolyCBD)

CBD_η(σ, b): Input: seed σ ∈ {0,1}^256, nonce b ∈ {0,1}^8 Output: polinomio f ∈ R_q con coefficienti in [-η, η] bytes = PRF(σ, b) // SHAKE256, genera 64η byte per j = 0..255: a = somma dei bit di bytes nelle posizioni [2ηj .. 2ηj+η-1] b = somma dei bit di bytes nelle posizioni [2ηj+η .. 2ηj+2η-1] f[j] = a - b return f

Ogni polinomio \(\mathbf{s}[i]\) e \(\mathbf{e}[i]\) è campionato con nonce diverso, garantendo indipendenza statistica.

5.4 Campionamento in ML-KEM

CBD: Centered Binomial Distribution

ML-KEM usa una distribuzione binomiale centrata \(B_\eta\) per generare errori piccoli e segreti. Questa distribuzione è efficiente e non richiede rejection sampling.

Funzione SamplePolyCBD(σ, b, η)

Input: seed σ ∈ {0,1}^256, nonce b, parametro η
Output: polinomio f ∈ R_q con coeff. in [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, genera 64·η byte
2. For j = 0 to 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // conta gli 1 nel primo gruppo
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // conta gli 1 nel secondo gruppo
     f[j] = a - b                     // differenza centrata su 0
3. Return f

Per \(\eta=2\), i coefficienti sono in \(\{-2, -1, 0, 1, 2\}\). Per \(\eta=3\), in \(\{-3, \ldots, 3\}\).

SampleNTT: Campionamento Uniforme

Per generare la matrice pubblica \(\mathbf{A}\), servono coefficienti uniformi in \(\mathbb{Z}_q\). Si usa il rejection sampling sull'output di SHAKE128.

Funzione SampleNTT(stream)

Input: stream di byte da XOF (SHAKE128)
Output: polinomio con coeff. uniformi in [0, q-1]

coefficients = []
while len(coefficients) < 256:
    // Leggi 3 byte per generare 2 valori candidati
    b0, b1, b2 = next_3_bytes(stream)
    
    // Combina i bit per formare due numeri a 12 bit
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2
    
    // Accetta solo se < q (3329)
    if d1 < q:
        coefficients.append(d1)
    if d2 < q and len(coefficients) < 256:
        coefficients.append(d2)

return coefficients

Questo metodo garantisce una distribuzione uniforme perfetta, scartando i valori fuori range.

5.5 Hardness: perché MLWE è difficile

Riduzione worst-case a average-case

La proprietà più importante di LWE/MLWE è la riduzione worst-case to average-case:

Se esiste un algoritmo efficiente che risolve MLWE per una frazione non trascurabile di istanze casuali, allora esiste un algoritmo efficiente per risolvere GapSVP (la versione approssimata di SVP) su qualsiasi reticolo, nel caso peggiore.

Questa riduzione (Regev 2005, adattata da Peikert 2009 e Brakerski et al. per MLWE) è eccezionale: la maggior parte dei problemi crittografici ha solo riduzioni average-case to average-case.

In pratica: rompere MLWE su istanze casuali è difficile quanto risolvere SVP nel caso peggiore → le assunzioni crittografiche sono solidissime.

Assenza di struttura sfruttabile dai quantum

L'algoritmo di Shor sfrutta la struttura di gruppo abeliano dei problemi di fattorizzazione e logaritmo discreto: esiste un'azione di gruppo periodica che la QFT può rilevare.

MLWE non ha questa struttura:

  • Non c'è periodicità da sfruttare
  • Non c'è un gruppo abeliano naturale su cui applicare la QFT
  • I migliori algoritmi quantistici (basati su quantum walks o QRAM) offrono al più speedup polinomiale, non esponenziale

5.6 Da MLWE a un PKE: l'idea costruttiva

Come si costruisce un sistema di cifratura da MLWE? L'intuizione è elegante.

Analogia con Diffie-Hellman

In DH, la chiave pubblica è \(g^s\): facile da calcolare, difficile da invertire.
In MLWE, la chiave pubblica è \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): facile da calcolare, difficile da invertire.

Schema di cifratura (Regev-like)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Chiave pubblica: \((\mathbf{A}, \mathbf{t})\).
Chiave privata: \(\mathbf{s}\).

Encrypt (messaggio \(m \in \{0,1\}\), codificato come \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Ciphertext: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Analisi:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{rumore piccolo}} + \mu \approx \mu \]

Il rumore è piccolo → arrotondando si recupera \(\mu\) e quindi \(m\).

La versione polinomiale (MLWE reale)

In ML-KEM, ogni scalare diventa un polinomio in \(R_q\), e le operazioni sono prodotti polinomiali. Il meccanismo è identico, ma le moltiplicazioni avvengono nell'anello:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

dove \(\circ\) è la moltiplicazione in \(R_q\) (polinomiale, accelerata da NTT).

5.7 Esempio numerico completo

Usiamo parametri giocattolo: \(n = 4\), \(q = 17\), \(k = 2\), coefficienti piccoli in \(\{-1, 0, 1\}\).

I polinomi sono in \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), quindi di grado \(\leq 3\).

Dati di partenza

Matrice pubblica \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

con \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Segreto \(\mathbf{s} = (s_0, s_1)^T\) con \(s_0 = 1 - X\), \(s_1 = X^2\).

Errore \(\mathbf{e} = (e_0, e_1)^T\) con \(e_0 = 1\), \(e_1 = -X\).

Calcolo di t = As + e

Componente t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Riduciamo \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Risultato: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (la seconda componente si calcola analogamente).

Osservazione chiave

Un avversario che vede \((\mathbf{A}, \mathbf{t})\) deve trovare \((\mathbf{s}, \mathbf{e})\). Anche con questi numeri piccoli, il problema è già non banale: non può usare eliminazione gaussiana (l'errore rompe la linearità) e lo spazio di ricerca è esponenziale nella dimensione reale di ML-KEM.

5.8 Perché i parametri di ML-KEM sono quelli che sono

\(n = 256\)

  • Deve essere una potenza di 2 (per NTT efficiente)
  • Il polinomio \(X^{256}+1\) deve essere irriducibile su \(\mathbb{Z}_q\): lo è se \(q \equiv 1 \pmod{512}\)
  • \(256\) bilancia sicurezza e performance: \(n = 128\) sarebbe troppo insicuro, \(n = 512\) troppo lento

\(q = 3329\)

  • Deve essere primo (per \(\mathbb{Z}_q\) campo)
  • Deve soddisfare \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Deve essere tale che esistano radici 256-esime dell'unità: garantito dalla condizione sopra
  • Deve essere il più piccolo possibile (chiavi compatte) compatibilmente con il budget del rumore
  • \(3329\) è il primo che soddisfa tutte le condizioni con abbastanza margine per il rumore

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): livello 1 NIST, equivalente ad AES-128 pre-quantum
  • \(k = 3\) (ML-KEM-768): livello 3, equivalente ad AES-192, raccomandato per uso generale
  • \(k = 4\) (ML-KEM-1024): livello 5, equivalente ad AES-256, per sistemi ad alta criticità

\(\eta_1, \eta_2 \in \{2, 3\}\)

Il rumore deve essere:

  • abbastanza grande da rendere difficile il problema MLWE
  • abbastanza piccolo da garantire che la decifratura non fallisca (budget del rumore)

Aumentare \(\eta\) aumenta la sicurezza ma anche la probabilità di errore di decifratura. I valori \(\eta_1 = 2, \eta_2 = 2\) per ML-KEM-768 sono il punto ottimale.
