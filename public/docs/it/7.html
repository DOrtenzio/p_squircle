07 – NTT (Number Theoretic Transform)

Il motore che rende ML-KEM praticamente utilizzabile

7.1 Il problema: moltiplicare polinomi

In ML-KEM, le operazioni fondamentali coinvolgono moltiplicazioni di polinomi nell'anello \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Moltiplicazione naïve

Due polinomi di grado \(n-1\) si moltiplicano con l'algoritmo scolastico in complessità \(O(n^2)\).

  • Per \(n = 256\): circa \(256^2 = 65536\) moltiplicazioni per singolo prodotto.
  • In ML-KEM-768 (\(k=3\)), una singola operazione Encaps richiede decine di prodotti polinomiali → milioni di moltiplicazioni con il metodo naïve.

Con NTT

La complessità scende a \(O(n \log n)\):

\[ 256 \cdot 8 = 2048 \text{ operazioni per prodotto} \]

Speedup: ~32×. Su hardware ottimizzato, ML-KEM-768 impiega meno di 1 ms.

7.2 Trasformate di Fourier e DFT

Il teorema di convoluzione

La trasformata di Fourier trasforma una convoluzione (come la moltiplicazione di polinomi) in un prodotto puntuale:

\[ f * g \;\longleftrightarrow\; \hat{f} \cdot \hat{g} \]

Procedimento:

  1. Calcola \(\hat{f} = \text{DFT}(f)\) e \(\hat{g} = \text{DFT}(g)\)
  2. Moltiplica puntualmente: \(\hat{h}_i = \hat{f}_i \cdot \hat{g}_i\)
  3. Antitrasforma: \(h = \text{DFT}^{-1}(\hat{h})\)

Se DFT e DFT-1 costano \(O(n \log n)\) (tramite FFT), l'intera moltiplicazione costa \(O(n \log n)\).

Fast Fourier Transform (FFT)

L'algoritmo Cooley-Tukey (1965) calcola la DFT sfruttando la struttura ricorsiva:

\[ \text{DFT}[f] = \left(\text{DFT}[f_{\text{pari}}], \; \text{DFT}[f_{\text{dispari}}]\right) \text{ combinati con twiddle factors} \]

Il problema: La FFT standard usa numeri complessi (floating point), che introducono errori di arrotondamento e timing non costante, rendendoli inadatti alla crittografia.

7.3 NTT: DFT nel mondo modulare

L'idea

La NTT (Number Theoretic Transform) è la DFT applicata a \(\mathbb{Z}_q\) invece di \(\mathbb{C}\). Invece di usare le radici dell'unità complesse \(e^{2\pi i k/n}\), si usano le radici primitive dell'unità in \(\mathbb{Z}_q\).

Radici primitive dell'unità modulo q

Un elemento \(\omega \in \mathbb{Z}_q\) è una radice \(n\)-esima primitiva dell'unità se:

\[ \omega^n \equiv 1 \pmod{q} \quad \text{e} \quad \omega^k \not\equiv 1 \pmod{q} \text{ per } 0 < k < n \]

Condizione necessaria: \(n \mid (q-1)\) (cioè \(n\) deve dividere \(q-1\)).

In ML-KEM:

  • \(q = 3329\), \(n = 256\)
  • Verifica: \(3329 - 1 = 3328 = 256 \cdot 13\) \(\checkmark\)
  • Esistono quindi radici 256-esime dell'unità modulo 3329.
  • La radice primitiva usata in FIPS 203: \(\omega = 17\) (poiché \(17^{128} \equiv -1 \pmod{3329}\), la radice usata per NTT negacyclica è \(\zeta = 17\)).

Definizione NTT

\[ \hat{f}_i = \text{NTT}(f)_i = \sum_{j=0}^{n-1} f_j \cdot \omega^{ij} \pmod{q} \]

Inverse NTT:

\[ f_j = \text{NTT}^{-1}(\hat{f})_j = n^{-1} \sum_{i=0}^{n-1} \hat{f}_i \cdot \omega^{-ij} \pmod{q} \]

dove \(n^{-1} = 256^{-1} \bmod 3329 = 3303\).

Proprietà chiave

  • Esatta: nessun errore di arrotondamento, tutto in \(\mathbb{Z}_q\)
  • Efficiente: \(O(n \log n)\) come FFT
  • Costante nel tempo: implementabile senza branch su dati segreti (sicurezza side-channel)

7.4 NTT in ML-KEM

NTT negacyclica

In ML-KEM, la riduzione non è modulo \(X^n - 1\) (ciclica), ma modulo \(X^n + 1\) (negacyclica). Nella convoluzione negacyclica, i termini "avvolti" cambiano segno. Questo richiede una variante della NTT classica con fattori di torsione (twiddle factors) aggiustati.

La NTT in FIPS 203 applica preventivamente una pre-torsione con potenze di \(\zeta = 17\):

\[ \tilde{f}_j = f_j \cdot \zeta^j \bmod q \quad \text{prima di NTT classica} \]

Operazioni ML-KEM in dominio NTT

Una volta trasformati, i polinomi vivono nel dominio NTT. Le operazioni diventano elementari:

Operazione Nel dominio NTT
Moltiplicazione \(f \cdot g\) \(\hat{f}_i \cdot \hat{g}_i\) per ogni \(i\)
Somma \(f + g\) \(\hat{f}_i + \hat{g}_i\) per ogni \(i\)
Prodotto matrice-vettore \(A \cdot s\) \(k^2\) prodotti e \(k^2\) somme puntuali

La chiave pubblica \(A\) è generata e memorizzata già in dominio NTT, evitando di ricalcolare la NTT ogni volta.

Flusso completo di KeyGen

seed 
  │
  ├──► SHAKE128 ──► A_hat (già in NTT)
  │
  └──► Campionamento binomiale ──► s, e
         │              │
         ▼              ▼
     s_hat = NTT(s)   e_hat = NTT(e)
         │              │
         └──────┬───────┘
                ▼
     t_hat = A_hat * s_hat + e_hat
                │
                ▼
          Chiave Pubblica (t_hat)

L'output t_hat è la chiave pubblica (già in NTT). Si evita la NTT-1 per \(t\).

7.5 Esempio numerico semplificato

Usiamo \(n = 4\), \(q = 5\), \(\omega = 2\) (radice 4-esima di 1 modulo 5: \(2^4 = 16 \equiv 1 \pmod 5\)).

Polinomi:

\[ f = 1 + 2X + 3X^2 + 4X^3 \quad \Rightarrow \quad \mathbf{f} = (1, 2, 3, 4) \]
\[ g = 1 + X + X^2 + X^3 \quad \Rightarrow \quad \mathbf{g} = (1, 1, 1, 1) \]

NTT di f:

  • \(\hat{f}_0 = 1 + 2 + 3 + 4 = 10 \equiv 0\)
  • \(\hat{f}_1 = 1 + 2 \cdot 2 + 3 \cdot 4 + 4 \cdot 8 = 49 \equiv 4\)
  • \(\hat{f}_2 = 1 + 2 \cdot 4 + 3 \cdot 16 + 4 \cdot 64 = 313 \equiv 3\)
  • \(\hat{f}_3 = 1 + 2 \cdot 8 + 3 \cdot 64 + 4 \cdot 512 = 2257 \equiv 2\)

NTT di g: \(\hat{g}_i = \sum_j \omega^{ij} \pmod 5\). Per \(i=0\): \(4 \equiv 4\); per \(i \neq 0\): somma di radici \(= 0\).

Prodotto puntuale: \(\hat{h}_i = \hat{f}_i \cdot \hat{g}_i \pmod 5\).

INTT di \(\hat{h}\): dà il prodotto \(f \cdot g \bmod (X^4-1, 5)\).

Nota: questo esempio usa riduzione modulo \(X^4-1\) (ciclica). ML-KEM usa \(X^n+1\) (negacyclica) con la variante descritta nella sezione 7.4.

7.6 Implementazione

Pseudocodice Cooley-Tukey per NTT

def ntt(f, q, omega):
    """
    NTT iterativa in-place (Cooley-Tukey).
    f: lista di n coefficienti in Z_q
    q: modulo primo
    omega: radice n-esima primitiva dell'unità mod q
    """
    n = len(f)
    # bit-reversal permutation
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            f[i], f[j] = f[j], f[i]

    # butterfly operations
    length = 2
    while length <= n:
        w = pow(omega, n // length, q)
        for i in range(0, n, length):
            wn = 1
            for k in range(length // 2):
                u = f[i + k]
                v = f[i + k + length // 2] * wn % q
                f[i + k] = (u + v) % q
                f[i + k + length // 2] = (u - v) % q
                wn = wn * w % q
        length <<= 1
    return f

Implementazione di riferimento

FIPS 203 specifica l'esatta implementazione NTT e la tabella delle radici precomputate \(\zeta^{br(i)}\) (dove \(br\) è la permutazione bit-reversal).

Implementazioni ottimizzate in assembly/SIMD sono disponibili in:

  • liboqs (C con AVX2)
  • pqclean (C portabile)
  • kyber reference implementation (C)
