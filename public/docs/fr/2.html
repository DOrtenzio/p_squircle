02 – Asymmetric Cryptography

The foundation of classical security and its quantum limit

2.1 The key exchange problem

Alice wants to communicate securely with Bob over a public channel. To use AES, they need a shared key. How do they establish it without Eve (who is listening to everything) discovering it?

This problem remained unsolved for centuries. The solution arrived in 1976 with Diffie and Hellman, and in 1977 with Rivest, Shamir, and Adleman (RSA).

The key idea: there are mathematical operations that are easy in one direction, hard in the other.

Easy operation Hard operation
Multiplying two large primes: \(p \cdot q = n\) Factoring \(n\) to find \(p\) and \(q\)
Computing \(g^x \bmod p\) Finding \(x\) given \(g^x \bmod p\) (discrete logarithm)
Adding a point on an elliptic curve \(k\) times: \(kP\) Finding \(k\) given \(kP\) (ECDLP)

2.2 RSA

Key Generation

  1. Choose two large prime numbers \(p\) and \(q\) (typically 2048+ bits each)
  2. Compute \(n = p \cdot q\)
  3. Compute \(\phi(n) = (p-1)(q-1)\)
  4. Choose \(e\) such that \(\gcd(e, \phi(n)) = 1\) (typically \(e = 65537\))
  5. Compute \(d = e^{-1} \bmod \phi(n)\)

Public key: \((n, e)\)
Private key: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) must be destroyed.

Encryption and Decryption

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Why it works: by Euler's theorem, \(M^{\phi(n)} \equiv 1 \pmod{n}\), therefore \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Numerical Example (with small numbers, for educational purposes only)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(since } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Let's encrypt \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Let's decrypt:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA as KEM

RSA-KEM (simplified):

  1. Bob randomly generates \(r \leftarrow \{1, \ldots, n-1\}\)
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (symmetric key)
  4. Sends \(C\) to Alice
  5. Alice computes \(r = C^d \bmod n\), then \(K = H(r)\)

2.3 Diffie-Hellman (DH)

The Protocol

Public parameters: a large prime \(p\) and a generator \(g\) of \(\mathbb{Z}_p^*\).

Alice
  1. Chooses a secret \(a\)
  2. Computes \(A = g^a \bmod p\)
A → ← B
Bob
  1. Chooses a secret \(b\)
  2. Computes \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Alice computes: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Bob computes: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Result: Both share the same secret key \(K\). Eve, who only sees \(A\) and \(B\), cannot compute \(K\) without solving the discrete logarithm problem.

2.4 Elliptic Curve Cryptography (ECDH)

ECDH is the elliptic curve analogue of DH. It is used in TLS 1.3 with the X25519 curve.

Alice
  1. Chooses a secret \(a\)
  2. Computes \(A = a \cdot G\)
A → ← B
Bob
  1. Chooses a secret \(b\)
  2. Computes \(B = b \cdot G\)
\[ \begin{aligned} \text{Alice computes: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Bob computes: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Where \(G\) is the generator point of the curve. Security is based on the hardness of the ECDLP (Elliptic Curve Discrete Logarithm Problem).

2.4 Elliptic Curve Cryptography (ECC)

What Elliptic Curves Are

An elliptic curve over \(\mathbb{Z}_p\) is the set of points \((x, y)\) that satisfy:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

plus a special point \(\mathcal{O}\) called the point at infinity.

An addition operation with group properties is defined on these points.

Scalar Multiplication

Given the addition of points, scalar multiplication is defined as:

\(kP = P + P + \cdots + P \quad (k \text{ times})\)

Computing \(kP\) from \(P\) and \(k\) is easy (\(O(\log k)\) operations). The inverse problem – finding \(k\) given \(P\) and \(kP\) – is the Elliptic Curve Discrete Logarithm Problem (ECDLP), which is computationally hard.

Advantages of ECC compared to DH/RSA

Equivalent Security RSA/DH (bits of n/p) ECC (key bits)
80 bits 1024 160
128 bits 3072 256
256 bits 15360 512

ECC offers much smaller keys for the same level of security → making it more efficient.

ECDH (Elliptic Curve Diffie-Hellman)

Alice Bob | | | chooses secret a | chooses secret b | A = aG | B = bG | | | ------------ A ----------->| | | | <------------ B -----------| | | | K = aB = abG | K = bA = abG | | | ✓ shared key K |

ECDH is used in TLS 1.3 with the X25519 curve (Bernstein's curve25519).

2.5 Classical security and quantum limits

Against Classical Computers

The problems on which RSA and ECC are based are subexponential (not purely exponential) for classical computers.

The best classical algorithm for factorization is the General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

For an \(n\) of 2048 bits, this requires an astronomically long time → secure in practice.

Against Quantum Computers: Shor's Algorithm

In 1994, Peter Shor demonstrated that a quantum computer can:

  • Factor \(n\) in \(O((\log n)^3)\) time
  • Solve the DLP in \(O((\log p)^3)\) time
  • Solve the ECDLP in \(O((\log p)^3)\) time

A quantum computer with enough qubits would break RSA-2048 in hours or days.

The detailed analysis of Shor's algorithm can be found in the file 03 – Shor's Algorithm.

The Answer: Post-Quantum Cryptography

To continue having secure asymmetric cryptography in the quantum era, we need mathematical problems that do not have known efficient quantum algorithms.

Lattice-based problems, on which ML-KEM is built, satisfy this requirement: the best known quantum algorithms offer at most a modest speedup compared to classical algorithms.
