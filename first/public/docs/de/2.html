Das Fundament der klassischen Sicherheit und ihre quantenmechanische Grenze

2.1 Das Problem des Schlüsselaustauschs

Alice möchte sicher mit Bob über einen öffentlichen Kanal kommunizieren. Für die Verwendung von AES wird ein gemeinsamer Schlüssel benötigt. Wie können sie ihn festlegen, ohne dass Eve (die alles mithört) ihn herausfindet?

Dieses Problem war jahrhundertelang ungelöst. Die Lösung kam 1976 mit Diffie und Hellman und 1977 mit Rivest, Shamir und Adleman (RSA).

Die Schlüsselidee: Es gibt mathematische Operationen, die in einer Richtung einfach, in der anderen schwer sind.

Einfache Operation Schwere Operation
Multiplikation zweier großer Primzahlen: \(p \cdot q = n\) Faktorisierung von \(n\) zur Bestimmung von \(p\) und \(q\)
Berechnung von \(g^x \bmod p\) Bestimmung von \(x\) aus \(g^x \bmod p\) (diskreter Logarithmus)
\(k\)-fache Addition eines Punkts auf einer elliptischen Kurve: \(kP\) Bestimmung von \(k\) aus \(kP\) (ECDLP)

2.2 RSA

Schlüsselgenerierung

  1. Wähle zwei große Primzahlen \(p\) und \(q\) (typischerweise jeweils 2048+ Bit)
  2. Berechne \(n = p \cdot q\)
  3. Berechne \(\phi(n) = (p-1)(q-1)\)
  4. Wähle \(e\) mit \(\gcd(e, \phi(n)) = 1\) (typischerweise \(e = 65537\))
  5. Berechne \(d = e^{-1} \bmod \phi(n)\)

Öffentlicher Schlüssel: \((n, e)\)
Privater Schlüssel: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) müssen vernichtet werden.

Verschlüsselung und Entschlüsselung

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Warum es funktioniert: Nach dem Satz von Euler gilt \(M^{\phi(n)} \equiv 1 \pmod{n}\), also \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Numerisches Beispiel (mit kleinen Zahlen, nur zu Lehrzwecken)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(weil } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Verschlüsseln wir \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Entschlüsseln wir:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA als KEM

RSA-KEM (vereinfacht):

  1. Bob wählt zufällig \(r \leftarrow \{1, \ldots, n-1\}\)
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (symmetrischer Schlüssel)
  4. Sendet \(C\) an Alice
  5. Alice berechnet \(r = C^d \bmod n\), dann \(K = H(r)\)

2.3 Diffie-Hellman (DH)

Das Protokoll

Öffentliche Parameter: eine große Primzahl \(p\) und ein Generator \(g\) von \(\mathbb{Z}_p^*\).

Alice
  1. Wählt geheimes \(a\)
  2. Berechnet \(A = g^a \bmod p\)
A → ← B
Bob
  1. Wählt geheimes \(b\)
  2. Berechnet \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Alice berechnet: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Bob berechnet: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Ergebnis: Beide teilen denselben geheimen Schlüssel \(K\). Eve, die nur \(A\) und \(B\) sieht, kann \(K\) nicht berechnen, ohne das Problem des diskreten Logarithmus zu lösen.

2.4 Elliptische-Kurven-Kryptographie (ECDH)

ECDH ist das Analogon zu DH auf elliptischen Kurven. Es wird in TLS 1.3 mit der Kurve X25519 verwendet.

Alice
  1. Wählt geheimes \(a\)
  2. Berechnet \(A = a \cdot G\)
A → ← B
Bob
  1. Wählt geheimes \(b\)
  2. Berechnet \(B = b \cdot G\)
\[ \begin{aligned} \text{Alice berechnet: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Bob berechnet: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Wobei \(G\) der Generatorpunkt der Kurve ist. Die Sicherheit basiert auf der Schwierigkeit des ECDLP (Elliptic Curve Discrete Logarithm Problem).

Was sind elliptische Kurven

Eine elliptische Kurve über \(\mathbb{Z}_p\) ist die Menge der Punkte \((x, y)\), die erfüllen:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

plus einem speziellen Punkt \(\mathcal{O}\), dem Punkt im Unendlichen.

Auf diesen Punkten wird eine Additions-Operation mit Gruppeneigenschaften definiert.

Skalarmultiplikation

Mit der Punktaddition wird die Skalarmultiplikation definiert:

\(kP = P + P + \cdots + P \quad (k \text{-mal})\)

Die Berechnung von \(kP\) aus \(P\) und \(k\) ist einfach (\(O(\log k)\) Operationen). Das inverse Problem – die Bestimmung von \(k\) aus \(P\) und \(kP\) – ist das Elliptic Curve Discrete Logarithm Problem (ECDLP), das rechnerisch schwer ist.

Vorteile von ECC gegenüber DH/RSA

Äquivalente Sicherheit RSA/DH (Bit von n/p) ECC (Schlüsselbit)
80 Bit 1024 160
128 Bit 3072 256
256 Bit 15360 512

ECC bietet viel kleinere Schlüssel bei gleicher Sicherheit → effizienter.

ECDH (Elliptic Curve Diffie-Hellman)

Alice Bob | | | wählt geheimes a | wählt geheimes b | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ gemeinsamer Schlüssel K |

ECDH wird in TLS 1.3 mit der Kurve X25519 (Curve25519 von Bernstein) verwendet.

2.5 Klassische Sicherheit und quantenmechanische Grenzen

Gegen klassische Computer

Die Probleme, auf denen RSA und ECC basieren, sind für klassische Computer subexponentiell (nicht rein exponentiell).

Der beste klassische Algorithmus für die Faktorisierung ist das General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

Für \(n\) mit 2048 Bit benötigt dies astronomisch lange Zeit → in der Praxis sicher.

Gegen Quantencomputer: Shors Algorithmus

1994 zeigte Peter Shor, dass ein Quantencomputer:

  • Faktorisieren von \(n\) in Zeit \(O((\log n)^3)\)
  • DLP lösen in Zeit \(O((\log p)^3)\)
  • ECDLP lösen in Zeit \(O((\log p)^3)\)

Ein Quantencomputer mit genügend Qubits würde RSA-2048 in Stunden oder Tagen brechen.

Die detaillierte Analyse von Shors Algorithmus findet sich in Datei 03 – Shors Algorithmus.

Die Antwort: Post-Quanten-Kryptographie

Um auch im Quantenzeitalter über sichere asymmetrische Kryptographie zu verfügen, werden mathematische Probleme benötigt, für die keine effizienten Quantenalgorithmen bekannt sind.

Die Gitterprobleme (Lattice), auf denen ML-KEM basiert, erfüllen diese Anforderung: Die besten bekannten Quantenalgorithmen bieten höchstens eine moderate Beschleunigung gegenüber klassischen Algorithmen.
