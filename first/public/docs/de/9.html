09 – Sicherheit und Parameter

Warum ML-KEM sicher ist und wie die Zahlen gewählt wurden

9.1 Sicherheitsmodelle

IND-CPA (Indistinguishability under Chosen Plaintext Attack)

In diesem Modell:

  1. Erhält der Angreifer den öffentlichen Schlüssel \(ek\)
  2. Wählt er zwei Nachrichten \(m_0, m_1\)
  3. Erhält er das Chiffrat einer der beiden (zufällig ausgewählt)
  4. Muss er erraten, welche Nachricht verschlüsselt wurde

Das Schema ist sicher, wenn: \(\Pr[\text{errät}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (die zugrundeliegende Verschlüsselungskomponente) ist unter der MLWE-Annahme IND-CPA.

IND-CCA2 (Indistinguishability under Adaptive Chosen Ciphertext Attack)

Wie CPA, aber der Angreifer kann zusätzlich ein Entschlüsselungsorakel für beliebige Chiffrate abfragen (außer dem Challenge-Chiffrat). Dieses Modell erfasst reale Angriffe (wie Bleichenbacher), bei denen ein aktiver Angreifer maßgeschneiderte Nachrichten sendet und die Antworten beobachtet.

ML-KEM ist IND-CCA2. Dies ist das für ein sicheres KEM in realen Protokollen wie TLS oder SSH erforderliche Niveau.

ROM vs. QROM

Die Sicherheitsbeweise verwenden idealisierte Modelle für Hash-Funktionen:

  • ROM (Random Oracle Model): Die Hashes sind perfekte Zufallsorakel.
  • QROM (Quantum Random Oracle Model): Der Quantenangreifer kann das Orakel in Superposition abfragen.

Die modernen Beweise für die in ML-KEM verwendete FO-Transformation (Fujisaki-Okamoto) garantieren Sicherheit im QROM, was gegen Quantenangreifer unerlässlich ist.

9.2 Messung der Schwierigkeit von MLWE

Sicherheit als Kosten des Angriffs

Es gibt keinen absoluten Beweis, dass MLWE schwierig ist. Die Sicherheit wird geschätzt, indem die Kosten des besten bekannten Angriffsalgorithmus berechnet werden. Eine Sicherheit von \(\lambda\) Bit bedeutet, dass der Angriff etwa \(2^\lambda\) Operationen erfordert.

Die Parameter

Die Schwierigkeit hängt ab von:

  • \(n = 256\) (Polynomdimension, fest)
  • \(k \in \{2, 3, 4\}\) (Modul-Dimension)
  • \(q = 3329\) (Primmodul)
  • \(\eta \in \{2, 3\}\) (Rauschamplitude)

Lattice Estimator

Das Standardwerkzeug ist der Lattice Estimator von Albrecht et al. Für ML-KEM-768:

Angriff Geschätzte Kosten (Bit)
Primal Attack (BKZ) ~178 Bit
Dual Attack ~175 Bit
Kombinatorisch > 200 Bit

Die Sicherheitsmarge ist im Vergleich zum Ziel von 128 Bit klassisch/quantisch groß.

9.3 Hauptangriffe auf Gitter

BKZ (Block Korkine-Zolotarev)

Dies ist der beste allgemeine Algorithmus zum Finden kurzer Vektoren. Er teilt das Gitter in Blöcke der Größe \(\beta\) auf und löst SVP lokal. Komplexität: \(2^{O(\beta \log \beta)}\). Für ML-KEM-768: \(\beta \approx 430\).

Primal Attack (uSVP)

Reduziert MLWE auf ein Problem des kurzen Vektors in einem erweiterten Gitter, das den öffentlichen Schlüssel und das Chiffrat enthält. Der geheime Vektor \((\mathbf{s}, \mathbf{e}, -1)\) wird zu einem kurzen Vektor, den BKZ zu finden versucht.

Dual Attack

Nutzt das duale Gitter aus, um MLWE-Stichproben von gleichverteilten mittels Statistik zu unterscheiden. Es konstruiert viele kurze Vektoren im Dualen, um den Unterscheider durchzuführen.

Wahl von q = 3329

Da es prim ist und keine spezielle algebraische Struktur aufweist, verhindert es spezifische algebraische Angriffe. Es gibt keine kleinen Faktoren oder einfachen Beziehungen, die ausgenutzt werden könnten.

9.4 NIST-Sicherheitsstufen

NIST hat 5 Stufen definiert. ML-KEM deckt die Stufen 1, 3 und 5 ab:

Schema NIST-Stufe Klassische Sicherheit Quantensicherheit
ML-KEM-512 1 (AES-128) ~118 Bit ~100 Bit
ML-KEM-768 3 (AES-192) ~178 Bit ~164 Bit
ML-KEM-1024 5 (AES-256) ~230 Bit ~218 Bit

Empfehlung: ML-KEM-768 bietet das optimale Gleichgewicht zwischen Sicherheit und Leistung für die meisten Anwendungen. ML-KEM-1024 ist für hochkritische Systeme reserviert.

9.6 Seitenkanäle und sichere Implementierungen

Eine korrekte Implementierung kann verwundbar sein, wenn Informationen über die Ausführungszeit (Timing-Angriffe) oder den Stromverbrauch preisgegeben werden.

Zeitkonstanz (Constant-Time, CT)

Alle Operationen müssen unabhängig von geheimen Daten eine konstante Laufzeit haben. Ein kritisches Beispiel in Decaps:

// NICHT sicher (variable Laufzeit):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Sicher (zeitkonstant):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF bei Gleichheit, 0x00 bei Ungleichheit
K = ct_select(mask, K_good, K_reject);     // CT-Auswahl ohne Verzweigung

Kritische Bereiche für CT in ML-KEM

  • Sampling \(B_\eta\): Addition von Bits ohne bedingte Verzweigungen.
  • NTT: Butterfly-Operationen müssen immer ausgeführt werden, auch wenn sich das Ergebnis nicht ändert.
  • Chiffrat-Verifikation: Verwendung von ct_memcmp.

Referenzimplementierungen

  • pqclean: portable CT-Implementierungen.
  • liboqs: AVX2-Optimierungen mit verifizierten CT-Eigenschaften.
