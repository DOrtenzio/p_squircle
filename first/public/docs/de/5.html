5.1 Von LWE zu MLWE: die Motivation

Klassisches LWE und seine Kosten

In Datei 04 haben wir Standard-LWE gesehen: Gegeben \(m\) Stichproben \((\mathbf{a}_i, b_i)\) mit \(\mathbf{a}_i \in \mathbb{Z}_q^n\) und \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), finde \(\mathbf{s}\). Das Problem ist schwierig, hat aber in der Praxis hohe Kosten:

  • Der öffentliche Schlüssel (die Matrix \(A \in \mathbb{Z}_q^{m \times n}\)) hat die Größe \(O(n^2)\): für \(n = 1024\) und \(q = 3329\) wären das über 2 MB.
  • Die Matrix-Vektor-Multiplikation \(A \cdot \mathbf{s}\) kostet \(O(n^2)\) Multiplikationen.

RLWE: zu starr

Ring-LWE überführt die Operationen in den Ring \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Ein einzelnes Polynom \(a \in R_q\) ersetzt die gesamte Matrix und reduziert den öffentlichen Schlüssel auf \(O(n)\).

Aber RLWE hat eine sehr spezifische algebraische Struktur, die einige Forscher für potenziell ausnutzbar halten (obwohl bis 2024 kein praktischer Angriff bekannt ist).

MLWE: der optimale Kompromiss

Module-LWE verallgemeinert beide, indem es eine \(k \times k\)-Matrix von Polynomen in \(R_q\) verwendet:

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Für \(k = 1\): reduziert sich auf RLWE
  • Für \(k \to \infty\) (Polynome vom Grad 0): reduziert sich auf klassisches LWE

Der Parameter \(k\) ermöglicht es, Sicherheit und Leistung unabhängig von \(n\) zu kalibrieren.

Variante Öffentlicher Schlüssel Sicherheit Flexibilität
LWE \(O(n^2)\) hoch niedrig
RLWE \(O(n)\) mittel niedrig
MLWE \(O(k \cdot n)\) mit \(k\) einstellbar hoch

5.2 Formale Definition von MLWE

Arbeitsraum

Gegeben die Parameter:

  • \(n = 256\): Grad des zyklotomischen Polynoms
  • \(q = 3329\): Primmodul
  • \(k \in \{2, 3, 4\}\): Modul-Dimension
  • \(\chi\): Rauschverteilung (zentrierte Binomialverteilung \(B_\eta\))

Der Basisring ist \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

MLWE-Verteilung

Sei \(\mathbf{s} \in R_q^k\) ein geheimer Vektor von Polynomen, deren Koeffizienten aus \(\chi\) gezogen werden.

Eine MLWE-Instanz ist ein Paar:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{mit} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

mit \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Entscheidungs-MLWE-Problem

Eingabe: \((\mathbf{A}, \mathbf{t})\) wobei:

  • entweder \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (MLWE-Verteilung), oder
  • \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) gleichverteilt

Ziel: Unterscheide die beiden Fälle mit nicht vernachlässigbarem Vorteil.

Such-MLWE-Problem

Eingabe: \((\mathbf{A}, \mathbf{t})\) mit \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Ziel: finde \(\mathbf{s}\).

Die Reduktion von Regev (angepasst an MLWE) zeigt, dass das Suchproblem dem Entscheidungsproblem rechnerisch äquivalent ist und dass beide mindestens so schwer sind wie GapSVP auf hochdimensionalen Gittern.

5.3 Die Rauschverteilung in ML-KEM

Zentrierte Binomialverteilung \(B_\eta\)

In ML-KEM ist das Rauschen nicht gaußsch, sondern zentriert binomial. Um einen einzelnen Koeffizienten aus \(B_\eta\) zu sampeln:

  1. Sampel \(2\eta\) uniforme Bits: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Gib \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\) zurück

Das Ergebnis ist eine ganze Zahl in \([-\eta, \eta]\).

Wahrscheinlichkeitsverteilung für η = 2:

Wert Wahrscheinlichkeit
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Warum keine echte Gauß-Verteilung?

Die diskrete Gauß-Verteilung ist theoretisch optimal, aber ihre zeitkonstante Stichprobennahme (resistenz gegen Timing-Angriffe) ist komplex. Die zentrierte Binomialverteilung:

  • hat endlichen Träger → keine Extremfälle
  • wird mit reinen Bit-Operationen gesampelt → trivial zeitkonstant
  • ist für bekannte Angriffe statistisch von der Gauß-Verteilung nicht unterscheidbar

Stichprobennahme in ML-KEM (Funktion SamplePolyCBD)

CBD_η(σ, b): Eingabe: Seed σ ∈ {0,1}^256, Nonce b ∈ {0,1}^8 Ausgabe: Polynom f ∈ R_q mit Koeffizienten in [-η, η] bytes = PRF(σ, b) // SHAKE256, erzeugt 64η Byte für j = 0..255: a = Summe der Bits von bytes an den Positionen [2ηj .. 2ηj+η-1] b = Summe der Bits von bytes an den Positionen [2ηj+η .. 2ηj+2η-1] f[j] = a - b return f

Jedes Polynom \(\mathbf{s}[i]\) und \(\mathbf{e}[i]\) wird mit einer anderen Nonce gesampelt, was statistische Unabhängigkeit garantiert.

5.4 Stichprobennahme in ML-KEM

CBD: Centered Binomial Distribution

ML-KEM verwendet eine zentrierte Binomialverteilung \(B_\eta\), um kleine Fehler und Geheimnisse zu erzeugen. Diese Verteilung ist effizient und benötigt kein Rejection Sampling.

Funktion SamplePolyCBD(σ, b, η)

Eingabe: Seed σ ∈ {0,1}^256, Nonce b, Parameter η
Ausgabe: Polynom f ∈ R_q mit Koeff. in [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, erzeugt 64·η Byte
2. Für j = 0 bis 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // zähle die 1en in der ersten Gruppe
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // zähle die 1en in der zweiten Gruppe
     f[j] = a - b                     // auf 0 zentrierte Differenz
3. Return f

Für \(\eta=2\) liegen die Koeffizienten in \(\{-2, -1, 0, 1, 2\}\). Für \(\eta=3\) in \(\{-3, \ldots, 3\}\).

SampleNTT: Gleichverteilte Stichprobennahme

Zur Erzeugung der öffentlichen Matrix \(\mathbf{A}\) werden gleichverteilte Koeffizienten in \(\mathbb{Z}_q\) benötigt. Dazu wird Rejection Sampling auf der Ausgabe von SHAKE128 verwendet.

Funktion SampleNTT(stream)

Eingabe: Byte-Stream von XOF (SHAKE128)
Ausgabe: Polynom mit gleichverteilten Koeff. in [0, q-1]

koeffizienten = []
while len(koeffizienten) < 256:
    // Lese 3 Byte, um 2 Kandidatenwerte zu erzeugen
    b0, b1, b2 = next_3_bytes(stream)
    
    // Kombiniere die Bits zu zwei 12-Bit-Zahlen
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2
    
    // Akzeptiere nur, wenn < q (3329)
    if d1 < q:
        koeffizienten.append(d1)
    if d2 < q and len(koeffizienten) < 256:
        koeffizienten.append(d2)

return koeffizienten

Diese Methode garantiert eine perfekte gleichmäßige Verteilung, indem Werte außerhalb des Bereichs verworfen werden.

5.5 Härte: warum MLWE schwierig ist

Worst-Case-zu-Average-Case-Reduktion

Die wichtigste Eigenschaft von LWE/MLWE ist die Worst-Case-zu-Average-Case-Reduktion:

Wenn es einen effizienten Algorithmus gibt, der MLWE für einen nicht vernachlässigbaren Bruchteil zufälliger Instanzen löst, dann gibt es einen effizienten Algorithmus zur Lösung von GapSVP (der approximierten Version von SVP) auf jedem Gitter im schlechtesten Fall.

Diese Reduktion (Regev 2005, angepasst von Peikert 2009 und Brakerski et al. für MLWE) ist außergewöhnlich: Die meisten kryptographischen Probleme haben nur Average-Case-zu-Average-Case-Reduktionen.

In der Praxis: MLWE auf zufälligen Instanzen zu brechen ist so schwierig wie SVP im schlechtesten Fall zu lösen → die kryptographischen Annahmen sind äußerst solide.

Fehlen einer für Quantencomputer ausnutzbaren Struktur

Shors Algorithmus nutzt die Struktur abelscher Gruppen bei Faktorisierung und diskretem Logarithmus: Es gibt eine periodische Gruppenwirkung, die die QFT erkennen kann.

MLWE hat diese Struktur nicht:

  • Es gibt keine ausnutzbare Periodizität
  • Es gibt keine natürliche abelsche Gruppe, auf die die QFT angewendet werden kann
  • Die besten Quantenalgorithmen (basiert auf Quantum Walks oder QRAM) bieten höchstens polynomiale Beschleunigung, keine exponentielle

5.6 Von MLWE zu einem PKE: die konstruktive Idee

Wie konstruiert man ein Verschlüsselungssystem aus MLWE? Die Intuition ist elegant.

Analogie zu Diffie-Hellman

Bei DH ist der öffentliche Schlüssel \(g^s\): leicht zu berechnen, schwer zu invertieren.
Bei MLWE ist der öffentliche Schlüssel \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): leicht zu berechnen, schwer zu invertieren.

Verschlüsselungsschema (Regev-ähnlich)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Öffentlicher Schlüssel: \((\mathbf{A}, \mathbf{t})\).
Privater Schlüssel: \(\mathbf{s}\).

Verschlüsseln (Nachricht \(m \in \{0,1\}\), codiert als \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Chiffrat: \((\mathbf{u}, v)\).

Entschlüsseln: \(w = v - \mathbf{s}^T\mathbf{u}\)

Analyse:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{kleines Rauschen}} + \mu \approx \mu \]

Das Rauschen ist klein → durch Runden wird \(\mu\) und damit \(m\) wiederhergestellt.

Die polynomielle Version (echtes MLWE)

In ML-KEM wird jeder Skalar zu einem Polynom in \(R_q\), und die Operationen sind Polynomprodukte. Der Mechanismus ist identisch, aber die Multiplikationen finden im Ring statt:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

wobei \(\circ\) die Multiplikation in \(R_q\) ist (polynomiell, beschleunigt durch NTT).

5.7 Vollständiges numerisches Beispiel

Wir verwenden Spielzeugparameter: \(n = 4\), \(q = 17\), \(k = 2\), kleine Koeffizienten in \(\{-1, 0, 1\}\).

Die Polynome liegen in \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), haben also Grad \(\leq 3\).

Ausgangsdaten

Öffentliche Matrix \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

mit \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Geheimnis \(\mathbf{s} = (s_0, s_1)^T\) mit \(s_0 = 1 - X\), \(s_1 = X^2\).

Fehler \(\mathbf{e} = (e_0, e_1)^T\) mit \(e_0 = 1\), \(e_1 = -X\).

Berechnung von t = As + e

Komponente t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Wir reduzieren \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Ergebnis: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (die zweite Komponente wird analog berechnet).

Schlüsselbeobachtung

Ein Angreifer, der \((\mathbf{A}, \mathbf{t})\) sieht, muss \((\mathbf{s}, \mathbf{e})\) finden. Selbst mit diesen kleinen Zahlen ist das Problem bereits nicht trivial: Er kann keine Gauß-Elimination verwenden (der Fehler bricht die Linearität), und der Suchraum ist exponentiell in der realen Dimension von ML-KEM.

5.8 Warum die Parameter von ML-KEM genau so gewählt sind

\(n = 256\)

  • Muss eine Zweierpotenz sein (für effiziente NTT)
  • Das Polynom \(X^{256}+1\) muss über \(\mathbb{Z}_q\) irreduzibel sein: Dies ist der Fall, wenn \(q \equiv 1 \pmod{512}\)
  • \(256\) balanciert Sicherheit und Leistung: \(n = 128\) wäre zu unsicher, \(n = 512\) zu langsam

\(q = 3329\)

  • Muss prim sein (damit \(\mathbb{Z}_q\) ein Körper ist)
  • Muss \(q \equiv 1 \pmod{256}\) erfüllen: \(3329 = 13 \cdot 256 + 1\) ✓
  • Muss so sein, dass 256-te Einheitswurzeln existieren: durch die obige Bedingung garantiert
  • Muss so klein wie möglich sein (kompakte Schlüssel), aber mit ausreichend Rauschbudget
  • \(3329\) ist die erste Primzahl, die alle Bedingungen mit ausreichend Rauschmarge erfüllt

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): NIST-Stufe 1, äquivalent zu AES-128 vor-Quanten
  • \(k = 3\) (ML-KEM-768): Stufe 3, äquivalent zu AES-192, für den allgemeinen Gebrauch empfohlen
  • \(k = 4\) (ML-KEM-1024): Stufe 5, äquivalent zu AES-256, für hochkritische Systeme

\(\eta_1, \eta_2 \in \{2, 3\}\)

Das Rauschen muss:

  • groß genug sein, um das MLWE-Problem schwierig zu machen
  • klein genug, um sicherzustellen, dass die Entschlüsselung nicht fehlschlägt (Rauschbudget)

Eine Erhöhung von \(\eta\) erhöht die Sicherheit, aber auch die Wahrscheinlichkeit von Entschlüsselungsfehlern. Die Werte \(\eta_1 = 2, \eta_2 = 2\) für ML-KEM-768 sind der optimale Punkt.
