1.1 Was ist symmetrische Kryptographie

In einem symmetrischen Kryptosystem verwenden Sender und Empfänger den gleichen Schlüssel \(K\) zum Ver- und Entschlüsseln.

\(\text{Sender: } C = \text{Enc}(K, M)\)

\(\text{Empfänger: } M = \text{Dec}(K, C)\)

Hauptvorteil: Effizienz. AES-256 erreicht auf moderner Hardware mehrere zehn GB/s.

Nachteil: Es wird ein sicherer Kanal benötigt, um \(K\) vor der Kommunikation auszutauschen. Genau dieses Problem lösen KEMs.

Sicherheit der symmetrischen Kryptographie vs. Quantencomputer

Quantencomputer brechen AES nicht. Der Grover-Algorithmus bietet eine quadratische Beschleunigung bei der Schlüsselsuche, aber:

  • AES-128: effektive Sicherheit von 128 Bit sinkt auf ~64 Bit → unzureichend
  • AES-256: effektive Sicherheit von 256 Bit sinkt auf ~128 Bit → immer noch sicher

Aus diesem Grund erzeugt FIPS 203 (ML-KEM) 256-Bit-Schlüssel, die für die Verwendung mit AES-256 vorgesehen sind.

1.2 AES: Advanced Encryption Standard

AES ist eine Blockchiffre: Sie nimmt einen 128-Bit-Block und einen Schlüssel (\(K\)) und erzeugt 128 verschlüsselte Bits.

Interne Struktur

AES organisiert die 128 Eingangsbits als eine \(4 \times 4\)-Matrix von Bytes. Es werden dann \(r\) Runden (10, 12 oder 14 abhängig von der Schlüssellänge) angewendet, jede bestehend aus vier Transformationen:

Transformation Zweck
SubBytes Nichtlineare Substitution via S-Box (Resistenz gegen differentielle Kryptoanalyse)
ShiftRows Zyklische Rotation der Zeilen (Diffusion)
MixColumns Lineare Kombination der Spalten (Diffusion)
AddRoundKey XOR mit dem Rundenschlüssel der aktuellen Runde

Key Schedule

Der ursprüngliche Schlüssel (\(K\) von 128, 192 oder 256 Bit) wird in \(r+1\) Rundenschlüssel expandiert, einen für jede Runde.

AES-128: 128-Bit-Schlüssel, 10 Runden

AES-192: 192-Bit-Schlüssel, 12 Runden

AES-256: 256-Bit-Schlüssel, 14 Runden

Sicherheit

Der beste bekannte Angriff auf AES-128 benötigt \(2^{126.1}\) Operationen (Biryukov & Khovratovich, 2009) – im Wesentlichen Brute-Force.

1.3 Betriebsmodi

AES verschlüsselt einen 128-Bit-Block. Aber echte Nachrichten sind länger. Die Betriebsmodi definieren, wie AES wiederholt angewendet wird.

ECB (Electronic Codebook) – nicht verwenden

Jeder Block wird unabhängig verschlüsselt. Identische Blöcke erzeugen identische Chiffratblöcke → die Struktur des Klartexts bleibt erhalten.

CBC (Cipher Block Chaining)

Jeder Klartextblock wird vor der Verschlüsselung mit dem Chiffrat des vorherigen Blocks XOR-verknüpft. Erfordert einen zufälligen IV (Initialization Vector).

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Sicherer als ECB, aber bei der Verschlüsselung nicht parallelisierbar.

CTR (Counter Mode) – empfohlen

Erzeugt einen Schlüsselstrom, indem ein inkrementeller Zähler verschlüsselt wird. Der Klartext wird mit dem Schlüsselstrom XOR-verknüpft.

\[ C_i = P_i \oplus E_K(\text{Nonce} \| i) \]

Sowohl bei der Ver- als auch bei der Entschlüsselung parallelisierbar. Verwandelt AES in eine Stromchiffre.

GCM (Galois/Counter Mode) – verwendet in TLS 1.3

Kombiniert CTR mit einem MAC basierend auf Galois-Feldern. Bietet Vertraulichkeit und Authentizität.

1.4 Authentifizierung und AEAD

Vertraulichkeit allein reicht nicht aus: Ein Angreifer könnte das Chiffrat ändern, ohne dass der Empfänger es bemerkt. Es wird Authentizität benötigt.

MAC (Message Authentication Code)

Ein MAC ist eine Funktion \(\text{MAC}(K, M) \to \tau\), wobei \(\tau\) der Authentizitätstag ist. Nur wer \(K\) kennt, kann \(\tau\) erzeugen und verifizieren.

AEAD (Authenticated Encryption with Associated Data)

Kombiniert Verschlüsselung und Authentifizierung in einer einzigen primitiven Funktion:

\(\text{Enc: } (K, \text{Nonce}, \text{AAD}, \text{Klartext}) \to (\text{Chiffrat}, \text{Tag})\)

\(\text{Dec: } (K, \text{Nonce}, \text{AAD}, \text{Chiffrat}, \text{Tag}) \to \text{Klartext}\) oder \(\perp\) (wenn Tag ungültig)

AAD (Additional Authenticated Data) sind authentifizierte, aber nicht verschlüsselte Daten (z.B. Paket-Header).

AES-256-GCM ist das Standard-AEAD-Verfahren, das in TLS 1.3 und als symmetrische Chiffre nach einem KEM verwendet wird.

1.5 Rolle im PQC-Kontext

Ein vollständiger ML-KEM im realen Einsatz funktioniert wie folgt:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Nachricht) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Nachricht = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Sichere Kommunikation |

Der von ML-KEM erzeugte Schlüssel \(K\) (32 Byte) wird nicht direkt als AES-Schlüssel verwendet, sondern mit einer KDF (Key Derivation Function) wie HKDF abgeleitet, um verschiedene Kontexte zu trennen.

Praktische Größen (ML-KEM-768 + AES-256-GCM)

Komponente Größe
ML-KEM-öffentlicher Schlüssel 1184 Byte
ML-KEM-Chiffrat 1088 Byte
Shared Secret → AES-Schlüssel 32 Byte
AEAD-Overhead (GCM-Tag) 16 Byte
