9.1 Modelli di sicurezza

IND-CPA (Indistinguishability under Chosen Plaintext Attack)

In questo modello, un avversario:

  1. Riceve la chiave pubblica \(ek\)
  2. Sceglie due messaggi \(m_0, m_1\)
  3. Riceve il cifrario di uno dei due (scelto casualmente)
  4. Deve indovinare quale messaggio è stato cifrato

Lo schema è sicuro se: \(\Pr[\text{indovina}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (la componente di cifratura di base) è IND-CPA sotto l'assunzione MLWE.

IND-CCA2 (Indistinguishability under Adaptive Chosen Ciphertext Attack)

Come CPA, ma l'avversario può anche interrogare un oracolo di decifratura su qualsiasi ciphertext (eccetto quello sfida). Questo modello cattura attacchi reali (come Bleichenbacher), dove un avversario attivo manda messaggi costruiti ad hoc e osserva le risposte.

ML-KEM è IND-CCA2. Questo è il livello richiesto per un KEM sicuro in protocolli reali come TLS o SSH.

ROM vs. QROM

Le prove di sicurezza usano modelli idealizzati per le funzioni hash:

  • ROM (Random Oracle Model): le hash sono oracoli random perfetti.
  • QROM (Quantum Random Oracle Model): l'avversario quantistico può interrogare l'oracolo in sovrapposizione.

Le prove moderne per la trasformazione FO (Fujisaki-Okamoto) usata in ML-KEM garantiscono sicurezza nel QROM, essenziale contro avversari quantistici.

9.2 Come si misura la difficoltà di MLWE

Sicurezza come costo dell'attacco

Non esiste una prova assoluta che MLWE sia difficile. La sicurezza si stima calcolando il costo del miglior algoritmo di attacco noto. Una sicurezza di \(\lambda\) bit significa che l'attacco richiede circa \(2^\lambda\) operazioni.

I parametri

La difficoltà dipende da:

  • \(n = 256\) (dimensione polinomio, fissa)
  • \(k \in \{2, 3, 4\}\) (dimensione modulo)
  • \(q = 3329\) (modulo primo)
  • \(\eta \in \{2, 3\}\) (ampiezza rumore)

Lattice Estimator

Lo strumento standard è il Lattice Estimator di Albrecht et al. Per ML-KEM-768:

Attacco Costo stimato (bit)
Primal attack (BKZ) ~178 bit
Dual attack ~175 bit
Combinatorial > 200 bit

Il margine di sicurezza è ampio rispetto al target di 128 bit classico/quantistico.

9.3 Attacchi principali ai reticoli

BKZ (Block Korkine-Zolotarev)

È il miglior algoritmo generale per trovare vettori corti. Divide il reticolo in blocchi di dimensione \(\beta\) e risolve SVP localmente. Complessità: \(2^{O(\beta \log \beta)}\). Per ML-KEM-768, \(\beta \approx 430\).

Attacco primale (uSVP)

Riduce MLWE a un problema di vettore corto in un reticolo aumentato contenente la chiave pubblica e il ciphertext. Il vettore segreto \((\mathbf{s}, \mathbf{e}, -1)\) diventa un vettore corto che BKZ cerca di trovare.

Attacco duale

Sfrutta il reticolo duale per distinguere campioni MLWE da quelli uniformi tramite statistiche. Costruisce molti vettori corti nel duale per effettuare il distinguisher.

Scelta di q = 3329

Essendo primo e privo di struttura algebrica speciale, previene attacchi algebrici specifici. Non esistono fattori piccoli o relazioni semplici che possano essere sfruttate.

9.4 Livelli di sicurezza NIST

NIST ha definito 5 livelli. ML-KEM copre i livelli 1, 3 e 5:

Schema Livello NIST Sicurezza Classica Sicurezza Quantistica
ML-KEM-512 1 (AES-128) ~118 bit ~100 bit
ML-KEM-768 3 (AES-192) ~178 bit ~164 bit
ML-KEM-1024 5 (AES-256) ~230 bit ~218 bit

Raccomandazione: ML-KEM-768 offre il bilanciamento ottimale sicurezza/performance per la maggior parte degli usi. ML-KEM-1024 è riservato a sistemi ad altissima criticidad.

Confronto con Crittografia Classica

Schema Chiave Pubblica Sicurezza Quantistica
RSA-3072 384 B ❌ Vulnerabile

Il costo principale è la dimensione maggiore (~37× rispetto a ECDH), ma rimane accettabile per handshake TLS moderni.

9.6 Side-channel e implementazioni sicure

Un'implementazione corretta può essere vulnerabile se trapela informazioni tramite tempo di esecuzione (timing attacks) o consumo energetico.

Constant-Time (CT)

Tutte le operazioni devono avere tempo costante indipendentemente dai dati segreti. Esempio critico in Decaps:

// NON sicuro (timing variabile):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Sicuro (constant-time):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF se uguale, 0x00 se diverso
K = ct_select(mask, K_good, K_reject);     // selezione CT senza branch

Aree critiche per CT in ML-KEM

  • Campionamento \(B_\eta\): addizioni di bit senza branch condizionali.
  • NTT: butterfly operations devono essere eseguite sempre, anche se il risultato non cambia.
  • Verifica Ciphertext: uso di ct_memcmp.

Implementazioni di riferimento

  • pqclean: implementazioni portabili CT.
  • liboqs: ottimizzazioni AVX2 con proprietà CT verificate.
