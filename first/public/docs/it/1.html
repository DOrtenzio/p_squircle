01 – Crittografia Simmetrica

Il punto di arrivo pratico di tutto il percorso PQC

1.1 Cos'è la crittografia simmetrica

In un sistema a crittografia simmetrica, mittente e destinatario usano la stessa chiave \(K\) per cifrare e decifrare.

\(\text{Mittente: } C = \text{Enc}(K, M)\)

\(\text{Destinatario: } M = \text{Dec}(K, C)\)

Vantaggio principale: efficienza. AES-256 su hardware moderno raggiunge decine di GB/s.

Svantaggio: serve un canale sicuro per scambiarsi \(K\) prima di comunicare. Questo è esattamente il problema che i KEM risolvono.

Sicurezza della crittografia simmetrica vs. quantistica

I computer quantistici non rompono AES. L'algoritmo di Grover offre un quadratico speedup nella ricerca della chiave, ma:

  • AES-128: sicurezza effettiva da 128 bit scende a ~64 bit → insufficiente
  • AES-256: sicurezza effettiva da 256 bit scende a ~128 bit → ancora sicuro

Per questo FIPS 203 (ML-KEM) produce chiavi da 256 bit, destinate ad essere usate con AES-256.

1.2 AES: Advanced Encryption Standard

AES è un cifrario a blocchi: prende un blocco di 128 bit e una chiave (\(K\)), e produce 128 bit cifrati.

Struttura interna

AES organizza i 128 bit di input come una matrice \(4 \times 4\) di byte. Applica poi \(r\) round (10, 12 o 14 in base alla dimensione della chiave), ciascuno composto da quattro trasformazioni:

Trasformazione Scopo
SubBytes Sostituzione non lineare via S-Box (resistenza alla crittanalisi differenziale)
ShiftRows Rotazione ciclica delle righe (diffusione)
MixColumns Combinazione lineare delle colonne (diffusione)
AddRoundKey XOR con la sottochiave del round corrente

Key schedule

La chiave originale (\(K\) di 128, 192 o 256 bit) viene espansa in \(r+1\) sottochiavi, una per ogni round.

AES-128: chiave 128 bit, 10 round

AES-192: chiave 192 bit, 12 round

AES-256: chiave 256 bit, 14 round

Sicurezza

Il migliore attacco noto ad AES-128 richiede \(2^{126.1}\) operazioni (Biryukov & Khovratovich, 2009) – sostanzialmente forza bruta.

1.3 Modalità operative

AES cifra un blocco da 128 bit. Ma i messaggi reali sono più lunghi. Le modalità operative definiscono come applicare AES ripetutamente.

ECB (Electronic Codebook) – da non usare

Ogni blocco è cifrato indipendentemente. Blocchi identici producono ciphertext identici → perde la struttura del plaintext.

CBC (Cipher Block Chaining)

Ogni blocco plaintext viene XORato con il ciphertext del blocco precedente prima di essere cifrato. Richiede un IV (Initialization Vector) casuale.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Più sicuro di ECB, ma non parallelizzabile in cifratura.

CTR (Counter Mode) – consigliato

Genera un keystream cifrando un contatore incrementale. Il plaintext viene XORato con il keystream.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Parallelizzabile sia in cifratura che decifratura. Trasforma AES in cifrario a flusso.

GCM (Galois/Counter Mode) – usato in TLS 1.3

Combina CTR con un MAC basato su campi di Galois. Offre confidenzialità e autenticità.

1.4 Autenticazione e AEAD

La confidenzialità non basta: un attaccante potrebbe modificare il ciphertext senza che il destinatario se ne accorga. Serve autenticità.

MAC (Message Authentication Code)

Un MAC è una funzione \(\text{MAC}(K, M) \to \tau\) dove \(\tau\) è il tag di autenticità. Solo chi conosce \(K\) può generare e verificare \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Combina cifratura e autenticazione in una sola primitiva:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) oppure \(\perp\) (se tag non valido)

AAD (Additional Authenticated Data) è dati autenticati ma non cifrati (es. header di pacchetti).

AES-256-GCM è lo schema AEAD standard usato in TLS 1.3 e come cifrario simmetrico dopo un KEM.

1.5 Ruolo nel contesto PQC

Un ML-KEM completo in uso reale funziona così:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Messaggio) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Messaggio = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Comunicazione sicura |

La chiave \(K\) prodotta da ML-KEM (32 byte) non viene usata direttamente come chiave AES, ma derivata con una KDF (Key Derivation Function) come HKDF per separare contesti diversi.

Dimensioni pratiche (ML-KEM-768 + AES-256-GCM)

Componente Dimensione
Chiave pubblica ML-KEM 1184 byte
Ciphertext ML-KEM 1088 byte
Shared secret → chiave AES 32 byte
Overhead AEAD (tag GCM) 16 byte
