1.1 ¿Qué es la criptografía simétrica?

En un sistema de criptografía simétrica, el emisor y el receptor usan la misma clave \(K\) para cifrar y descifrar.

\(\text{Emisor: } C = \text{Enc}(K, M)\)

\(\text{Receptor: } M = \text{Dec}(K, C)\)

Ventaja principal: eficiencia. AES-256 en hardware moderno alcanza decenas de GB/s.

Desventaja: se necesita un canal seguro para intercambiar \(K\) antes de comunicarse. Este es exactamente el problema que los KEM resuelven.

Seguridad de la criptografía simétrica vs. cuántica

Los computadores cuánticos no rompen AES. El algoritmo de Grover ofrece una aceleración cuadrática en la búsqueda de la clave, pero:

  • AES-128: seguridad efectiva de 128 bits baja a ~64 bits → insuficiente
  • AES-256: seguridad efectiva de 256 bits baja a ~128 bits → aún seguro

Por esto, FIPS 203 (ML-KEM) produce claves de 256 bits, destinadas a ser usadas con AES-256.

1.2 AES: Advanced Encryption Standard

AES es un cifrador por bloques: toma un bloque de 128 bits y una clave (\(K\)), y produce 128 bits cifrados.

Estructura interna

AES organiza los 128 bits de entrada como una matriz \(4 \times 4\) de bytes. Luego aplica \(r\) rondas (10, 12 o 14 según el tamaño de la clave), cada una compuesta por cuatro transformaciones:

Transformación Propósito
SubBytes Sustitución no lineal vía S-Box (resistencia al criptoanálisis diferencial)
ShiftRows Rotación cíclica de filas (difusión)
MixColumns Combinación lineal de columnas (difusión)
AddRoundKey XOR con la subclave de la ronda actual

Key schedule

La clave original (\(K\) de 128, 192 o 256 bits) se expande en \(r+1\) subclaves, una para cada ronda.

AES-128: clave 128 bits, 10 rondas

AES-192: clave 192 bits, 12 rondas

AES-256: clave 256 bits, 14 rondas

Seguridad

El mejor ataque conocido a AES-128 requiere \(2^{126.1}\) operaciones (Biryukov & Khovratovich, 2009) – esencialmente fuerza bruta.

1.3 Modos de operación

AES cifra un bloque de 128 bits. Pero los mensajes reales son más largos. Los modos de operación definen cómo aplicar AES repetidamente.

ECB (Electronic Codebook) – no usar

Cada bloque se cifra de forma independiente. Bloques idénticos producen texto cifrado idéntico → pierde la estructura del texto plano.

CBC (Cipher Block Chaining)

Cada bloque de texto plano se XORea con el texto cifrado del bloque anterior antes de ser cifrado. Requiere un IV (Initialization Vector) aleatorio.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Más seguro que ECB, pero no paralelizable en el cifrado.

CTR (Counter Mode) – recomendado

Genera un flujo de clave cifrando un contador incremental. El texto plano se XORea con el flujo de clave.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Paralelizable tanto en el cifrado como en el descifrado. Convierte AES en un cifrador de flujo.

GCM (Galois/Counter Mode) – usado en TLS 1.3

Combina CTR con un MAC basado en campos de Galois. Ofrece confidencialidad y autenticidad.

1.4 Autenticación y AEAD

La confidencialidad no es suficiente: un atacante podría modificar el texto cifrado sin que el receptor se dé cuenta. Se necesita autenticidad.

MAC (Message Authentication Code)

Un MAC es una función \(\text{MAC}(K, M) \to \tau\) donde \(\tau\) es la etiqueta de autenticidad. Solo quien conoce \(K\) puede generar y verificar \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Combina cifrado y autenticación en una sola primitiva:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) o \(\perp\) (si la etiqueta no es válida)

AAD (Additional Authenticated Data) son datos autenticados pero no cifrados (ej. cabeceras de paquetes).

AES-256-GCM es el esquema AEAD estándar usado en TLS 1.3 y como cifrador simétrico después de un KEM.

1.5 Rol en el contexto PQC

Un ML-KEM completo en uso real funciona así:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Mensaje) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Mensaje = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Comunicación segura |

La clave \(K\) producida por ML-KEM (32 bytes) no se usa directamente como clave AES, sino que se deriva con una KDF (Key Derivation Function) como HKDF para separar contextos diferentes.

Dimensiones prácticas (ML-KEM-768 + AES-256-GCM)

Componente Tamaño
Clave pública ML-KEM 1184 bytes
Texto cifrado ML-KEM 1088 bytes
Secreto compartido → clave AES 32 bytes
Overhead AEAD (tag GCM) 16 bytes
