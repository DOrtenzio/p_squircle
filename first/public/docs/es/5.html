5.1 De LWE a MLWE: la motivación

LWE clásico y su coste

En el archivo 04 vimos LWE estándar: dados \(m\) muestras \((\mathbf{a}_i, b_i)\) con \(\mathbf{a}_i \in \mathbb{Z}_q^n\) y \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), encontrar \(\mathbf{s}\). El problema es difícil, pero tiene un coste práctico alto:

  • La clave pública (la matriz \(A \in \mathbb{Z}_q^{m \times n}\)) tiene un tamaño \(O(n^2)\): para \(n = 1024\) y \(q = 3329\) serían más de 2 MB.
  • La multiplicación matriz-vector \(A \cdot \mathbf{s}\) cuesta \(O(n^2)\) multiplicaciones.

RLWE: demasiado rígido

Ring-LWE traslada las operaciones al anillo \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Un único polinomio \(a \in R_q\) sustituye a toda la matriz, reduciendo la clave pública a \(O(n)\).

Pero RLWE tiene una estructura algebraica muy específica que algunos investigadores consideran potencialmente explotable (aunque no se conoce ningún ataque práctico en 2024).

MLWE: el compromiso óptimo

Module-LWE generaliza ambos usando una matriz \(k \times k\) de polinomios en \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Para \(k = 1\): se reduce a RLWE
  • Para \(k \to \infty\) (polinomios de grado 0): se reduce a LWE clásico

El parámetro \(k\) permite calibrar la seguridad y el rendimiento de forma independiente de \(n\).

Variante Clave pública Seguridad Flexibilidad
LWE \(O(n^2)\) alta baja
RLWE \(O(n)\) media baja
MLWE \(O(k \cdot n)\) regulable con \(k\) alta

5.2 Definición formal de MLWE

Espacio de trabajo

Fijados los parámetros:

  • \(n = 256\): grado del polinomio ciclotómico
  • \(q = 3329\): módulo primo
  • \(k \in \{2, 3, 4\}\): dimensión del módulo
  • \(\chi\): distribución del ruido (distribución binomial centrada \(B_\eta\))

El anillo base es \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Distribución MLWE

Sea \(\mathbf{s} \in R_q^k\) un vector secreto de polinomios, cada uno con coeficientes muestreados de \(\chi\).

Una instancia MLWE es un par:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{donde} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

con \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Problema decisional MLWE

Entrada: \((\mathbf{A}, \mathbf{t})\) donde:

  • sea \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (distribución MLWE), o
  • sea \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) uniforme

Objetivo: distinguir los dos casos con ventaja no despreciable.

Problema de búsqueda MLWE

Entrada: \((\mathbf{A}, \mathbf{t})\) con \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Objetivo: encontrar \(\mathbf{s}\).

La reducción de Regev (adaptada a MLWE) demuestra que el problema de búsqueda es computacionalmente equivalente al problema decisional, y que ambos son al menos tan difíciles como GapSVP en retículos de alta dimensión.

5.3 La distribución del ruido en ML-KEM

Distribución binomial centrada \(B_\eta\)

En ML-KEM el ruido no es gaussiano sino binomial centrado. Para muestrear un solo coeficiente de \(B_\eta\):

  1. Muestrear \(2\eta\) bits uniformes: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Devolver \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

El resultado es un entero en \([-\eta, \eta]\).

Distribución de probabilidad para η = 2:

Valor Probabilidad
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

¿Por qué no gaussiana verdadera?

La gaussiana discreta es teóricamente óptima, pero muestrearla de forma de tiempo constante (resistente a ataques de temporización) es complejo. La binomial centrada:

  • tiene soporte finito → sin casos extremos
  • se muestrea con solo operaciones sobre bits → trivialmente de tiempo constante
  • es estadísticamente indistinguible de la gaussiana para los ataques conocidos

Muestreo en ML-KEM (función SamplePolyCBD)

CBD_η(σ, b): Entrada: semilla σ ∈ {0,1}^256, nonce b ∈ {0,1}^8 Salida: polinomio f ∈ R_q con coeficientes en [-η, η] bytes = PRF(σ, b) // SHAKE256, genera 64η bytes para j = 0..255: a = suma de los bits de bytes en las posiciones [2ηj .. 2ηj+η-1] b = suma de los bits de bytes en las posiciones [2ηj+η .. 2ηj+2η-1] f[j] = a - b devolver f

Cada polinomio \(\mathbf{s}[i]\) y \(\mathbf{e}[i]\) se muestrea con un nonce diferente, garantizando la independencia estadística.

5.4 Muestreo en ML-KEM

CBD: Centered Binomial Distribution

ML-KEM usa una distribución binomial centrada \(B_\eta\) para generar errores pequeños y secretos. Esta distribución es eficiente y no requiere rejection sampling.

Función SamplePolyCBD(σ, b, η)

Entrada: semilla σ ∈ {0,1}^256, nonce b, parámetro η
Salida: polinomio f ∈ R_q con coeficientes en [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, genera 64·η bytes
2. Para j = 0 a 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // cuenta los 1 en el primer grupo
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // cuenta los 1 en el segundo grupo
     f[j] = a - b                     // diferencia centrada en 0
3. Devolver f

Para \(\eta=2\), los coeficientes están en \(\{-2, -1, 0, 1, 2\}\). Para \(\eta=3\), en \(\{-3, \ldots, 3\}\).

SampleNTT: Muestreo Uniforme

Para generar la matriz pública \(\mathbf{A}\), se necesitan coeficientes uniformes en \(\mathbb{Z}_q\). Se utiliza el rejection sampling sobre la salida de SHAKE128.

Función SampleNTT(stream)

Entrada: flujo de bytes desde XOF (SHAKE128)
Salida: polinomio con coeficientes uniformes en [0, q-1]

coeficientes = []
mientras len(coeficientes) < 256:
    // Leer 3 bytes para generar 2 valores candidatos
    b0, b1, b2 = next_3_bytes(stream)

    // Combinar los bits para formar dos números de 12 bits
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2

    // Aceptar solo si son < q (3329)
    si d1 < q:
        coeficientes.append(d1)
    si d2 < q and len(coeficientes) < 256:
        coeficientes.append(d2)

devolver coeficientes

Este método garantiza una distribución uniforme perfecta, descartando los valores fuera de rango.

5.5 Hardness: por qué MLWE es difícil

Reducción del peor caso al caso promedio

La propiedad más importante de LWE/MLWE es la reducción del peor caso al caso promedio:

Si existe un algoritmo eficiente que resuelve MLWE para una fracción no despreciable de instancias aleatorias, entonces existe un algoritmo eficiente para resolver GapSVP (la versión aproximada de SVP) en cualquier retículo, en el peor caso.

Esta reducción (Regev 2005, adaptada por Peikert 2009 y Brakerski et al. para MLWE) es excepcional: la mayoría de los problemas criptográficos solo tienen reducciones de caso promedio a caso promedio.

En la práctica: romper MLWE en instancias aleatorias es tan difícil como resolver SVP en el peor caso → los supuestos criptográficos son muy sólidos.

Ausencia de estructura explotable por cuánticos

El algoritmo de Shor explota la estructura de grupo abeliano de los problemas de factorización y logaritmo discreto: existe una acción de grupo periódica que la QFT puede detectar.

MLWE no tiene esta estructura:

  • No hay periodicidad que explotar
  • No hay un grupo abeliano natural sobre el que aplicar la QFT
  • Los mejores algoritmos cuánticos (basados en quantum walks o QRAM) ofrecen como mucho una aceleración polinómica, no exponencial

5.6 De MLWE a un PKE: la idea constructiva

¿Cómo se construye un sistema de cifrado a partir de MLWE? La intuición es elegante.

Analogía con Diffie-Hellman

En DH, la clave pública es \(g^s\): fácil de calcular, difícil de invertir.
En MLWE, la clave pública es \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): fácil de calcular, difícil de invertir.

Esquema de cifrado (tipo Regev)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Clave pública: \((\mathbf{A}, \mathbf{t})\).
Clave privada: \(\mathbf{s}\).

Encrypt (mensaje \(m \in \{0,1\}\), codificado como \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Texto cifrado: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Análisis:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{ruido pequeño}} + \mu \approx \mu \]

El ruido es pequeño → redondeando se recupera \(\mu\) y por tanto \(m\).

La versión polinomial (MLWE real)

En ML-KEM, cada escalar se convierte en un polinomio en \(R_q\), y las operaciones son productos polinomiales. El mecanismo es idéntico, pero las multiplicaciones se realizan en el anillo:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

donde \(\circ\) es la multiplicación en \(R_q\) (polinomial, acelerada por NTT).

5.7 Ejemplo numérico completo

Usamos parámetros de juguete: \(n = 4\), \(q = 17\), \(k = 2\), coeficientes pequeños en \(\{-1, 0, 1\}\).

Los polinomios están en \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), por lo tanto de grado \(\leq 3\).

Datos de partida

Matriz pública \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

con \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Secreto \(\mathbf{s} = (s_0, s_1)^T\) con \(s_0 = 1 - X\), \(s_1 = X^2\).

Error \(\mathbf{e} = (e_0, e_1)^T\) con \(e_0 = 1\), \(e_1 = -X\).

Cálculo de t = As + e

Componente t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Reducimos \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Resultado: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (la segunda componente se calcula de forma análoga).

Observación clave

Un adversario que ve \((\mathbf{A}, \mathbf{t})\) debe encontrar \((\mathbf{s}, \mathbf{e})\). Incluso con estos números pequeños, el problema ya no es trivial: no puede usar eliminación gaussiana (el error rompe la linealidad) y el espacio de búsqueda es exponencial en la dimensión real de ML-KEM.

5.8 Por qué los parámetros de ML-KEM son los que son

\(n = 256\)

  • Debe ser una potencia de 2 (para NTT eficiente)
  • El polinomio \(X^{256}+1\) debe ser irreducible sobre \(\mathbb{Z}_q\): lo es si \(q \equiv 1 \pmod{512}\)
  • \(256\) equilibra seguridad y rendimiento: \(n = 128\) sería demasiado inseguro, \(n = 512\) demasiado lento

\(q = 3329\)

  • Debe ser primo (para que \(\mathbb{Z}_q\) sea un campo)
  • Debe satisfacer \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Debe ser tal que existan raíces 256-ésimas de la unidad: garantizado por la condición anterior
  • Debe ser el más pequeño posible (claves compactas) compatible con el presupuesto de ruido
  • \(3329\) es el primo que satisface todas las condiciones con suficiente margen para el ruido

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): nivel 1 NIST, equivalente a AES-128 pre-cuántico
  • \(k = 3\) (ML-KEM-768): nivel 3, equivalente a AES-192, recomendado para uso general
  • \(k = 4\) (ML-KEM-1024): nivel 5, equivalente a AES-256, para sistemas de alta criticidad

\(\eta_1, \eta_2 \in \{2, 3\}\)

El ruido debe ser:

  • lo suficientemente grande para hacer difícil el problema MLWE
  • lo suficientemente pequeño para garantizar que el descifrado no falle (presupuesto de ruido)

Aumentar \(\eta\) aumenta la seguridad pero también la probabilidad de error de descifrado. Los valores \(\eta_1 = 2, \eta_2 = 2\) para ML-KEM-768 son el punto óptimo.
