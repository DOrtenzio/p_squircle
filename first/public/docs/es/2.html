2.1 El problema del intercambio de claves

Alice quiere comunicarse de forma segura con Bob a través de un canal público. Para usar AES se necesita una clave compartida. ¿Cómo se establece sin que Eve (que escucha todo) la descubra?

Este problema no tuvo solución durante siglos. La respuesta llegó en 1976 con Diffie y Hellman, y en 1977 con Rivest, Shamir y Adleman (RSA).

La idea clave: existen operaciones matemáticas fáciles en un sentido, difíciles en el otro.

Operación fácil Operación difícil
Multiplicar dos primos grandes: \(p \cdot q = n\) Factorizar \(n\) para encontrar \(p\) y \(q\)
Calcular \(g^x \bmod p\) Encontrar \(x\) dado \(g^x \bmod p\) (logaritmo discreto)
Sumar un punto en curva elíptica \(k\) veces: \(kP\) Encontrar \(k\) dado \(kP\) (ECDLP)

2.2 RSA

Generación de claves

  1. Elegir dos primos grandes \(p\) y \(q\) (típicamente 2048+ bits cada uno)
  2. Calcular \(n = p \cdot q\)
  3. Calcular \(\phi(n) = (p-1)(q-1)\)
  4. Elegir \(e\) tal que \(\gcd(e, \phi(n)) = 1\) (típicamente \(e = 65537\))
  5. Calcular \(d = e^{-1} \bmod \phi(n)\)

Clave pública: \((n, e)\)
Clave privada: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) deben destruirse.

Cifrado y descifrado

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Por qué funciona: por el teorema de Euler, \(M^{\phi(n)} \equiv 1 \pmod{n}\), por lo tanto \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Ejemplo numérico (con números pequeños, solo didáctico)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(porque } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Ciframos \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Desciframos:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA como KEM

RSA-KEM (simplificado):

  1. Bob genera \(r \leftarrow \{1, \ldots, n-1\}\) al azar
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (clave simétrica)
  4. Envía \(C\) a Alice
  5. Alice calcula \(r = C^d \bmod n\), luego \(K = H(r)\)

2.3 Diffie-Hellman (DH)

El protocolo

Parámetros públicos: un primo grande \(p\) y un generador \(g\) de \(\mathbb{Z}_p^*\).

Alice
  1. Elige \(a\) secreto
  2. Calcula \(A = g^a \bmod p\)
A → ← B
Bob
  1. Elige \(b\) secreto
  2. Calcula \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Alice calcula: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Bob calcula: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Resultado: Ambos comparten la misma clave secreta \(K\). Eve, que solo ve \(A\) y \(B\), no puede calcular \(K\) sin resolver el problema del logaritmo discreto.

2.4 Criptografía sobre Curvas Elípticas (ECDH)

ECDH es el análogo de DH sobre curvas elípticas. Se usa en TLS 1.3 con la curva X25519.

Alice
  1. Elige \(a\) secreto
  2. Calcula \(A = a \cdot G\)
A → ← B
Bob
  1. Elige \(b\) secreto
  2. Calcula \(B = b \cdot G\)
\[ \begin{aligned} \text{Alice calcula: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Bob calcula: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Donde \(G\) es el punto generador de la curva. La seguridad se basa en la dificultad del ECDLP (Elliptic Curve Discrete Logarithm Problem).

2.4 Criptografía sobre curvas elípticas (ECC)

Qué son las curvas elípticas

Una curva elíptica sobre \(\mathbb{Z}_p\) es el conjunto de puntos \((x, y)\) que satisfacen:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

más un punto especial \(\mathcal{O}\) llamado punto en el infinito.

En estos puntos se define una operación de suma con propiedades de grupo.

Multiplicación escalar

Dada la suma de puntos, se define la multiplicación escalar:

\(kP = P + P + \cdots + P \quad (k \text{ veces})\)

Calcular \(kP\) a partir de \(P\) y \(k\) es fácil (\(O(\log k)\) operaciones). El problema inverso – encontrar \(k\) a partir de \(P\) y \(kP\) – es el Problema del Logaritmo Discreto sobre Curvas Elípticas (ECDLP), computacionalmente difícil.

Ventajas de ECC frente a DH/RSA

Seguridad equivalente RSA/DH (bits de n/p) ECC (bits de la clave)
80 bits 1024 160
128 bits 3072 256
256 bits 15360 512

ECC ofrece claves mucho más pequeñas con la misma seguridad → más eficiente.

ECDH (Elliptic Curve Diffie-Hellman)

Alice Bob | | | elige a secreto | elige b secreto | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ clave compartida K |

ECDH se usa en TLS 1.3 con la curva X25519 (curve25519 de Bernstein).

2.5 Seguridad clásica y límites cuánticos

Contra computadores clásicos

Los problemas en los que se basan RSA y ECC son subexponenciales (no puramente exponenciales) para computadores clásicos.

El mejor algoritmo clásico para la factorización es el General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

Para \(n\) de 2048 bits, esto requiere un tiempo astronómicamente largo → seguro en la práctica.

Contra computadores cuánticos: el algoritmo de Shor

En 1994, Peter Shor demostró que un computador cuántico puede:

  • Factorizar \(n\) en tiempo \(O((\log n)^3)\)
  • Resolver el DLP en tiempo \(O((\log p)^3)\)
  • Resolver el ECDLP en tiempo \(O((\log p)^3)\)

Un computador cuántico con suficientes qubits rompería RSA-2048 en horas o días.

El análisis detallado del algoritmo de Shor está en el archivo 03 – Algoritmo de Shor.

La respuesta: criptografía post-cuántica

Para seguir teniendo criptografía asimétrica segura en la era cuántica, se necesitan problemas matemáticos que no tengan algoritmos cuánticos eficientes conocidos.

Los problemas sobre retículos (lattice), en los que se basa ML-KEM, cumplen este requisito: los mejores algoritmos cuánticos conocidos ofrecen como mucho una modesta aceleración respecto a los algoritmos clásicos.
