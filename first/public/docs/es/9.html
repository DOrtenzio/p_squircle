9.1 Modelos de seguridad

IND-CPA (Indistinguishability under Chosen Plaintext Attack)

En este modelo, un atacante:

  1. Recibe la clave pública \(ek\)
  2. Elige dos mensajes \(m_0, m_1\)
  3. Recibe el cifrado de uno de ellos (elegido al azar)
  4. Debe adivinar qué mensaje fue cifrado

El esquema es seguro si: \(\Pr[\text{adivina}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (el componente de cifrado base) es IND-CPA bajo el supuesto MLWE.

IND-CCA2 (Indistinguishability under Adaptive Chosen Ciphertext Attack)

Como CPA, pero el atacante también puede consultar un oráculo de descifrado sobre cualquier texto cifrado (excepto el desafío). Este modelo captura ataques reales (como Bleichenbacher), donde un atacante activo envía mensajes construidos ad hoc y observa las respuestas.

ML-KEM es IND-CCA2. Este es el nivel requerido para un KEM seguro en protocolos reales como TLS o SSH.

ROM vs. QROM

Las pruebas de seguridad utilizan modelos idealizados para las funciones hash:

  • ROM (Random Oracle Model): los hash son oráculos aleatorios perfectos.
  • QROM (Quantum Random Oracle Model): el atacante cuántico puede consultar el oráculo en superposición.

Las pruebas modernas para la transformación FO (Fujisaki-Okamoto) utilizada en ML-KEM garantizan la seguridad en el QROM, esencial contra atacantes cuánticos.

9.2 Cómo se mide la dificultad de MLWE

Seguridad como coste del ataque

No existe una prueba absoluta de que MLWE sea difícil. La seguridad se estima calculando el coste del mejor algoritmo de ataque conocido. Una seguridad de \(\lambda\) bits significa que el ataque requiere aproximadamente \(2^\lambda\) operaciones.

Los parámetros

La dificultad depende de:

  • \(n = 256\) (tamaño del polinomio, fijo)
  • \(k \in \{2, 3, 4\}\) (dimensión del módulo)
  • \(q = 3329\) (módulo primo)
  • \(\eta \in \{2, 3\}\) (amplitud del ruido)

Lattice Estimator

La herramienta estándar es el Lattice Estimator de Albrecht et al. Para ML-KEM-768:

Ataque Coste estimado (bits)
Ataque primal (BKZ) ~178 bits
Ataque dual ~175 bits
Combinatorio > 200 bits

El margen de seguridad es amplio en comparación con el objetivo de 128 bits clásico/cuántico.

9.3 Ataques principales a los retículos

BKZ (Block Korkine-Zolotarev)

Es el mejor algoritmo general para encontrar vectores cortos. Divide el retículo en bloques de tamaño \(\beta\) y resuelve SVP localmente. Complejidad: \(2^{O(\beta \log \beta)}\). Para ML-KEM-768, \(\beta \approx 430\).

Ataque primal (uSVP)

Reduce MLWE a un problema de vector corto en un retículo aumentado que contiene la clave pública y el texto cifrado. El vector secreto \((\mathbf{s}, \mathbf{e}, -1)\) se convierte en un vector corto que BKZ intenta encontrar.

Ataque dual

Aprovecha el retículo dual para distinguir muestras MLWE de las uniformes mediante estadísticas. Construye muchos vectores cortos en el dual para realizar el distinguidor.

Elección de q = 3329

Al ser primo y carecer de estructura algebraica especial, previene ataques algebraicos específicos. No existen factores pequeños ni relaciones simples que puedan ser explotadas.

9.4 Niveles de seguridad NIST

NIST ha definido 5 niveles. ML-KEM cubre los niveles 1, 3 y 5:

Esquema Nivel NIST Seguridad Clásica Seguridad Cuántica
ML-KEM-512 1 (AES-128) ~118 bits ~100 bits
ML-KEM-768 3 (AES-192) ~178 bits ~164 bits
ML-KEM-1024 5 (AES-256) ~230 bits ~218 bits

Recomendación: ML-KEM-768 ofrece el equilibrio óptimo seguridad/rendimiento para la mayoría de los usos. ML-KEM-1024 está reservado para sistemas de muy alta criticidad.

9.6 Canales laterales e implementaciones seguras

Una implementación correcta puede ser vulnerable si filtra información a través del tiempo de ejecución (ataques de temporización) o el consumo de energía.

Tiempo Constante (CT)

Todas las operaciones deben tener un tiempo constante independientemente de los datos secretos. Ejemplo crítico en Decaps:

// NO seguro (tiempo variable):
if (memcmp(c, c_prime, len) == 0) {
    K = K_good;
} else {
    K = K_reject;
}

// Seguro (tiempo constante):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF si iguales, 0x00 si diferentes
K = ct_select(mask, K_good, K_reject);     // selección CT sin bifurcaciones

Áreas críticas para CT en ML-KEM

  • Muestreo \(B_\eta\): sumas de bits sin bifurcaciones condicionales.
  • NTT: las operaciones mariposa deben ejecutarse siempre, incluso si el resultado no cambia.
  • Verificación del Texto Cifrado: uso de ct_memcmp.

Implementaciones de referencia

  • pqclean: implementaciones portables CT.
  • liboqs: optimizaciones AVX2 con propiedades CT verificadas.
