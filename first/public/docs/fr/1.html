01 – Cryptographie Symétrique

Le point d'arrivée pratique de tout le parcours PQC

1.1 Qu'est-ce que la cryptographie symétrique

Dans un système de cryptographie symétrique, l'expéditeur et le destinataire utilisent la même clé \(K\) pour chiffrer et déchiffrer.

\(\text{Expéditeur: } C = \text{Enc}(K, M)\)

\(\text{Destinataire: } M = \text{Dec}(K, C)\)

Avantage principal: l'efficacité. AES-256 sur du matériel moderne atteint des dizaines de Go/s.

Inconvénient: il faut un canal sécurisé pour échanger \(K\) avant de communiquer. C'est exactement le problème que les KEM résolvent.

Sécurité de la cryptographie symétrique vs. quantique

Les ordinateurs quantiques ne cassent pas AES. L'algorithme de Grover offre un accélération quadratique dans la recherche de la clé, mais:

  • AES-128: sécurité effective de 128 bits descend à ~64 bits → insuffisant
  • AES-256: sécurité effective de 256 bits descend à ~128 bits → encore sécurisé

C'est pourquoi FIPS 203 (ML-KEM) produit des clés de 256 bits, destinées à être utilisées avec AES-256.

1.2 AES: Advanced Encryption Standard

AES est un chiffrement par blocs: il prend un bloc de 128 bits et une clé (\(K\)), et produit 128 bits chiffrés.

Structure interne

AES organise les 128 bits d'entrée comme une matrice \(4 \times 4\) d'octets. Il applique ensuite \(r\) rounds (10, 12 ou 14 selon la taille de la clé), chacun composé de quatre transformations:

Transformation Objectif
SubBytes Substitution non linéaire via S-Box (résistance à la cryptanalyse différentielle)
ShiftRows Rotation cyclique des lignes (diffusion)
MixColumns Combinaison linéaire des colonnes (diffusion)
AddRoundKey XOR avec la sous-clé du round courant

Key schedule

La clé originale (\(K\) de 128, 192 ou 256 bits) est étendue en \(r+1\) sous-clés, une pour chaque round.

AES-128: clé 128 bits, 10 rounds

AES-192: clé 192 bits, 12 rounds

AES-256: clé 256 bits, 14 rounds

Sécurité

La meilleure attaque connue contre AES-128 nécessite \(2^{126.1}\) opérations (Biryukov & Khovratovich, 2009) – essentiellement une force brute.

1.3 Modes opératoires

AES chiffre un bloc de 128 bits. Mais les messages réels sont plus longs. Les modes opératoires définissent comment appliquer AES de manière répétée.

ECB (Electronic Codebook) – à ne pas utiliser

Chaque bloc est chiffré indépendamment. Des blocs identiques produisent des chiffrés identiques → la structure du clair est révélée.

CBC (Cipher Block Chaining)

Chaque bloc de clair est XORé avec le chiffré du bloc précédent avant d'être chiffré. Nécessite un IV (Initialization Vector) aléatoire.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Plus sécurisé que ECB, mais non parallélisable en chiffrement.

CTR (Counter Mode) – recommandé

Génère un flux de clés en chiffrant un compteur incrémentiel. Le clair est XORé avec le flux de clés.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Parallélisable en chiffrement et déchiffrement. Transforme AES en chiffrement de flux.

GCM (Galois/Counter Mode) – utilisé dans TLS 1.3

Combine CTR avec un MAC basé sur les corps de Galois. Offre confidentialité et authenticité.

1.4 Authentification et AEAD

La confidentialité ne suffit pas: un attaquant pourrait modifier le chiffré sans que le destinataire s'en aperçoive. Il faut de l'authenticité.

MAC (Message Authentication Code)

Un MAC est une fonction \(\text{MAC}(K, M) \to \tau\) où \(\tau\) est le tag d'authenticité. Seul celui qui connaît \(K\) peut générer et vérifier \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Combine chiffrement et authentification en une seule primitive:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{clair}) \to (\text{chiffré}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{chiffré}, \text{tag}) \to \text{clair}\) ou \(\perp\) (si tag invalide)

AAD (Additional Authenticated Data) sont des données authentifiées mais non chiffrées (ex. en-têtes de paquets).

AES-256-GCM est le schéma AEAD standard utilisé dans TLS 1.3 et comme chiffrement symétrique après un KEM.

1.5 Rôle dans le contexte PQC

Un ML-KEM complet en usage réel fonctionne comme suit:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Message) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Message = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Communication sécurisée |

La clé \(K\) produite par ML-KEM (32 octets) n'est pas utilisée directement comme clé AES, mais dérivée avec une KDF (Key Derivation Function) comme HKDF pour séparer différents contextes.

Tailles pratiques (ML-KEM-768 + AES-256-GCM)

Composant Taille
Clé publique ML-KEM 1184 octets
Chiffré ML-KEM 1088 octets
Secret partagé → clé AES 32 octets
Overhead AEAD (tag GCM) 16 octets
