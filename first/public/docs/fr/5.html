5.1 De LWE à MLWE: la motivation

LWE classique et son coût

Dans le fichier 04 nous avons vu LWE standard: étant donné \(m\) échantillons \((\mathbf{a}_i, b_i)\) avec \(\mathbf{a}_i \in \mathbb{Z}_q^n\) et \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), trouver \(\mathbf{s}\). Le problème est difficile, mais il a un coût pratique élevé:

  • La clé publique (la matrice \(A \in \mathbb{Z}_q^{m \times n}\)) a une taille \(O(n^2)\): pour \(n = 1024\) et \(q = 3329\) cela ferait plus de 2 Mo.
  • La multiplication matrice-vecteur \(A \cdot \mathbf{s}\) coûte \(O(n^2)\) multiplications.

RLWE: trop rigide

Ring-LWE place les opérations dans l'anneau \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Un seul polynôme \(a \in R_q\) remplace toute la matrice, réduisant la clé publique à \(O(n)\).

Mais RLWE a une structure algébrique très spécifique que certains chercheurs considèrent comme potentiellement exploitable (bien qu'aucune attaque pratique ne soit connue en 2024).

MLWE: le compromis optimal

Module-LWE généralise les deux en utilisant une matrice \(k \times k\) de polynômes dans \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Pour \(k = 1\): se réduit à RLWE
  • Pour \(k \to \infty\) (polynômes de degré 0): se réduit à LWE classique

Le paramètre \(k\) permet de calibrer sécurité et performance indépendamment de \(n\).

Variante Clé publique Sécurité Flexibilité
LWE \(O(n^2)\) élevée faible
RLWE \(O(n)\) moyenne faible
MLWE \(O(k \cdot n)\) réglable avec \(k\) élevée

5.2 Définition formelle de MLWE

Espace de travail

Paramètres fixés:

  • \(n = 256\): degré du polynôme cyclotomique
  • \(q = 3329\): module premier
  • \(k \in \{2, 3, 4\}\): dimension du module
  • \(\chi\): distribution du bruit (distribution binomiale centrée \(B_\eta\))

L'anneau de base est \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Distribution MLWE

Soit \(\mathbf{s} \in R_q^k\) un vecteur secret de polynômes, chacun avec des coefficients échantillonnés depuis \(\chi\).

Une instance MLWE est une paire:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{où} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

avec \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Problème décisionnel MLWE

Entrée: \((\mathbf{A}, \mathbf{t})\) où:

  • soit \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (distribution MLWE), soit
  • soit \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) uniforme

Objectif: distinguer les deux cas avec un avantage non négligeable.

Problème de recherche MLWE

Entrée: \((\mathbf{A}, \mathbf{t})\) avec \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Objectif: trouver \(\mathbf{s}\).

La réduction de Regev (adaptée à MLWE) démontre que le problème de recherche est computationnellement équivalent au problème décisionnel, et que les deux sont au moins aussi difficiles que GapSVP sur des treillis de haute dimension.

5.3 La distribution du bruit dans ML-KEM

Distribution binomiale centrée \(B_\eta\)

Dans ML-KEM, le bruit n'est pas gaussien mais binomial centré. Pour échantillonner un seul coefficient depuis \(B_\eta\):

  1. Échantillonner \(2\eta\) bits uniformes: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Retourner \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

Le résultat est un entier dans \([-\eta, \eta]\).

Distribution de probabilité pour η = 2:

Valeur Probabilité
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Pourquoi pas une vraie gaussienne?

La gaussienne discrète est théoriquement optimale, mais l'échantillonner de manière constant-time (résistante aux attaques temporelles) est complexe. La binomiale centrée:

  • a un support fini → pas de cas extrêmes
  • s'échantillonne avec seulement des opérations sur bits → trivialement constant-time
  • est statistiquement indiscernable de la gaussienne pour les attaques connues

Échantillonnage dans ML-KEM (fonction SamplePolyCBD)

CBD_η(σ, b): Entrée: graine σ ∈ {0,1}^256, nonce b ∈ {0,1}^8 Sortie: polynôme f ∈ R_q avec coefficients dans [-η, η] bytes = PRF(σ, b) // SHAKE256, génère 64η octets pour j = 0..255: a = somme des bits de bytes aux positions [2ηj .. 2ηj+η-1] b = somme des bits de bytes aux positions [2ηj+η .. 2ηj+2η-1] f[j] = a - b retourner f

Chaque polynôme \(\mathbf{s}[i]\) et \(\mathbf{e}[i]\) est échantillonné avec un nonce différent, garantissant l'indépendance statistique.

5.4 Échantillonnage dans ML-KEM

CBD: Centered Binomial Distribution

ML-KEM utilise une distribution binomiale centrée \(B_\eta\) pour générer de petites erreurs et secrets. Cette distribution est efficace et ne nécessite pas de rejet d'échantillonnage.

Fonction SamplePolyCBD(σ, b, η)

Entrée: graine σ ∈ {0,1}^256, nonce b, paramètre η
Sortie: polynôme f ∈ R_q avec coeff. dans [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, génère 64·η octets
2. Pour j = 0 à 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // compte les 1 dans le premier groupe
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // compte les 1 dans le deuxième groupe
     f[j] = a - b                     // différence centrée sur 0
3. Retourner f

Pour \(\eta=2\), les coefficients sont dans \(\{-2, -1, 0, 1, 2\}\). Pour \(\eta=3\), dans \(\{-3, \ldots, 3\}\).

SampleNTT: Échantillonnage Uniforme

Pour générer la matrice publique \(\mathbf{A}\), des coefficients uniformes dans \(\mathbb{Z}_q\) sont nécessaires. On utilise le rejet d'échantillonnage sur la sortie de SHAKE128.

Fonction SampleNTT(flux)

Entrée: flux d'octets de XOF (SHAKE128)
Sortie: polynôme avec coeff. uniformes dans [0, q-1]

coefficients = []
tant que len(coefficients) < 256:
    // Lire 3 octets pour générer 2 valeurs candidates
    b0, b1, b2 = next_3_bytes(flux)
    
    // Combiner les bits pour former deux nombres de 12 bits
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2
    
    // Accepter seulement si < q (3329)
    si d1 < q:
        coefficients.append(d1)
    si d2 < q et len(coefficients) < 256:
        coefficients.append(d2)

retourner coefficients

Cette méthode garantit une distribution uniforme parfaite, en rejetant les valeurs hors de la plage.

5.5 Hardness: pourquoi MLWE est difficile

Réduction worst-case à average-case

La propriété la plus importante de LWE/MLWE est la réduction du pire cas au cas moyen:

S'il existe un algorithme efficace qui résout MLWE pour une fraction non négligeable d'instances aléatoires, alors il existe un algorithme efficace pour résoudre GapSVP (la version approchée de SVP) sur n'importe quel treillis, dans le pire cas.

Cette réduction (Regev 2005, adaptée par Peikert 2009 et Brakerski et al. pour MLWE) est exceptionnelle: la plupart des problèmes cryptographiques n'ont que des réductions du cas moyen au cas moyen.

En pratique: casser MLWE sur des instances aléatoires est aussi difficile que de résoudre SVP dans le pire cas → les hypothèses cryptographiques sont extrêmement solides.

Absence de structure exploitable par les quantiques

L'algorithme de Shor exploite la structure de groupe abélien des problèmes de factorisation et de logarithme discret: il existe une action de groupe périodique que la QFT peut détecter.

MLWE n'a pas cette structure:

  • Il n'y a pas de périodicité à exploiter
  • Il n'y a pas de groupe abélien naturel sur lequel appliquer la QFT
  • Les meilleurs algorithmes quantiques (basés sur des marches quantiques ou QRAM) offrent au plus une accélération polynomiale, pas exponentielle

5.6 De MLWE à un PKE: l'idée constructive

Comment construit-on un système de chiffrement à partir de MLWE? L'intuition est élégante.

Analogie avec Diffie-Hellman

En DH, la clé publique est \(g^s\): facile à calculer, difficile à inverser.
En MLWE, la clé publique est \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): facile à calculer, difficile à inverser.

Schéma de chiffrement (de type Regev)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Clé publique: \((\mathbf{A}, \mathbf{t})\).
Clé privée: \(\mathbf{s}\).

Encrypt (message \(m \in \{0,1\}\), encodé comme \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Chiffré: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Analyse:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{bruit petit}} + \mu \approx \mu \]

Le bruit est petit → l'arrondi permet de récupérer \(\mu\) et donc \(m\).

La version polynomiale (MLWE réel)

Dans ML-KEM, chaque scalaire devient un polynôme dans \(R_q\), et les opérations sont des produits polynomiaux. Le mécanisme est identique, mais les multiplications se font dans l'anneau:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

où \(\circ\) est la multiplication dans \(R_q\) (polynomiale, accélérée par NTT).

5.7 Exemple numérique complet

Utilisons des paramètres jouets: \(n = 4\), \(q = 17\), \(k = 2\), coefficients petits dans \(\{-1, 0, 1\}\).

Les polynômes sont dans \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), donc de degré \(\leq 3\).

Données de départ

Matrice publique \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

avec \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Secret \(\mathbf{s} = (s_0, s_1)^T\) avec \(s_0 = 1 - X\), \(s_1 = X^2\).

Erreur \(\mathbf{e} = (e_0, e_1)^T\) avec \(e_0 = 1\), \(e_1 = -X\).

Calcul de t = As + e

Composante t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Réduisons \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Résultat: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (la seconde composante se calcule de manière analogue).

Observation clé

Un adversaire qui voit \((\mathbf{A}, \mathbf{t})\) doit trouver \((\mathbf{s}, \mathbf{e})\). Même avec ces petits nombres, le problème est déjà non trivial: il ne peut pas utiliser l'élimination gaussienne (l'erreur brise la linéarité) et l'espace de recherche est exponentiel dans la dimension réelle de ML-KEM.

5.8 Pourquoi les paramètres de ML-KEM sont ceux qu'ils sont

\(n = 256\)

  • Doit être une puissance de 2 (pour NTT efficace)
  • Le polynôme \(X^{256}+1\) doit être irréductible sur \(\mathbb{Z}_q\): il l'est si \(q \equiv 1 \pmod{512}\)
  • \(256\) équilibre sécurité et performance: \(n = 128\) serait trop peu sécurisé, \(n = 512\) trop lent

\(q = 3329\)

  • Doit être premier (pour \(\mathbb{Z}_q\) corps)
  • Doit satisfaire \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Doit être tel qu'il existe des racines 256-ièmes de l'unité: garanti par la condition ci-dessus
  • Doit être le plus petit possible (clés compactes) tout en étant compatible avec le budget de bruit
  • \(3329\) est le premier premier qui satisfait toutes les conditions avec suffisamment de marge pour le bruit

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): niveau 1 NIST, équivalent à AES-128 pré-quantique
  • \(k = 3\) (ML-KEM-768): niveau 3, équivalent à AES-192, recommandé pour un usage général
  • \(k = 4\) (ML-KEM-1024): niveau 5, équivalent à AES-256, pour les systèmes à haute criticité

\(\eta_1, \eta_2 \in \{2, 3\}\)

Le bruit doit être:

  • assez grand pour rendre le problème MLWE difficile
  • assez petit pour garantir que le déchiffrement ne échoue pas (budget de bruit)

Augmenter \(\eta\) augmente la sécurité mais aussi la probabilité d'erreur de déchiffrement. Les valeurs \(\eta_1 = 2, \eta_2 = 2\) pour ML-KEM-768 sont le point optimal.
