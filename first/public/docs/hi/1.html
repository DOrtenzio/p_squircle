1.1 सममित क्रिप्टोग्राफी क्या है

एक सममित क्रिप्टोग्राफी प्रणाली में, प्रेषक और प्राप्तकर्ता एन्क्रिप्ट और डिक्रिप्ट करने के लिए एक ही कुंजी \(K\) का उपयोग करते हैं।

\(\text{प्रेषक: } C = \text{Enc}(K, M)\)

\(\text{प्राप्तकर्ता: } M = \text{Dec}(K, C)\)

मुख्य लाभ: दक्षता। आधुनिक हार्डवेयर पर AES-256 दसियों GB/s की गति प्राप्त करता है।

नुकसान: संचार करने से पहले \(K\) का सुरक्षित आदान-प्रदान करने के लिए एक सुरक्षित चैनल की आवश्यकता होती है। यह ठीक वही समस्या है जिसे KEM हल करते हैं।

सममित क्रिप्टोग्राफी की सुरक्षा बनाम क्वांटम

क्वांटम कंप्यूटर AES को नहीं तोड़ते। ग्रोवर का एल्गोरिथ्म कुंजी खोज में द्विघात त्वरण प्रदान करता है, लेकिन:

  • AES-128: 128 बिट से प्रभावी सुरक्षा घटकर ~64 बिट हो जाती है → अपर्याप्त
  • AES-256: 256 बिट से प्रभावी सुरक्षा घटकर ~128 बिट हो जाती है → अभी भी सुरक्षित

इसीलिए FIPS 203 (ML-KEM) 256-बिट कुंजियाँ उत्पन्न करता है, जिनका उपयोग AES-256 के साथ करने का इरादा है।

1.2 AES: उन्नत एन्क्रिप्शन मानक

AES एक ब्लॉक सिफर है: यह 128-बिट ब्लॉक और एक कुंजी (\(K\)) लेता है, और 128-बिट एन्क्रिप्टेड आउटपुट उत्पन्न करता है।

आंतरिक संरचना

AES इनपुट के 128 बिट्स को बाइट्स की \(4 \times 4\) मैट्रिक्स के रूप में व्यवस्थित करता है। फिर यह कुंजी के आकार के आधार पर \(r\) राउंड (10, 12 या 14) लागू करता है, प्रत्येक राउंड चार परिवर्तनों से बना होता है:

परिवर्तन उद्देश्य
SubBytes S-बॉक्स के माध्यम से अरेखीय प्रतिस्थापन (विभेदक क्रिप्टो-विश्लेषण के प्रति प्रतिरोध)
ShiftRows पंक्तियों का चक्रीय घुमाव (प्रसार)
MixColumns स्तंभों का रैखिक संयोजन (प्रसार)
AddRoundKey वर्तमान राउंड की सब-कुंजी के साथ XOR

कुंजी अनुसूची (Key Schedule)

मूल कुंजी (\(K\) 128, 192 या 256 बिट की) को प्रत्येक राउंड के लिए \(r+1\) सब-कुंजियों में विस्तारित किया जाता है।

AES-128: 128-बिट कुंजी, 10 राउंड

AES-192: 192-बिट कुंजी, 12 राउंड

AES-256: 256-बिट कुंजी, 14 राउंड

सुरक्षा

AES-128 पर सबसे अच्छा ज्ञात हमला \(2^{126.1}\) ऑपरेशन की आवश्यकता है (Biryukov & Khovratovich, 2009) – अनिवार्य रूप से ब्रूट-फोर्स।

1.3 ऑपरेटिंग मोड

AES 128-बिट के एक ब्लॉक को एन्क्रिप्ट करता है। लेकिन वास्तविक संदेश लंबे होते हैं। ऑपरेटिंग मोड परिभाषित करते हैं कि AES को बार-बार कैसे लागू किया जाए।

ECB (Electronic Codebook) – उपयोग न करें

प्रत्येक ब्लॉक स्वतंत्र रूप से एन्क्रिप्ट किया जाता है। समान ब्लॉक समान सिफरटेक्स्ट उत्पन्न करते हैं → प्लेनटेक्स्ट की संरचना खो जाती है।

CBC (Cipher Block Chaining)

प्रत्येक प्लेनटेक्स्ट ब्लॉक को एन्क्रिप्ट करने से पहले पिछले ब्लॉक के सिफरटेक्स्ट के साथ XOR किया जाता है। एक यादृच्छिक IV (Initialization Vector) की आवश्यकता होती है।

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

ECB से अधिक सुरक्षित, लेकिन एन्क्रिप्शन में समानांतरीकरण योग्य नहीं।

CTR (Counter Mode) – अनुशंसित

एक वृद्धिशील काउंटर को एन्क्रिप्ट करके कीस्ट्रीम उत्पन्न करता है। प्लेनटेक्स्ट को कीस्ट्रीम के साथ XOR किया जाता है।

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

एन्क्रिप्शन और डिक्रिप्शन दोनों में समानांतरीकरण योग्य। AES को स्ट्रीम सिफर में बदल देता है।

GCM (Galois/Counter Mode) – TLS 1.3 में उपयोग किया जाता है

CTR को गैलोइस फ़ील्ड पर आधारित MAC के साथ जोड़ता है। गोपनीयता और प्रामाणिकता प्रदान करता है।

1.4 प्रमाणीकरण और AEAD

गोपनीयता पर्याप्त नहीं है: एक हमलावर सिफरटेक्स्ट को इस तरह संशोधित कर सकता है कि प्राप्तकर्ता को पता न चले। प्रामाणिकता की आवश्यकता है।

MAC (Message Authentication Code)

MAC एक फलन है \(\text{MAC}(K, M) \to \tau\) जहाँ \(\tau\) प्रामाणिकता टैग है। केवल \(K\) जानने वाला ही \(\tau\) उत्पन्न और सत्यापित कर सकता है।

AEAD (Authenticated Encryption with Associated Data)

एक ही प्राइमिटिव में एन्क्रिप्शन और प्रमाणीकरण को जोड़ता है:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) या \(\perp\) (यदि टैग अमान्य हो)

AAD (Additional Authenticated Data) वह डेटा है जो प्रमाणित तो होता है लेकिन एन्क्रिप्ट नहीं होता (जैसे पैकेट हेडर)।

AES-256-GCM TLS 1.3 में उपयोग किया जाने वाला मानक AEAD स्कीम है और KEM के बाद सममित सिफर के रूप में भी।

1.5 PQC संदर्भ में भूमिका

वास्तविक उपयोग में एक पूर्ण ML-KEM इस प्रकार काम करता है:

ऐलिस बॉब | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, संदेश) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | संदेश = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ सुरक्षित संचार |

ML-KEM (32 बाइट) द्वारा उत्पादित कुंजी \(K\) का उपयोग सीधे AES कुंजी के रूप में नहीं किया जाता है, बल्कि विभिन्न संदर्भों को अलग करने के लिए HKDF जैसे KDF (Key Derivation Function) के साथ व्युत्पन्न किया जाता है।

व्यावहारिक आकार (ML-KEM-768 + AES-256-GCM)

घटक आकार

ML-KEM सिफरटेक्स्ट 1088 बाइट
साझा रहस्य → AES कुंजी 32 बाइट
