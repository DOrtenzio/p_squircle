9.1 セキュリティモデル

IND-CPA（選択平文攻撃に対する識別不可能性）

このモデルでは、攻撃者は：

  1. 公開鍵 \(ek\) を受け取る
  2. 2つのメッセージ \(m_0, m_1\) を選択する
  3. そのうちの1つ（ランダムに選択）の暗号文を受け取る
  4. どちらのメッセージが暗号化されたかを推測する

スキームは次の場合に安全です：\(\Pr[\text{推測成功}] \leq 1/2 + \text{negl}(\lambda)\)。

K-PKE（基本暗号化コンポーネント）は MLWE 仮定の下で IND-CPA です。

IND-CCA2（適応的選択暗号文攻撃に対する識別不可能性）

CPA と同様ですが、攻撃者はチャレンジ暗号文以外の任意の暗号文に対する復号オラクルに問い合わせることができます。このモデルは、攻撃者がアドホックに構築したメッセージを送信し、応答を観察する実際の攻撃（Bleichenbacher など）を捉えます。

ML-KEM は IND-CCA2 です。 これは、TLS や SSH などの実際のプロトコルで安全な KEM に要求されるレベルです。

ROM vs. QROM

セキュリティ証明はハッシュ関数に理想化されたモデルを使用します。

  • ROM（ランダムオラクルモデル）： ハッシュは完全にランダムなオラクルです。
  • QROM（量子ランダムオラクルモデル）： 量子攻撃者はオラクルを重ね合わせで問い合わせることができます。

ML-KEM で使用される FO（Fujisaki-Okamoto）変換の現代的な証明は QROM でのセキュリティを保証し、量子攻撃者に対して不可欠です。

9.2 MLWE の困難性の測定

攻撃コストとしてのセキュリティ

MLWE が困難であるという絶対的な証明は存在しません。セキュリティは、既知の最良の攻撃アルゴリズムのコストを見積もることによって評価されます。\(\lambda\) ビットのセキュリティは、攻撃に約 \(2^\lambda\) 回の演算が必要であることを意味します。

パラメータ

困難性は以下に依存します。

  • \(n = 256\)（多項式次元、固定）
  • \(k \in \{2, 3, 4\}\)（モジュール次元）
  • \(q = 3329\)（素数法）
  • \(\eta \in \{2, 3\}\)（ノイズ振幅）

格子推定器（Lattice Estimator）

標準的なツールは Albrecht らの Lattice Estimator です。ML-KEM-768 の場合：

攻撃 推定コスト（ビット）
Primal attack（BKZ） ~178 ビット
Dual attack ~175 ビット
Combinatorial > 200 ビット

セキュリティマージンは、古典的/量子的な 128 ビットのターゲットに対して大きく余裕があります。

9.3 格子に対する主要な攻撃

BKZ（Block Korkine-Zolotarev）

これは短いベクトルを見つけるための最良の汎用アルゴリズムです。格子をブロックサイズ \(\beta\) のブロックに分割し、局所的に SVP を解きます。複雑さ：\(2^{O(\beta \log \beta)}\)。ML-KEM-768 の場合、\(\beta \approx 430\) です。

Primal attack（uSVP）

MLWE を、公開鍵と暗号文を含む拡張格子における短ベクトル問題に帰着させます。秘密ベクトル \((\mathbf{s}, \mathbf{e}, -1)\) は BKZ が探す短ベクトルになります。

Dual attack

双対格子を利用して、MLWE サンプルを一様サンプルから統計的に区別します。双対格子内の多くの短ベクトルを構築して識別器を実行します。

\(q = 3329\) の選択

素数であり、特殊な代数構造を持たないため、特定の代数攻撃を防ぎます。悪用可能な小さな因数や単純な関係は存在しません。

9.4 NIST セキュリティレベル

NIST は 5 つのレベルを定義しています。ML-KEM はレベル 1、3、5 をカバーします。

スキーム NIST レベル 古典的セキュリティ 量子的セキュリティ
ML-KEM-512 1（AES-128） ~118 ビット ~100 ビット
ML-KEM-768 3（AES-192） ~178 ビット ~164 ビット
ML-KEM-1024 5（AES-256） ~230 ビット ~218 ビット

推奨： ML-KEM-768 は、ほとんどの用途においてセキュリティとパフォーマンスの最適なバランスを提供します。ML-KEM-1024 は非常に高重要度のシステムのために予約されています。

9.6 サイドチャネルと安全な実装

正しい実装でも、実行時間や消費電力などの情報が漏洩する場合、脆弱になる可能性があります。

定数時間（CT）

すべての演算は、秘密データに関係なく一定の時間で実行されなければなりません。Decaps での重要な例：

// 安全でない（変動時間）：
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// 安全（定数時間）：
uint8_t mask = ct_memcmp(c, c_prime, len); // 一致なら 0xFF、不一致なら 0x00
K = ct_select(mask, K_good, K_reject);     // 分岐なしの CT 選択

ML-KEM における CT の重要領域

  • \(B_\eta\) サンプリング： 条件分岐なしのビット加算。
  • NTT： バタフライ演算は、結果が変わらない場合でも常に実行されなければなりません。
  • 暗号文検証： ct_memcmp の使用。

リファレンス実装

  • pqclean：ポータブルな CT 実装。
  • liboqs：CT 特性が検証された AVX2 最適化。
