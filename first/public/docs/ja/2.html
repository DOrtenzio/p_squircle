2.1 鍵共有の問題

アリスは公開チャネル上でボブと安全に通信したいと考えています。AES を使用するには共有鍵が必要です。Eve（すべてを傍受している）に知られることなく、どうやってそれを確立するのでしょうか？

この問題は何世紀にもわたって未解決でした。解決策は 1976 年に Diffie と Hellman によってもたらされ、1977 年には Rivest、Shamir、Adleman（RSA） によってもたらされました。

核となるアイデア：一方通行は簡単で、逆方向は難しい 数学的演算が存在するということです。

簡単な演算 難しい演算
2つの大きな素数を掛ける：\(p \cdot q = n\) \(n\) を因数分解して \(p\) と \(q\) を見つける
\(g^x \bmod p\) を計算する \(g^x \bmod p\) から \(x\) を見つける（離散対数）
楕円曲線上の点を \(k\) 回加算する：\(kP\) \(kP\) から \(k\) を見つける（ECDLP）

2.2 RSA

鍵生成

  1. 2つの大きな素数 \(p\) と \(q\) を選択する（通常それぞれ 2048+ ビット）
  2. \(n = p \cdot q\) を計算する
  3. \(\phi(n) = (p-1)(q-1)\) を計算する
  4. \(\gcd(e, \phi(n)) = 1\) となる \(e\) を選択する（通常 \(e = 65537\)）
  5. \(d = e^{-1} \bmod \phi(n)\) を計算する

公開鍵： \((n, e)\)
秘密鍵： \((n, d)\)
\(p\)、\(q\)、\(\phi(n)\) は破棄されます。

暗号化と復号

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

なぜ機能するのか： オイラーの定理により、\(M^{\phi(n)} \equiv 1 \pmod{n}\) であるため、\(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\) となります。

数値例（教育目的の小さな数値）

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{（なぜなら } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{）}\)

\(M = 65\) を暗号化：

\(C = 65^{17} \bmod 3233 = 2790\)

復号：

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA を KEM として使用

RSA-KEM（簡略化）：

  1. ボブがランダムに \(r \leftarrow \{1, \ldots, n-1\}\) を選択
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\)（対称鍵）
  4. \(C\) をアリスに送信
  5. アリスが \(r = C^d \bmod n\) を計算し、\(K = H(r)\) を計算

2.3 Diffie-Hellman（DH）

プロトコル

公開パラメータ：大きな素数 \(p\) と \(\mathbb{Z}_p^*\) の生成元 \(g\)。

アリス
  1. 秘密の \(a\) を選択
  2. \(A = g^a \bmod p\) を計算
A → ← B
ボブ
  1. 秘密の \(b\) を選択
  2. \(B = g^b \bmod p\) を計算
\[ \begin{aligned} \text{アリスが計算： } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{ボブが計算： } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

結果： 両者が同じ秘密鍵 \(K\) を共有します。Eve は \(A\) と \(B\) しか見ることができず、離散対数問題を解くことなく \(K\) を計算することはできません。

2.4 楕円曲線暗号（ECDH）

ECDH は DH の楕円曲線版です。TLS 1.3 で X25519 曲線とともに使用されています。

アリス
  1. 秘密の \(a\) を選択
  2. \(A = a \cdot G\) を計算
A → ← B
ボブ
  1. 秘密の \(b\) を選択
  2. \(B = b \cdot G\) を計算
\[ \begin{aligned} \text{アリスが計算： } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{ボブが計算： } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

ここで \(G\) は曲線の生成点です。セキュリティは ECDLP（楕円曲線離散対数問題）の困難性に基づいています。

2.4 楕円曲線暗号（ECC）

楕円曲線とは

\(\mathbb{Z}_p\) 上の楕円曲線は、次の方程式を満たす点 \((x, y)\) の集合です。

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

これに特殊な点 \(\mathcal{O}\)（無限遠点）を加えたものです。

これらの点には加法演算が定義され、群の性質を持ちます。

スカラー倍算

点の加法を利用して、スカラー倍算を定義します。

\(kP = P + P + \cdots + P \quad (k \text{ 回})\)

\(P\) と \(k\) から \(kP\) を計算するのは簡単です（\(O(\log k)\) 回の演算）。逆問題 – \(P\) と \(kP\) から \(k\) を見つける – は 楕円曲線離散対数問題（ECDLP） であり、計算量的に困難です。

RSA/DH に対する ECC の利点

同等のセキュリティ RSA/DH（n/p のビット数） ECC（鍵のビット数）
80 ビット 1024 160
128 ビット 3072 256
256 ビット 15360 512

ECC は同じセキュリティレベルではるかに小さな鍵を提供します → より効率的です。

ECDH（楕円曲線 Diffie-Hellman）

アリス ボブ | | | 秘密の a を選択 | 秘密の b を選択 | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ 共有鍵 K |

ECDH は TLS 1.3 で X25519（Bernstein の Curve25519）とともに使用されています。

2.5 古典的セキュリティと量子限界

古典コンピュータに対する安全性

RSA と ECC の基盤となる問題は、古典コンピュータに対して準指数関数的（純粋な指数関数ではない）です。

因数分解に対する最良の古典的アルゴリズムは 一般数体篩法（GNFS） です。

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

2048 ビットの \(n\) の場合、これは天文学的に長い時間がかかります → 実用上は安全です。

量子コンピュータに対する安全性：Shor のアルゴリズム

1994 年、Peter Shor は量子コンピュータが以下を実現できることを示しました。

  • \(n\) を \(O((\log n)^3)\) 時間で因数分解する
  • \(O((\log p)^3)\) 時間でDLP を解く
  • \(O((\log p)^3)\) 時間でECDLP を解く

十分な量子ビットを持つ量子コンピュータは、RSA-2048 を数時間から数日で破ります。

Shor のアルゴリズムの詳細な分析はファイル 03 – Shor のアルゴリズム にあります。

答え：耐量子暗号

量子時代においても安全な公開鍵暗号を維持するには、効率的な量子アルゴリズムが知られていない数学的問題が必要です。

ML-KEM の基盤となる格子問題はこの要件を満たします。既知の最良の量子アルゴリズムは、古典的アルゴリズムと比較してせいぜい小幅な高速化しか提供しません。
