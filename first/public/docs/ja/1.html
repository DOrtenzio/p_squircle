01 – 対称鍵暗号

PQC の全行程の実践的な到達点

目次

1.1 対称鍵暗号とは

対称鍵暗号システムでは、送信者と受信者は暗号化と復号に同じ鍵 \(K\) を使用します。

\(\text{送信者: } C = \text{Enc}(K, M)\)

\(\text{受信者: } M = \text{Dec}(K, C)\)

主な利点：効率性。AES-256 は最新のハードウェアで毎秒数十 GB の速度を達成します。

欠点：通信を開始する前に \(K\) を安全に交換するための安全なチャネルが必要です。これはまさに KEM が解決する問題です。

対称鍵暗号のセキュリティ vs. 量子コンピュータ

量子コンピュータは AES を破りません。Grover のアルゴリズムは鍵探索において二次の高速化をもたらしますが、

  • AES-128： 実効セキュリティが 128 ビットから約 64 ビットに低下 → 不十分
  • AES-256： 実効セキュリティが 256 ビットから約 128 ビットに低下 → 依然として安全

このため、FIPS 203（ML-KEM）は AES-256 で使用することを意図した 256 ビットの鍵を生成します。

1.2 AES：Advanced Encryption Standard

AES はブロック暗号です。128 ビットのブロックと鍵（\(K\)）を入力として受け取り、128 ビットの暗号文を出力します。

内部構造

AES は入力 128 ビットをバイトの \(4 \times 4\) 行列として整理します。次に、鍵サイズに応じて \(r\) ラウンド（10、12、または 14）を適用します。各ラウンドは 4 つの変換から構成されます。

変換 目的
SubBytes S-Box による非線形置換（差分解読法への耐性）
ShiftRows 行の巡回シフト（拡散）
MixColumns 列の線形結合（拡散）
AddRoundKey 現在のラウンド鍵との XOR

鍵スケジュール

元の鍵（\(K\)、128、192、または 256 ビット）は、各ラウンドに 1 つずつ、\(r+1\) 個のラウンド鍵に展開されます。

AES-128：128 ビット鍵、10 ラウンド

AES-192：192 ビット鍵、12 ラウンド

AES-256：256 ビット鍵、14 ラウンド

セキュリティ

AES-128 に対する既知の最良の攻撃は \(2^{126.1}\) 回の演算を必要とします（Biryukov & Khovratovich, 2009）– 実質的には総当たり攻撃です。

1.3 動作モード

AES は 128 ビットのブロックを暗号化します。しかし、実際のメッセージはより長いです。動作モードは、AES を繰り返し適用する方法を定義します。

ECB（電子コードブック） – 使用禁止

各ブロックは独立して暗号化されます。同一のブロックは同一の暗号文を生成します → 平文の構造が漏洩します。

CBC（暗号ブロック連鎖）

各平文ブロックは、暗号化される前に前のブロックの暗号文と XOR されます。ランダムな IV（初期化ベクトル）が必要です。

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

ECB よりも安全ですが、暗号化は並列化できません。

CTR（カウンタモード） – 推奨

増分カウンタを暗号化してキーストリームを生成します。平文はキーストリームと XOR されます。

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

暗号化と復号の両方で並列化可能です。AES をストリーム暗号に変換します。

GCM（ガロア/カウンタモード） – TLS 1.3 で使用

CTR とガロア体ベースの MAC を組み合わせます。機密性と完全性を提供します。

1.4 認証と AEAD

機密性だけでは不十分です。攻撃者が受信者に気付かれずに暗号文を改ざんする可能性があります。完全性が必要です。

MAC（メッセージ認証コード）

MAC は関数 \(\text{MAC}(K, M) \to \tau\) で、\(\tau\) は認証タグです。\(K\) を知っている者だけが \(\tau\) を生成および検証できます。

AEAD（関連データ付き認証付き暗号化）

暗号化と認証を単一のプリミティブに組み合わせます。

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{平文}) \to (\text{暗号文}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{暗号文}, \text{tag}) \to \text{平文}\) または \(\perp\)（タグが無効な場合）

AAD（追加認証データ）は、認証されるが暗号化されないデータです（例：パケットヘッダー）。

AES-256-GCM は、TLS 1.3 で使用される標準的な AEAD スキームであり、KEM 後の対称暗号としても使用されます。

1.5 PQC における役割

実際の使用における完全な ML-KEM は次のように機能します。

アリス ボブ | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, メッセージ) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | メッセージ = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ 安全な通信 |

ML-KEM によって生成された鍵 \(K\)（32 バイト）は、AES 鍵として直接使用されるのではなく、異なるコンテキストを分離するために KDF（鍵導出関数）（HKDF など）で導出されます。

実用的なサイズ（ML-KEM-768 + AES-256-GCM）

コンポーネント サイズ
ML-KEM 公開鍵 1184 バイト
ML-KEM 暗号文 1088 バイト
共有秘密 → AES 鍵 32 バイト
AEAD オーバーヘッド（GCM タグ） 16 バイト
