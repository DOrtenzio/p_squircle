01 – التشفير المتماثل

1.1 ما هو التشفير المتماثل

في نظام متماثل للتشفير، يستخدم المرسل والمستقبل نفس المفتاح \(K\) للتشفير وفك التشفير.

\(\text{المرسل: } C = \text{Enc}(K, M)\)

\(\text{المستقبل: } M = \text{Dec}(K, C)\)

الميزة الرئيسية: الكفاءة. يحقق AES-256 على الأجهزة الحديثة عشرات الـ GB/s.

العيب: يحتاج إلى قناة آمنة لتبادل \(K\) قبل التواصل. هذه هي بالضبط المشكلة التي تحلها أنظمة KEM.

أمن التشفير المتماثل مقابل الكمومي

أجهزة الكمبيوتر الكمومية لا تكسر AES. تقدم خوارزمية غروفر تسريعاً تربيعياً في البحث عن المفتاح، لكن:

  • AES-128: الأمن الفعال من 128 بت ينخفض إلى ~64 بت → غير كافٍ
  • AES-256: الأمن الفعال من 256 بت ينخفض إلى ~128 بت → لا يزال آمناً

لهذا السبب ينتج FIPS 203 (ML-KEM) مفاتيح بطول 256 بت، مخصصة للاستخدام مع AES-256.

1.2 AES: معيار التشفير المتقدم

AES هو شيفرة كتلية: يأخذ كتلة من 128 بت ومفتاحاً (\(K\))، وينتج 128 بت مشفرة.

التركيب الداخلي

ينظم AES 128 بت المدخلات كمصفوفة \(4 \times 4\) من البايتات. ثم يطبق \(r\) جولة (10، 12 أو 14 حسب حجم المفتاح)، كل منها تتألف من أربع تحويلات:

التحويل الغرض
SubBytes استبدال لاخطي عبر S-Box (مقاومة للتحليل التفاضلي)
ShiftRows إزاحة دورانية للصفوف (نشر)
MixColumns تركيب خطي للأعمدة (نشر)
AddRoundKey XOR مع المفتاح الفرعي للجولة الحالية

جدولة المفاتيح

يتم توسيع المفتاح الأصلي (\(K\) بطول 128 أو 192 أو 256 بت) إلى \(r+1\) مفتاحاً فرعياً، واحد لكل جولة.

AES-128: مفتاح 128 بت، 10 جولات

AES-192: مفتاح 192 بت، 12 جولة

AES-256: مفتاح 256 بت، 14 جولة

الأمن

أفضل هجوم معروف على AES-128 يتطلب \(2^{126.1}\) عملية (Biryukov & Khovratovich، 2009) – جوهرها بحث شامل.

1.3 أنماط التشغيل

AES يشفر كتلة من 128 بت. لكن الرسائل الحقيقية أطول. أنماط التشغيل تحدد كيفية تطبيق AES بشكل متكرر.

ECB (كتاب الشفرات الإلكتروني) – لا يُستخدم

يتم تشفير كل كتلة بشكل مستقل. الكتل المتطابقة تنتج نصوصاً مشفرة متطابقة → تفقد بنية النص العادي.

CBC (تسلسل كتل الشفرات)

يتم XOR كل كتلة نص عادي مع النص المشفر للكتلة السابقة قبل التشفير. يتطلب IV (متجه تهيئة) عشوائياً.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

أكثر أماناً من ECB، لكنه غير قابل للتوازي في التشفير.

CTR (نمط العداد) – موصى به

ينشئ تدفقاً مفتاحياً عن طريق تشفير عداد متزايد. يتم XOR النص العادي مع التدفق المفتاحي.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

قابل للتوازي في كل من التشفير وفك التشفير. يحول AES إلى شيفرة تدفقية.

GCM (نمط غالوا/العداد) – مستخدم في TLS 1.3

يجمع CTR مع MAC مبني على حقول غالوا. يوفر سرية و صحة.

1.4 المصادقة و AEAD

السرية وحدها لا تكفي: قد يعدل المهاجم النص المشفر دون أن يلاحظ المستقبل. هناك حاجة إلى صحة.

MAC (رمز مصادقة الرسالة)

MAC هو دالة \(\text{MAC}(K, M) \to \tau\) حيث \(\tau\) هو وسم الصحة. فقط من يعرف \(K\) يمكنه توليد والتحقق من \(\tau\).

AEAD (تشفير مصادق مع بيانات مرتبطة)

يجمع التشفير والمصادقة في بدائية واحدة:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{نص عادي}) \to (\text{نص مشفر}, \text{وسم})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{نص مشفر}, \text{وسم}) \to \text{نص عادي}\) أو \(\perp\) (إذا كان الوسم غير صالح)

AAD (بيانات إضافية مصادق عليها) هي بيانات مصادق عليها ولكن غير مشفرة (مثل رؤوس الحزم).

AES-256-GCM هو مخطط AEAD القياسي المستخدم في TLS 1.3 وكشيفرة متماثلة بعد KEM.

1.5 الدور في سياق التشفير ما بعد الكمي

يعمل ML-KEM الكامل في الاستخدام الحقيقي على النحو التالي:

أليس بوب | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, الرسالة) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | الرسالة = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ تواصل آمن |

المفتاح \(K\) الناتج من ML-KEM (32 بايت) لا يُستخدم مباشرة كمفتاح AES، بل يُشتق باستخدام KDF (دالة اشتقاق المفاتيح) مثل HKDF لفصل السياقات المختلفة.

الأحجام العملية (ML-KEM-768 + AES-256-GCM)

المكون الحجم
المفتاح العام ML-KEM 1184 بايت
النص المشفر ML-KEM 1088 بايت
السر المشترك → مفتاح AES 32 بايت
العبء الإضافي AEAD (وسم GCM) 16 بايت
