Por que o ML-KEM é seguro e como os números foram escolhidos

9.1 Modelos de segurança

IND-CPA (Indistinguibilidade sob Ataque de Texto Claro Escolhido)

Neste modelo, um adversário:

  1. Recebe a chave pública \(ek\)
  2. Escolhe duas mensagens \(m_0, m_1\)
  3. Recebe o texto cifrado de uma delas (escolhida aleatoriamente)
  4. Deve adivinhar qual mensagem foi cifrada

O esquema é seguro se: \(\Pr[\text{adivinha}] \leq 1/2 + \text{negl}(\lambda)\).

O K-PKE (o componente de cifra base) é IND-CPA sob a suposição MLWE.

IND-CCA2 (Indistinguibilidade sob Ataque Adaptativo de Texto Cifrado Escolhido)

Como CPA, mas o adversário também pode consultar um oráculo de decifra em qualquer texto cifrado (exceto o texto cifrado desafio). Este modelo capta ataques reais (como Bleichenbacher), onde um adversário ativo envia mensagens construídas ad hoc e observa as respostas.

O ML-KEM é IND-CCA2. Este é o nível exigido para um KEM seguro em protocolos reais como TLS ou SSH.

ROM vs. QROM

As provas de segurança usam modelos idealizados para as funções hash:

  • ROM (Random Oracle Model): os hashes são oráculos aleatórios perfeitos.
  • QROM (Quantum Random Oracle Model): o adversário quântico pode consultar o oráculo em sobreposição.

As provas modernas para a transformação FO (Fujisaki-Okamoto) usada em ML-KEM garantem segurança no QROM, essencial contra adversários quânticos.

9.2 Como se mede a dificuldade do MLWE

Segurança como custo do ataque

Não existe uma prova absoluta de que o MLWE é difícil. A segurança é estimada calculando o custo do melhor algoritmo de ataque conhecido. Uma segurança de \(\lambda\) bits significa que o ataque requer cerca de \(2^\lambda\) operações.

Os parâmetros

A dificuldade depende de:

  • \(n = 256\) (dimensão do polinómio, fixa)
  • \(k \in \{2, 3, 4\}\) (dimensão do módulo)
  • \(q = 3329\) (módulo primo)
  • \(\eta \in \{2, 3\}\) (amplitude do ruído)

Estimador de retículos

A ferramenta padrão é o Lattice Estimator de Albrecht et al. Para ML-KEM-768:

Ataque Custo estimado (bits)
Ataque primal (BKZ) ~178 bits
Ataque dual ~175 bits
Combinatório > 200 bits

A margem de segurança é ampla em comparação com o alvo de 128 bits clássicos/quânticos.

9.3 Principais ataques a retículos

BKZ (Block Korkine-Zolotarev)

É o melhor algoritmo geral para encontrar vetores curtos. Divide o retículo em blocos de dimensão \(\beta\) e resolve SVP localmente. Complexidade: \(2^{O(\beta \log \beta)}\). Para ML-KEM-768, \(\beta \approx 430\).

Ataque primal (uSVP)

Reduz o MLWE a um problema de vetor curto num retículo aumentado contendo a chave pública e o texto cifrado. O vetor secreto \((\mathbf{s}, \mathbf{e}, -1)\) torna-se um vetor curto que o BKZ tenta encontrar.

Ataque dual

Explora o retículo dual para distinguir amostras MLWE de uniformes através de estatísticas. Constrói muitos vetores curtos no dual para efetuar o distinguidor.

Escolha de q = 3329

Sendo primo e sem estrutura algébrica especial, previne ataques algébricos específicos. Não existem fatores pequenos ou relações simples que possam ser exploradas.

9.4 Níveis de segurança NIST

O NIST definiu 5 níveis. O ML-KEM cobre os níveis 1, 3 e 5:

Esquema Nível NIST Segurança Clássica Segurança Quântica
ML-KEM-512 1 (AES-128) ~118 bits ~100 bits
ML-KEM-768 3 (AES-192) ~178 bits ~164 bits
ML-KEM-1024 5 (AES-256) ~230 bits ~218 bits

Recomendação: O ML-KEM-768 oferece o equilíbrio ideal segurança/desempenho para a maioria dos usos. O ML-KEM-1024 é reservado para sistemas de altíssima criticidade.

9.6 Ataques de canal lateral e implementações seguras

Uma implementação correta pode ser vulnerável se vazar informações através do tempo de execução (ataques de temporização) ou consumo de energia.

Tempo Constante (Constant-Time - CT)

Todas as operações devem ter tempo constante independentemente dos dados secretos. Exemplo crítico em Decaps:

// NÃO seguro (tempo variável):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Seguro (tempo constante):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF se igual, 0x00 se diferente
K = ct_select(mask, K_good, K_reject);     // seleção CT sem ramificações

Áreas críticas para CT em ML-KEM

  • Amostragem \(B_\eta\): adições de bits sem ramificações condicionais.
  • NTT: as operações borboleta devem ser sempre executadas, mesmo que o resultado não mude.
  • Verificação do Texto Cifrado: uso de ct_memcmp.

Implementações de referência

  • pqclean: implementações portáveis CT.
  • liboqs: otimizações AVX2 com propriedades CT verificadas.
