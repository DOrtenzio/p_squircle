5.1 De LWE a MLWE: a motivação

LWE clássico e o seu custo

No ficheiro 04 vimos o LWE padrão: dadas \(m\) amostras \((\mathbf{a}_i, b_i)\) com \(\mathbf{a}_i \in \mathbb{Z}_q^n\) e \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), encontrar \(\mathbf{s}\). O problema é difícil, mas tem um custo prático elevado:

  • A chave pública (a matriz \(A \in \mathbb{Z}_q^{m \times n}\)) tem um tamanho \(O(n^2)\): para \(n = 1024\) e \(q = 3329\) seriam mais de 2 MB.
  • A multiplicação matriz-vetor \(A \cdot \mathbf{s}\) custa \(O(n^2)\) multiplicações.

RLWE: demasiado rígido

Ring-LWE transfere as operações para o anel \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Um único polinómio \(a \in R_q\) substitui toda a matriz, reduzindo a chave pública para \(O(n)\).

Mas o RLWE tem uma estrutura algébrica muito específica que alguns investigadores consideram potencialmente explorável (embora não se conheça nenhum ataque prático em 2024).

MLWE: o compromisso ótimo

Module-LWE generaliza ambos usando uma matriz \(k \times k\) de polinómios em \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Para \(k = 1\): reduz-se a RLWE
  • Para \(k \to \infty\) (polinómios de grau 0): reduz-se a LWE clássico

O parâmetro \(k\) permite calibrar a segurança e o desempenho de forma independente de \(n\).

Variante Chave pública Segurança Flexibilidade
LWE \(O(n^2)\) alta baixa
RLWE \(O(n)\) média baixa
MLWE \(O(k \cdot n)\) regulável com \(k\) alta

5.2 Definição formal de MLWE

Espaço de trabalho

Fixados os parâmetros:

  • \(n = 256\): grau do polinómio ciclotómico
  • \(q = 3329\): módulo primo
  • \(k \in \{2, 3, 4\}\): dimensão do módulo
  • \(\chi\): distribuição do ruído (distribuição binomial centrada \(B_\eta\))

O anel base é \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Distribuição MLWE

Seja \(\mathbf{s} \in R_q^k\) um vetor secreto de polinómios, cada um com coeficientes amostrados de \(\chi\).

Uma instância MLWE é um par:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{onde} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

com \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Problema decisionaL MLWE

Entrada: \((\mathbf{A}, \mathbf{t})\) onde:

  • seja \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (distribuição MLWE), ou
  • seja \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) uniforme

Objetivo: distinguir os dois casos com vantagem não negligenciável.

Problema de pesquisa MLWE

Entrada: \((\mathbf{A}, \mathbf{t})\) com \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Objetivo: encontrar \(\mathbf{s}\).

A redução de Regev (adaptada para MLWE) demonstra que o problema de pesquisa é computacionalmente equivalente ao problema decisionaL, e que ambos são pelo menos tão difíceis como GapSVP em retículos de alta dimensão.

5.3 A distribuição do ruído em ML-KEM

Distribuição binomial centrada \(B_\eta\)

Em ML-KEM o ruído não é gaussiano mas binomial centrado. Para amostrar um único coeficiente de \(B_\eta\):

  1. Amostrar \(2\eta\) bits uniformes: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Devolver \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

O resultado é um inteiro em \([-\eta, \eta]\).

Distribuição de probabilidade para η = 2:

Valor Probabilidade
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Por que não gaussiana verdadeira?

A gaussiana discreta é teoricamente ótima, mas amostrá-la de forma de tempo constante (resistente a ataques de temporização) é complexo. A binomial centrada:

  • tem suporte finito → sem casos extremos
  • é amostrada apenas com operações sobre bits → trivialmente de tempo constante
  • é estatisticamente indistinguível da gaussiana para os ataques conhecidos

5.4 Amostragem em ML-KEM

CBD: Distribuição Binomial Centrada

ML-KEM usa uma distribuição binomial centrada \(B_\eta\) para gerar erros pequenos e segredos. Esta distribuição é eficiente e não requer amostragem por rejeição.

Função SamplePolyCBD(σ, b, η)

Entrada: semente σ ∈ {0,1}^256, nonce b, parâmetro η
Saída: polinómio f ∈ R_q com coeficientes em [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, gera 64·η bytes
2. Para j = 0 a 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // conta os 1 no primeiro grupo
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // conta os 1 no segundo grupo
     f[j] = a - b                     // diferença centrada em 0
3. Devolver f

Para \(\eta=2\), os coeficientes estão em \(\{-2, -1, 0, 1, 2\}\). Para \(\eta=3\), em \(\{-3, \ldots, 3\}\).

SampleNTT: Amostragem Uniforme

Para gerar a matriz pública \(\mathbf{A}\), são necessários coeficientes uniformes em \(\mathbb{Z}_q\). Utiliza-se a amostragem por rejeição sobre a saída de SHAKE128.

Função SampleNTT(stream)

Entrada: fluxo de bytes do XOF (SHAKE128)
Saída: polinómio com coeficientes uniformes em [0, q-1]

coeficientes = []
enquanto len(coeficientes) < 256:
    // Ler 3 bytes para gerar 2 valores candidatos
    b0, b1, b2 = next_3_bytes(stream)

    // Combinar os bits para formar dois números de 12 bits
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2

    // Aceitar apenas se forem < q (3329)
    se d1 < q:
        coeficientes.append(d1)
    se d2 < q e len(coeficientes) < 256:
        coeficientes.append(d2)

devolver coeficientes

Este método garante uma distribuição uniforme perfeita, descartando os valores fora do intervalo.

5.5 Dificuldade: por que o MLWE é difícil

Redução do pior caso para o caso médio

A propriedade mais importante do LWE/MLWE é a redução do pior caso para o caso médio:

Se existe um algoritmo eficiente que resolve MLWE para uma fração não negligenciável de instâncias aleatórias, então existe um algoritmo eficiente para resolver GapSVP (a versão aproximada de SVP) em qualquer retículo, no pior caso.

Esta redução (Regev 2005, adaptada por Peikert 2009 e Brakerski et al. para MLWE) é excecional: a maioria dos problemas criptográficos tem apenas reduções de caso médio para caso médio.

Na prática: quebrar MLWE em instâncias aleatórias é tão difícil como resolver SVP no pior caso → os pressupostos criptográficos são muito sólidos.

Ausência de estrutura explorável por quânticos

O algoritmo de Shor explora a estrutura de grupo abeliano dos problemas de fatorização e logaritmo discreto: existe uma ação de grupo periódica que a QFT pode detetar.

MLWE não tem esta estrutura:

  • Não há periodicidade para explorar
  • Não há um grupo abeliano natural sobre o qual aplicar a QFT
  • Os melhores algoritmos quânticos (baseados em quantum walks ou QRAM) oferecem no máximo uma aceleração polinomial, não exponencial

5.6 De MLWE a um PKE: a ideia construtiva

Como se constrói um sistema de cifra a partir do MLWE? A intuição é elegante.

Analogia com Diffie-Hellman

Em DH, a chave pública é \(g^s\): fácil de calcular, difícil de inverter.
Em MLWE, a chave pública é \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): fácil de calcular, difícil de inverter.

Esquema de cifra (tipo Regev)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Chave pública: \((\mathbf{A}, \mathbf{t})\).
Chave privada: \(\mathbf{s}\).

Encrypt (mensagem \(m \in \{0,1\}\), codificada como \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Texto cifrado: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Análise:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{ruído pequeno}} + \mu \approx \mu \]

O ruído é pequeno → arredondando recupera-se \(\mu\) e portanto \(m\).

A versão polinomial (MLWE real)

Em ML-KEM, cada escalar torna-se um polinómio em \(R_q\), e as operações são produtos polinomiais. O mecanismo é idêntico, mas as multiplicações são realizadas no anel:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

onde \(\circ\) é a multiplicação em \(R_q\) (polinomial, acelerada por NTT).

5.7 Exemplo numérico completo

Usamos parâmetros de brinquedo: \(n = 4\), \(q = 17\), \(k = 2\), coeficientes pequenos em \(\{-1, 0, 1\}\).

Os polinómios estão em \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), portanto de grau \(\leq 3\).

Dados de partida

Matriz pública \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

com \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Segredo \(\mathbf{s} = (s_0, s_1)^T\) com \(s_0 = 1 - X\), \(s_1 = X^2\).

Erro \(\mathbf{e} = (e_0, e_1)^T\) com \(e_0 = 1\), \(e_1 = -X\).

Cálculo de t = As + e

Componente t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Reduzimos \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Resultado: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (a segunda componente é calculada de forma análoga).

Observação chave

Um adversário que vê \((\mathbf{A}, \mathbf{t})\) deve encontrar \((\mathbf{s}, \mathbf{e})\). Mesmo com estes números pequenos, o problema já não é trivial: não pode usar eliminação gaussiana (o erro quebra a linearidade) e o espaço de pesquisa é exponencial na dimensão real do ML-KEM.

5.8 Por que os parâmetros do ML-KEM são os que são

\(n = 256\)

  • Deve ser uma potência de 2 (para NTT eficiente)
  • O polinómio \(X^{256}+1\) deve ser irredutível sobre \(\mathbb{Z}_q\): é se \(q \equiv 1 \pmod{512}\)
  • \(256\) equilibra segurança e desempenho: \(n = 128\) seria demasiado inseguro, \(n = 512\) demasiado lento

\(q = 3329\)

  • Deve ser primo (para que \(\mathbb{Z}_q\) seja um corpo)
  • Deve satisfazer \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Deve ser tal que existam raízes 256-ésimas da unidade: garantido pela condição anterior
  • Deve ser o mais pequeno possível (chaves compactas) compatível com o orçamento de ruído
  • \(3329\) é o primo que satisfaz todas as condições com margem suficiente para o ruído

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): nível 1 NIST, equivalente a AES-128 pré-quântico
  • \(k = 3\) (ML-KEM-768): nível 3, equivalente a AES-192, recomendado para uso geral
  • \(k = 4\) (ML-KEM-1024): nível 5, equivalente a AES-256, para sistemas de alta criticidade

\(\eta_1, \eta_2 \in \{2, 3\}\)

O ruído deve ser:

  • suficientemente grande para tornar o problema MLWE difícil
  • suficientemente pequeno para garantir que a decifra não falhe (orçamento de ruído)

Aumentar \(\eta\) aumenta a segurança mas também a probabilidade de erro de decifra. Os valores \(\eta_1 = 2, \eta_2 = 2\) para ML-KEM-768 são o ponto ótimo.
