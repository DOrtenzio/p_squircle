2.1 O problema da troca de chaves

Alice quer comunicar de forma segura com Bob num canal público. Para usar AES, é necessária uma chave partilhada. Como a estabelecem sem que Eva (que ouve tudo) a descubra?

Este problema esteve sem solução durante séculos. A solução chegou em 1976 com Diffie e Hellman, e em 1977 com Rivest, Shamir e Adleman (RSA).

A ideia chave: existem operações matemáticas fáceis num sentido, difíceis no outro.

Operação fácil Operação difícil
Multiplicar dois primos grandes: \(p \cdot q = n\) Fatorizar \(n\) para encontrar \(p\) e \(q\)
Calcular \(g^x \bmod p\) Encontrar \(x\) dado \(g^x \bmod p\) (logaritmo discreto)
Somar um ponto numa curva elíptica \(k\) vezes: \(kP\) Encontrar \(k\) dado \(kP\) (ECDLP)

2.2 RSA

Geração de chaves

  1. Escolher dois primos grandes \(p\) e \(q\) (tipicamente 2048+ bits cada)
  2. Calcular \(n = p \cdot q\)
  3. Calcular \(\phi(n) = (p-1)(q-1)\)
  4. Escolher \(e\) tal que \(\gcd(e, \phi(n)) = 1\) (tipicamente \(e = 65537\))
  5. Calcular \(d = e^{-1} \bmod \phi(n)\)

Chave pública: \((n, e)\)
Chave privada: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) devem ser destruídos.

Cifração e decifração

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Porque funciona: pelo teorema de Euler, \(M^{\phi(n)} \equiv 1 \pmod{n}\), portanto \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Exemplo numérico (com números pequenos, apenas didático)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(porque } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Cifrar \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Decifrar:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA como KEM

RSA-KEM (simplificado):

  1. Bob gera \(r \leftarrow \{1, \ldots, n-1\}\) aleatoriamente
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (chave simétrica)
  4. Envia \(C\) para Alice
  5. Alice calcula \(r = C^d \bmod n\), depois \(K = H(r)\)

2.3 Diffie-Hellman (DH)

O protocolo

Parâmetros públicos: um primo grande \(p\) e um gerador \(g\) de \(\mathbb{Z}_p^*\).

Alice
  1. Escolhe \(a\) secreto
  2. Calcula \(A = g^a \bmod p\)
A → ← B
Bob
  1. Escolhe \(b\) secreto
  2. Calcula \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Alice calcula: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Bob calcula: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Resultado: Ambos partilham a mesma chave secreta \(K\). Eva, que vê apenas \(A\) e \(B\), não pode calcular \(K\) sem resolver o problema do logaritmo discreto.

2.4 Criptografia de curvas elípticas (ECDH)

ECDH é o análogo do DH em curvas elípticas. É usado em TLS 1.3 com a curva X25519.

Alice
  1. Escolhe \(a\) secreto
  2. Calcula \(A = a \cdot G\)
A → ← B
Bob
  1. Escolhe \(b\) secreto
  2. Calcula \(B = b \cdot G\)
\[ \begin{aligned} \text{Alice calcula: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Bob calcula: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Onde \(G\) é o ponto gerador da curva. A segurança baseia-se na dificuldade do ECDLP (Elliptic Curve Discrete Logarithm Problem).

2.4 Criptografia de curvas elípticas (ECC)

O que são curvas elípticas

Uma curva elíptica sobre \(\mathbb{Z}_p\) é o conjunto dos pontos \((x, y)\) que satisfazem:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

mais um ponto especial \(\mathcal{O}\) chamado ponto no infinito.

Nestes pontos, define-se uma operação de soma com propriedades de grupo.

Multiplicação escalar

Dada a soma de pontos, define-se a multiplicação escalar:

\(kP = P + P + \cdots + P \quad (k \text{ vezes})\)

Calcular \(kP\) a partir de \(P\) e \(k\) é fácil (\(O(\log k)\) operações). O problema inverso – encontrar \(k\) a partir de \(P\) e \(kP\) – é o Problema do Logaritmo Discreto em Curvas Elípticas (ECDLP), computacionalmente difícil.

Vantagens da ECC em relação a DH/RSA

Segurança equivalente RSA/DH (bits de n/p) ECC (bits da chave)
80 bits 1024 160
128 bits 3072 256
256 bits 15360 512

ECC oferece chaves muito mais pequenas com a mesma segurança → mais eficiente.

ECDH (Elliptic Curve Diffie-Hellman)

Alice Bob | | | escolhe a secreto | escolhe b secreto | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ chave partilhada K |

ECDH é usado em TLS 1.3 com a curva X25519 (curve25519 de Bernstein).

2.5 Segurança clássica e limites quânticos

Contra computadores clássicos

Os problemas em que se baseiam o RSA e a ECC são subexponenciais (não puramente exponenciais) para computadores clássicos.

O melhor algoritmo clássico para fatorização é o General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

Para \(n\) de 2048 bits, isto requer um tempo astronomicamente longo → seguro na prática.

Contra computadores quânticos: o algoritmo de Shor

Em 1994, Peter Shor demonstrou que um computador quântico pode:

  • Fatorizar \(n\) em tempo \(O((\log n)^3)\)
  • Resolver o DLP em tempo \(O((\log p)^3)\)
  • Resolver o ECDLP em tempo \(O((\log p)^3)\)

Um computador quântico com qubits suficientes quebraria o RSA-2048 em horas ou dias.

A análise detalhada do algoritmo de Shor está no ficheiro 03 – Algoritmo de Shor.

A resposta: criptografia pós-quântica

Para continuar a ter criptografia assimétrica segura na era quântica, são necessários problemas matemáticos que não tenham algoritmos quânticos eficientes conhecidos.

Os problemas de retículos (lattice), em que se baseia o ML-KEM, satisfazem este requisito: os melhores algoritmos quânticos conhecidos oferecem no máximo uma aceleração modesta em relação aos algoritmos clássicos.
