01 – Criptografia Simétrica

O ponto de chegada prático de todo o percurso PQC

Índice

1.1 O que é a criptografia simétrica

Num sistema de criptografia simétrica, o emissor e o recetor usam a mesma chave \(K\) para cifrar e decifrar.

\(\text{Emissor: } C = \text{Enc}(K, M)\)

\(\text{Recetor: } M = \text{Dec}(K, C)\)

Vantagem principal: eficiência. AES-256 em hardware moderno atinge dezenas de GB/s.

Desvantagem: é necessário um canal seguro para trocar \(K\) antes de comunicar. Este é exatamente o problema que os KEM resolvem.

Segurança da criptografia simétrica vs. quântica

Os computadores quânticos não quebram o AES. O algoritmo de Grover oferece uma aceleração quadrática na busca pela chave, mas:

  • AES-128: segurança efetiva de 128 bits cai para ~64 bits → insuficiente
  • AES-256: segurança efetiva de 256 bits cai para ~128 bits → ainda seguro

Por esta razão, o FIPS 203 (ML-KEM) produz chaves de 256 bits, destinadas a serem usadas com AES-256.

1.2 AES: Advanced Encryption Standard

AES é uma cifra de bloco: pega um bloco de 128 bits e uma chave (\(K\)), e produz 128 bits cifrados.

Estrutura interna

AES organiza os 128 bits de entrada como uma matriz \(4 \times 4\) de bytes. Em seguida, aplica \(r\) rondas (10, 12 ou 14 consoante o tamanho da chave), cada uma composta por quatro transformações:

Transformação Objetivo
SubBytes Substituição não linear via S-Box (resistência à criptoanálise diferencial)
ShiftRows Rotação cíclica das linhas (difusão)
MixColumns Combinação linear das colunas (difusão)
AddRoundKey XOR com a subchave da ronda atual

Key schedule

A chave original (\(K\) de 128, 192 ou 256 bits) é expandida em \(r+1\) subchaves, uma para cada ronda.

AES-128: chave 128 bits, 10 rondas

AES-192: chave 192 bits, 12 rondas

AES-256: chave 256 bits, 14 rondas

Segurança

O melhor ataque conhecido ao AES-128 requer \(2^{126.1}\) operações (Biryukov & Khovratovich, 2009) – essencialmente força bruta.

1.3 Modos operativos

AES cifra um bloco de 128 bits. Mas as mensagens reais são mais longas. Os modos operativos definem como aplicar o AES repetidamente.

ECB (Electronic Codebook) – não usar

Cada bloco é cifrado independentemente. Blocos idênticos produzem cifras idênticas → perde a estrutura do texto claro.

CBC (Cipher Block Chaining)

Cada bloco de texto claro é XORado com a cifra do bloco anterior antes de ser cifrado. Requer um IV (Initialization Vector) aleatório.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Mais seguro que ECB, mas não paralelizável na cifragem.

CTR (Counter Mode) – recomendado

Gera um keystream cifrando um contador incremental. O texto claro é XORado com o keystream.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Paralelizável tanto na cifragem como na decifragem. Transforma o AES numa cifra de fluxo.

GCM (Galois/Counter Mode) – usado em TLS 1.3

Combina o CTR com um MAC baseado em corpos de Galois. Oferece confidencialidade e autenticidade.

1.4 Autenticação e AEAD

A confidencialidade não basta: um atacante pode modificar a cifra sem que o recetor se aperceba. É necessária autenticidade.

MAC (Message Authentication Code)

Um MAC é uma função \(\text{MAC}(K, M) \to \tau\) onde \(\tau\) é a tag de autenticidade. Apenas quem conhece \(K\) pode gerar e verificar \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Combina cifragem e autenticação numa única primitiva:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) ou \(\perp\) (se a tag for inválida)

AAD (Additional Authenticated Data) são dados autenticados mas não cifrados (ex. cabeçalhos de pacotes).

AES-256-GCM é o esquema AEAD padrão usado em TLS 1.3 e como cifra simétrica após um KEM.

1.5 Papel no contexto PQC

Um ML-KEM completo em uso real funciona assim:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Mensagem) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Mensagem = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Comunicação segura |

A chave \(K\) produzida pelo ML-KEM (32 bytes) não é usada diretamente como chave AES, mas derivada com uma KDF (Key Derivation Function) como o HKDF para separar diferentes contextos.

Tamanhos práticos (ML-KEM-768 + AES-256-GCM)

Componente Tamanho
Chave pública ML-KEM 1184 bytes
Texto cifrado ML-KEM 1088 bytes
Segredo partilhado → chave AES 32 bytes
Overhead AEAD (tag GCM) 16 bytes
