01 – 对称加密

整个 PQC 学习路径的实际终点

1.1 什么是对称加密

在 对称 加密系统中，发送方和接收方使用 相同的密钥 \(K\) 进行加密和解密。

\(\text{发送方： } C = \text{Enc}(K, M)\)

\(\text{接收方： } M = \text{Dec}(K, C)\)

主要优势：高效。AES-256 在现代硬件上可达到数十 GB/s 的速度。

缺点：在通信 之前 需要一个安全通道来交换 \(K\)。这正是 KEM 要解决的问题。

对称加密 vs. 量子计算的安全性

量子计算机不会破解 AES。Grover 算法在密钥搜索中提供 二次 加速，但：

  • AES-128：有效安全性从 128 位降至 ~64 位 → 不足
  • AES-256：有效安全性从 256 位降至 ~128 位 → 仍然安全

因此，FIPS 203（ML-KEM）生成 256 位密钥，设计用于 AES-256。

1.2 AES：高级加密标准

AES 是一种 分组密码：它接收 128 位的块和密钥（\(K\)），输出 128 位的密文。

内部结构

AES 将 128 位输入组织为 \(4 \times 4\) 的字节矩阵。然后应用 \(r\) 轮（10、12 或 14，取决于密钥大小），每轮由四个变换组成：

变换 目的
SubBytes 通过 S-Box 进行非线性替换（抵抗差分密码分析）
ShiftRows 循环行移位（扩散）
MixColumns 列的线性组合（扩散）
AddRoundKey 与当前轮子密钥进行 XOR

密钥调度

原始密钥（\(K\) 为 128、192 或 256 位）扩展为 \(r+1\) 个子密钥，每轮一个。

AES-128：128 位密钥，10 轮

AES-192：192 位密钥，12 轮

AES-256：256 位密钥，14 轮

安全性

已知对 AES-128 的最佳攻击需要 \(2^{126.1}\) 次操作（Biryukov & Khovratovich, 2009）——基本上是暴力破解。

1.3 工作模式

AES 加密一个 128 位的块。但实际消息更长。工作模式 定义了如何重复应用 AES。

ECB（电子密码本）——不要使用

每个块独立加密。相同的块产生相同的密文 → 丢失明文结构。

CBC（密码块链接）

每个明文块在加密前与前一个块的密文进行 XOR。需要随机的 IV（初始化向量）。

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

比 ECB 更安全，但加密时不可并行。

CTR（计数器模式）——推荐

通过加密递增计数器生成密钥流。明文与密钥流进行 XOR。

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

加密和解密均可并行。将 AES 转换为流密码。

GCM（伽罗瓦/计数器模式）——在 TLS 1.3 中使用

将 CTR 与基于伽罗瓦域的 MAC 结合。提供机密性 和 真实性。

1.4 认证与 AEAD

仅有机密性是不够的：攻击者可能修改密文而接收者无法察觉。需要 真实性。

MAC（消息认证码）

MAC 是一个函数 \(\text{MAC}(K, M) \to \tau\)，其中 \(\tau\) 是 认证标签。只有知道 \(K\) 的人才能生成和验证 \(\tau\)。

AEAD（带关联数据的认证加密）

将加密和认证结合在一个基元中：

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) 或 \(\perp\)（如果标签无效）

AAD（附加认证数据）是被认证但未加密的数据（例如，数据包头部）。

AES-256-GCM 是 TLS 1.3 中使用的标准 AEAD 方案，也是 KEM 后的对称密码。

1.5 在 PQC 上下文中的角色

一个完整的 ML-KEM 在实际使用中如下工作：

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, 消息) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | 消息 = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ 安全通信 |

ML-KEM 生成的密钥 \(K\)（32 字节）不直接用作 AES 密钥，而是通过 KDF（密钥派生函数）（如 HKDF）派生，以分离不同的上下文。

实际大小（ML-KEM-768 + AES-256-GCM）

组件 大小
ML-KEM 公钥 1184 字节
ML-KEM 密文 1088 字节
共享密钥 → AES 密钥 32 字节
AEAD 开销（GCM 标签） 16 字节
