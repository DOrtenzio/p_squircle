1.1 Czym jest kryptografia symetryczna?

W systemie kryptografii symetrycznej nadawca i odbiorca używają tego samego klucza \(K\) do szyfrowania i deszyfrowania.

\(\text{Nadawca: } C = \text{Enc}(K, M)\)

\(\text{Odbiorca: } M = \text{Dec}(K, C)\)

Główna zaleta: wydajność. AES-256 na nowoczesnym sprzęcie osiąga dziesiątki GB/s.

Wada: potrzebny jest bezpieczny kanał do wymiany \(K\) przed rozpoczęciem komunikacji. To jest dokładnie problem, który rozwiązują KEM.

Bezpieczeństwo kryptografii symetrycznej vs. kwantowa

Komputery kwantowe nie łamią AES. Algorytm Grovera oferuje kwadratyczne przyspieszenie w wyszukiwaniu klucza, ale:

  • AES-128: efektywne bezpieczeństwo 128 bitów spada do ~64 bitów → niewystarczające
  • AES-256: efektywne bezpieczeństwo 256 bitów spada do ~128 bitów → nadal bezpieczne

Dlatego FIPS 203 (ML-KEM) produkuje klucze o długości 256 bitów, przeznaczone do użycia z AES-256.

1.2 AES: Advanced Encryption Standard

AES jest szyfrem blokowym: pobiera blok 128 bitów i klucz (\(K\)), a następnie produkuje 128 bitów zaszyfrowanego tekstu.

Struktura wewnętrzna

AES organizuje 128 bitów wejściowych jako macierz \(4 \times 4\) bajtów. Następnie stosuje \(r\) rund (10, 12 lub 14 w zależności od rozmiaru klucza), każda składająca się z czterech transformacji:

Transformacja Cel
SubBytes Nieliniowa substytucja za pomocą S-Box (odporność na kryptoanalizę różnicową)
ShiftRows Cykliczne przesunięcie wierszy (dyfuzja)
MixColumns Kombinacja liniowa kolumn (dyfuzja)
AddRoundKey XOR z podkluczem bieżącej rundy

Key schedule

Oryginalny klucz (\(K\) o długości 128, 192 lub 256 bitów) jest rozszerzany na \(r+1\) podkluczy, po jednym dla każdej rundy.

AES-128: klucz 128 bitów, 10 rund

AES-192: klucz 192 bity, 12 rund

AES-256: klucz 256 bitów, 14 rund

Bezpieczeństwo

Najlepszy znany atak na AES-128 wymaga \(2^{126.1}\) operacji (Biryukov & Khovratovich, 2009) – zasadniczo brute force.

1.3 Tryby działania

AES szyfruje blok 128 bitów. Ale rzeczywiste wiadomości są dłuższe. Tryby działania określają, jak AES jest stosowany wielokrotnie.

ECB (Electronic Codebook) – nie używać

Każdy blok jest szyfrowany niezależnie. Identyczne bloki dają identyczny tekst zaszyfrowany → traci się strukturę tekstu jawnego.

CBC (Cipher Block Chaining)

Każdy blok tekstu jawnego jest XOR-owany z zaszyfrowanym tekstem poprzedniego bloku przed zaszyfrowaniem. Wymaga losowego IV (Initialization Vector).

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Bezpieczniejszy niż ECB, ale nie można go równoleglić przy szyfrowaniu.

CTR (Counter Mode) – zalecany

Generuje strumień klucza poprzez szyfrowanie licznika. Tekst jawny jest XOR-owany ze strumieniem klucza.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Można go równoleglić zarówno przy szyfrowaniu, jak i deszyfrowaniu. Przekształca AES w szyfr strumieniowy.

GCM (Galois/Counter Mode) – używany w TLS 1.3

Łączy CTR z MAC opartym na ciałach Galois. Zapewnia zarówno poufność jak i autentyczność.

1.4 Uwierzytelnianie i AEAD

Poufność nie wystarczy: atakujący mógłby zmodyfikować zaszyfrowany tekst bez wiedzy odbiorcy. Potrzebna jest autentyczność.

MAC (Message Authentication Code)

MAC to funkcja \(\text{MAC}(K, M) \to \tau\), gdzie \(\tau\) to tag autentyczności. Tylko osoba znająca \(K\) może wygenerować i zweryfikować \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Łączy szyfrowanie i uwierzytelnianie w jednym prymitywie:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) lub \(\perp\) (jeśli tag jest nieprawidłowy)

AAD (Additional Authenticated Data) to dane uwierzytelniane, ale nie szyfrowane (np. nagłówki pakietów).

AES-256-GCM to standardowy schemat AEAD używany w TLS 1.3 i jako szyfr symetryczny po KEM.

1.5 Rola w kontekście PQC

Kompletny ML-KEM w rzeczywistym użyciu działa w następujący sposób:

Alicja Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Wiadomość) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Wiadomość = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Bezpieczna komunikacja |

Klucz \(K\) wyprodukowany przez ML-KEM (32 bajty) nie jest używany bezpośrednio jako klucz AES, ale jest wyprowadzany za pomocą KDF (Key Derivation Function) takiej jak HKDF, aby oddzielić różne konteksty.

Wymiary praktyczne (ML-KEM-768 + AES-256-GCM)

Komponent Rozmiar
Klucz publiczny ML-KEM 1184 bajty
Tekst zaszyfrowany ML-KEM 1088 bajtów
Wspólny sekret → klucz AES 32 bajty
Narzut AEAD (tag GCM) 16 bajtów
