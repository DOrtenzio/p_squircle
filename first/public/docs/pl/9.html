9.1 Modele bezpieczeństwa

IND-CPA (Nierozróżnialność przy wybranym ataku jawnym)

W tym modelu przeciwnik:

  1. Otrzymuje klucz publiczny \(ek\)
  2. Wybiega dwie wiadomości \(m_0, m_1\)
  3. Otrzymuje szyfrogram jednej z nich (wybranej losowo)
  4. Musi zgadnąć, która wiadomość została zaszyfrowana

Schemat jest bezpieczny, jeśli: \(\Pr[\text{zgadnie}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (podstawowy komponent szyfrowania) jest IND-CPA przy założeniu MLWE.

IND-CCA2 (Nierozróżnialność przy adaptacyjnym wybranym ataku szyfrogramem)

Jak CPA, ale przeciwnik może również zadawać pytania wyroczni deszyfrującej na dowolnych szyfrogramach (z wyjątkiem szyfrogramu wyzwania). Ten model oddaje rzeczywiste ataki (jak Bleichenbacher), gdzie aktywny przeciwnik wysyła specjalnie skonstruowane wiadomości i obserwuje odpowiedzi.

ML-KEM jest IND-CCA2. To poziom wymagany dla bezpiecznego KEM w rzeczywistych protokołach, takich jak TLS czy SSH.

ROM vs. QROM

Dowody bezpieczeństwa używają wyidealizowanych modeli dla funkcji hash:

  • ROM (Random Oracle Model): hasze są idealnymi losowymi wyroczniami.
  • QROM (Quantum Random Oracle Model): przeciwnik kwantowy może zadawać pytania wyroczni w superpozycji.

Nowoczesne dowody dla transformacji FO (Fujisaki-Okamoto) używanej w ML-KEM gwarantują bezpieczeństwo w QROM, co jest niezbędne przeciwko przeciwnikom kwantowym.

9.2 Jak mierzy się trudność MLWE

Bezpieczeństwo jako koszt ataku

Nie ma absolutnego dowodu, że MLWE jest trudny. Bezpieczeństwo szacuje się, obliczając koszt najlepszego znanego algorytmu ataku. Bezpieczeństwo \(\lambda\) bitów oznacza, że atak wymaga około \(2^\lambda\) operacji.

Parametry

Trudność zależy od:

  • \(n = 256\) (wymiar wielomianu, stały)
  • \(k \in \{2, 3, 4\}\) (wymiar modułu)
  • \(q = 3329\) (moduł pierwszy)
  • \(\eta \in \{2, 3\}\) (amplituda szumu)

Estymator krat

Standardowym narzędziem jest Lattice Estimator Albrechta i in. Dla ML-KEM-768:

Atak Szacowany koszt (bity)
Atak pierwotny (BKZ) ~178 bitów
Atak dualny ~175 bitów
Kombinatoryczny > 200 bitów

Margines bezpieczeństwa jest duży w porównaniu z celem 128 bitów klasycznych/kwantowych.

9.3 Główne ataki na kraty

BKZ (Block Korkine-Zolotarev)

To najlepszy ogólny algorytm znajdowania krótkich wektorów. Dzieli kratę na bloki o rozmiarze \(\beta\) i rozwiązuje SVP lokalnie. Złożoność: \(2^{O(\beta \log \beta)}\). Dla ML-KEM-768, \(\beta \approx 430\).

Atak pierwotny (uSVP)

Sprowadza MLWE do problemu krótkiego wektora w rozszerzonej kracie zawierającej klucz publiczny i szyfrogram. Wektor sekretny \((\mathbf{s}, \mathbf{e}, -1)\) staje się krótkim wektorem, którego BKZ próbuje znaleźć.

Atak dualny

Wykorzystuje kratę dualną do odróżnienia próbek MLWE od jednorodnych za pomocą statystyk. Konstruuje wiele krótkich wektorów w dualnej, aby przeprowadzić rozróżniacz.

Wybór q = 3329

Będąc liczbą pierwszą i pozbawioną specjalnej struktury algebraicznej, zapobiega specyficznym atakom algebraicznym. Nie ma małych czynników ani prostych zależności, które można by wykorzystać.

9.4 Poziomy bezpieczeństwa NIST

NIST zdefiniował 5 poziomów. ML-KEM obejmuje poziomy 1, 3 i 5:

Schemat Poziom NIST Bezpieczeństwo klasyczne Bezpieczeństwo kwantowe
ML-KEM-512 1 (AES-128) ~118 bitów ~100 bitów
ML-KEM-768 3 (AES-192) ~178 bitów ~164 bitów
ML-KEM-1024 5 (AES-256) ~230 bitów ~218 bitów

Zalecenie: ML-KEM-768 oferuje optymalną równowagę bezpieczeństwa/wydajności dla większości zastosowań. ML-KEM-1024 jest zarezerwowany dla systemów o bardzo wysokiej krytyczności.

BIKE Kody korekcyjne ~1541 B ~1573 B
HQC Kody korekcyjne ~2249 B ~4522 B
Classic McEliece Kody Goppa ~261 KB 128 B

Porównanie z kryptografią klasyczną

Schemat Klucz publiczny Bezpieczeństwo kwantowe
RSA-3072 384 B ❌ Podatny
ECDH X25519 32 B ❌ Podatny
ML-KEM-768 1184 B ✅ 164+ bitów

Głównym kosztem jest większy rozmiar (~37× w porównaniu z ECDH), ale pozostaje on akceptowalny dla nowoczesnych uzgodnień TLS.

9.6 Ataki bocznokanałowe i bezpieczne implementacje

Poprawna implementacja może być podatna, jeśli wycieka informacje poprzez czas wykonania (ataki czasowe) lub zużycie energii.

Stałoczasowość (Constant-Time - CT)

Wszystkie operacje muszą mieć stały czas niezależnie od tajnych danych. Krytyczny przykład w Decaps:

// NIEbezpieczne (zmienny czas):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Bezpieczne (stałoczasowe):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF jeśli równe, 0x00 jeśli różne
K = ct_select(mask, K_good, K_reject);     // wybór CT bez rozgałęzień

Krytyczne obszary dla CT w ML-KEM

  • Próbkowanie \(B_\eta\): dodawanie bitów bez warunkowych rozgałęzień.
  • NTT: operacje motylkowe muszą być zawsze wykonywane, nawet jeśli wynik się nie zmienia.
  • Weryfikacja szyfrogramu: użycie ct_memcmp.

Implementacje referencyjne

  • pqclean: przenośne implementacje CT.
  • liboqs: optymalizacje AVX2 ze zweryfikowanymi właściwościami CT.
