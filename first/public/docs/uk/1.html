1.1 Що таке симетрична криптографія

У системі симетричної криптографії відправник і отримувач використовують один і той самий ключ \(K\) для шифрування та дешифрування.

\(\text{Відправник: } C = \text{Enc}(K, M)\)

\(\text{Отримувач: } M = \text{Dec}(K, C)\)

Основна перевага: ефективність. AES-256 на сучасному обладнанні досягає десятків ГБ/с.

Недолік: потрібен захищений канал для обміну \(K\) до початку спілкування. Це саме та проблема, яку вирішують KEM.

Безпека симетричної криптографії проти квантової

Квантові комп'ютери не зламують AES. Алгоритм Гровера дає квадратичне прискорення при пошуку ключа, але:

  • AES-128: ефективна безпека зі 128 біт падає до ~64 біт → недостатньо
  • AES-256: ефективна безпека з 256 біт падає до ~128 біт → все ще безпечно

Тому FIPS 203 (ML-KEM) генерує 256-бітні ключі, призначені для використання з AES-256.

1.2 AES: Advanced Encryption Standard

AES — це блоковий шифр: він бере блок зі 128 біт і ключ (\(K\)) і видає 128 зашифрованих біт.

Внутрішня структура

AES організовує 128 вхідних біт у матрицю \(4 \times 4\) байтів. Потім застосовує \(r\) раундів (10, 12 або 14 залежно від розміру ключа), кожен з яких складається з чотирьох перетворень:

Перетворення Мета
SubBytes Нелінійна заміна через S-Box (стійкість до диференціального криптоаналізу)
ShiftRows Циклічний зсув рядків (розсіювання)
MixColumns Лінійна комбінація стовпців (розсіювання)
AddRoundKey XOR з підключем поточного раунду

Розклад ключів

Оригінальний ключ (\(K\) розміром 128, 192 або 256 біт) розширюється в \(r+1\) підключів, по одному на кожен раунд.

AES-128: ключ 128 біт, 10 раундів

AES-192: ключ 192 біт, 12 раундів

AES-256: ключ 256 біт, 14 раундів

Безпека

Найкраща відома атака на AES-128 потребує \(2^{126.1}\) операцій (Biryukov & Khovratovich, 2009) – по суті повний перебір.

1.3 Режими роботи

AES шифрує блок зі 128 біт. Але реальні повідомлення довші. Режими роботи визначають, як застосовувати AES багаторазово.

ECB (Electronic Codebook) – не використовуйте

Кожен блок шифрується незалежно. Однакові блоки дають однаковий шифртекст → втрачається структура відкритого тексту.

CBC (Cipher Block Chaining)

Кожен блок відкритого тексту XORиться з шифртекстом попереднього блоку перед шифруванням. Потрібен випадковий IV (Initialization Vector).

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Безпечніше за ECB, але не паралелізується при шифруванні.

CTR (Counter Mode) – рекомендується

Генерує ключовий потік шляхом шифрування інкрементованого лічильника. Відкритий текст XORиться з ключовим потоком.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Паралелізується як при шифруванні, так і при дешифруванні. Перетворює AES на потоковий шифр.

GCM (Galois/Counter Mode) – використовується в TLS 1.3

Поєднує CTR з MAC на основі полів Галуа. Забезпечує конфіденційність та автентичність.

1.4 Автентифікація та AEAD

Конфіденційності недостатньо: зловмисник може змінити шифртекст так, що отримувач цього не помітить. Потрібна автентичність.

MAC (Message Authentication Code)

MAC — це функція \(\text{MAC}(K, M) \to \tau\), де \(\tau\) — тег автентичності. Лише той, хто знає \(K\), може генерувати та перевіряти \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Об'єднує шифрування та автентифікацію в одному примітиві:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) або \(\perp\) (якщо тег недійсний)

AAD (Additional Authenticated Data) — це дані, які автентифікуються, але не шифруються (наприклад, заголовки пакетів).

AES-256-GCM — це стандартна схема AEAD, що використовується в TLS 1.3 і як симетричний шифр після KEM.

1.5 Роль у контексті PQC

Повний ML-KEM у реальному використанні працює так:

Аліса Боб | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Повідомлення) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Повідомлення = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Захищений зв'язок |

Ключ \(K\), отриманий від ML-KEM (32 байти), не використовується безпосередньо як ключ AES, а виводиться за допомогою KDF (Key Derivation Function), такої як HKDF, для розділення різних контекстів.

Практичні розміри (ML-KEM-768 + AES-256-GCM)

Компонент Розмір
Публічний ключ ML-KEM 1184 байти
Шифртекст ML-KEM 1088 байтів
Спільний секрет → ключ AES 32 байти
Накладні витрати AEAD (тег GCM) 16 байтів
