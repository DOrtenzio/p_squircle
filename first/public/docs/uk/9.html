9.1 Моделі безпеки

IND-CPA (Нерозрізненність при атаці на основі вибраного відкритого тексту)

У цій моделі противник:

  1. Отримує публічний ключ \(ek\)
  2. Обирає два повідомлення \(m_0, m_1\)
  3. Отримує шифртекст одного з них (обраного випадково)
  4. Має вгадати, яке повідомлення було зашифроване

Схема безпечна, якщо: \(\Pr[\text{вгадає}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (базовий компонент шифрування) є IND-CPA при припущенні MLWE.

IND-CCA2 (Нерозрізненність при адаптивній атаці на основі вибраного шифртекста)

Як CPA, але противник також може запитувати оракул розшифровки на будь-яких шифртекстах (крім шифртексту-виклику). Ця модель відображає реальні атаки (як Блейхенбахер), де активний противник надсилає спеціально сконструйовані повідомлення та спостерігає відповіді.

ML-KEM є IND-CCA2. Це рівень, необхідний для безпечного KEM у реальних протоколах, таких як TLS або SSH.

ROM vs. QROM

Доведення безпеки використовують ідеалізовані моделі для хеш-функцій:

  • ROM (Random Oracle Model): хеші є ідеальними випадковими оракулами.
  • QROM (Quantum Random Oracle Model): квантовий противник може запитувати оракул у суперпозиції.

Сучасні доведення для перетворення FO (Фуджісакі-Окамото), що використовується в ML-KEM, гарантують безпеку в QROM, що необхідно проти квантових противників.

9.2 Як вимірюється складність MLWE

Безпека як вартість атаки

Не існує абсолютного доведення того, що MLWE складний. Безпека оцінюється шляхом обчислення вартості найкращого відомого алгоритму атаки. Безпека в \(\lambda\) біт означає, що атака потребує близько \(2^\lambda\) операцій.

Параметри

Складність залежить від:

  • \(n = 256\) (розмірність полінома, фіксована)
  • \(k \in \{2, 3, 4\}\) (розмірність модуля)
  • \(q = 3329\) (простий модуль)
  • \(\eta \in \{2, 3\}\) (амплітуда шуму)

Оцінювач ґраток

Стандартним інструментом є Lattice Estimator Альбрехта та ін. Для ML-KEM-768:

Атака Оціночна вартість (біт)
Пряма атака (BKZ) ~178 біт
Двоїста атака ~175 біт
Комбінаторна > 200 біт

Запас безпеки великий порівняно з метою 128 біт класичної/квантової безпеки.

9.3 Основні атаки на ґратки

BKZ (Block Korkine-Zolotarev)

Це найкращий загальний алгоритм для знаходження коротких векторів. Він розбиває ґратку на блоки розміру \(\beta\) і розв'язує SVP локально. Складність: \(2^{O(\beta \log \beta)}\). Для ML-KEM-768 \(\beta \approx 430\).

Пряма атака (uSVP)

Зводить MLWE до задачі короткого вектора в розширеній ґратці, що містить публічний ключ і шифртекст. Секретний вектор \((\mathbf{s}, \mathbf{e}, -1)\) стає коротким вектором, який BKZ намагається знайти.

Двоїста атака

Використовує двоїсту ґратку для відрізнення вибірок MLWE від рівномірних за допомогою статистики. Будує багато коротких векторів у двоїстій ґратці для виконання розрізнювача.

Вибір q = 3329

Будучи простим і позбавленим спеціальної алгебраїчної структури, він запобігає специфічним алгебраїчним атакам. Немає малих множників або простих співвідношень, які можна було б використовувати.

9.4 Рівні безпеки NIST

NIST визначив 5 рівнів. ML-KEM охоплює рівні 1, 3 і 5:

Схема Рівень NIST Класична безпека Квантова безпека
ML-KEM-512 1 (AES-128) ~118 біт ~100 біт
ML-KEM-768 3 (AES-192) ~178 біт ~164 біт
ML-KEM-1024 5 (AES-256) ~230 біт ~218 біт

Рекомендація: ML-KEM-768 пропонує оптимальний баланс безпеки та продуктивності для більшості застосувань. ML-KEM-1024 призначений для систем з дуже високою критичністю.

Порівняння з класичною криптографією

Основна вартість — більший розмір (~37× порівняно з ECDH), але він залишається прийнятним для сучасних рукостискань TLS.

9.6 Атаки по побічних каналах і безпечні реалізації

Правильна реалізація може бути вразливою, якщо вона витікає інформацію через час виконання (атаки за часом) або споживання енергії.

Постійний час (Constant-Time - CT)

Всі операції повинні мати постійний час, незалежно від секретних даних. Критичний приклад у Decaps:

// НЕбезпечно (змінний час):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Безпечно (постійний час):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF якщо рівні, 0x00 якщо різні
K = ct_select(mask, K_good, K_reject);     // вибір CT без розгалужень

Критичні області для CT у ML-KEM

  • Семплювання \(B_\eta\): додавання бітів без умовних розгалужень.
  • NTT: операції "метелик" повинні завжди виконуватися, навіть якщо результат не змінюється.
  • Перевірка шифртексту: використання ct_memcmp.

Еталонні реалізації

  • pqclean: переносимі реалізації CT.
  • liboqs: оптимізації AVX2 з перевіреними властивостями CT.
