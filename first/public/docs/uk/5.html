5.1 Від LWE до MLWE: мотивація

Класичний LWE та його вартість

У файлі 04 ми бачили стандартний LWE: дано \(m\) вибірок \((\mathbf{a}_i, b_i)\) з \(\mathbf{a}_i \in \mathbb{Z}_q^n\) і \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), знайти \(\mathbf{s}\). Задача складна, але має високу практичну вартість:

  • Публічний ключ (матриця \(A \in \mathbb{Z}_q^{m \times n}\)) має розмір \(O(n^2)\): для \(n = 1024\) і \(q = 3329\) це було б понад 2 МБ.
  • Множення матриці на вектор \(A \cdot \mathbf{s}\) коштує \(O(n^2)\) множень.

RLWE: занадто жорсткий

Ring-LWE переносить операції в кільце \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Один поліном \(a \in R_q\) замінює всю матрицю, зменшуючи публічний ключ до \(O(n)\).

Але RLWE має дуже специфічну алгебраїчну структуру, яку деякі дослідники вважають потенційно експлуатованою (хоча у 2024 році не відомо жодної практичної атаки).

MLWE: оптимальний компроміс

Module-LWE узагальнює обидва підходи, використовуючи матрицю \(k \times k\) поліномів у \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Для \(k = 1\): зводиться до RLWE
  • Для \(k \to \infty\) (поліноми степеня 0): зводиться до класичного LWE

Параметр \(k\) дозволяє калібрувати безпеку та продуктивність незалежно від \(n\).

Варіант Публічний ключ Безпека Гнучкість
LWE \(O(n^2)\) висока низька
RLWE \(O(n)\) середня низька
MLWE \(O(k \cdot n)\) регулюється через \(k\) висока

5.2 Формальне визначення MLWE

Робочий простір

Задано параметри:

  • \(n = 256\): степінь циклотомічного полінома
  • \(q = 3329\): простий модуль
  • \(k \in \{2, 3, 4\}\): розмірність модуля
  • \(\chi\): розподіл шуму (центрований біноміальний розподіл \(B_\eta\))

Базове кільце — \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Розподіл MLWE

Нехай \(\mathbf{s} \in R_q^k\) — секретний вектор поліномів, кожен з коефіцієнтами, вибраними з \(\chi\).

Екземпляр MLWE — це пара:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{де} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

з \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Розрізнювальна задача MLWE

Вхід: \((\mathbf{A}, \mathbf{t})\) де:

  • або \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (розподіл MLWE), або
  • \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) рівномірне

Мета: розрізнити два випадки з незнехтуваною перевагою.

Пошукова задача MLWE

Вхід: \((\mathbf{A}, \mathbf{t})\) з \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Мета: знайти \(\mathbf{s}\).

Редукція Регева (адаптована для MLWE) показує, що пошукова задача обчислювально еквівалентна розрізнювальній задачі, і обидві принаймні такі ж складні, як GapSVP на ґратках високої розмірності.

5.3 Розподіл шуму в ML-KEM

Центрований біноміальний розподіл \(B_\eta\)

У ML-KEM шум не гауссівський, а центрований біноміальний. Для семплювання одного коефіцієнта з \(B_\eta\):

  1. Вибрати \(2\eta\) рівномірних бітів: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Повернути \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

Результат — ціле число в \([-\eta, \eta]\).

Розподіл ймовірностей для η = 2:

Значення Ймовірність
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Чому не справжній гауссівський?

Дискретний гауссівський теоретично оптимальний, але його семплювання за постійний час (стійке до атак за часом) складне. Центрований біноміальний:

  • має скінченний носій → немає крайніх випадків
  • семплюється лише за допомогою операцій над бітами → тривіально постійний час
  • статистично невідрізняний від гауссівського для відомих атак

5.4 Семплювання в ML-KEM

CBD: Центрований біноміальний розподіл

ML-KEM використовує центрований біноміальний розподіл \(B_\eta\) для генерації малих помилок і секретів. Цей розподіл ефективний і не потребує семплювання з відхиленням.

Функція SamplePolyCBD(σ, b, η)

Вхід: зерно σ ∈ {0,1}^256, nonce b, параметр η
Вихід: поліном f ∈ R_q з коефіцієнтами в [-η, η]

1. байти = PRF(σ, b)       // SHAKE256, генерує 64·η байт
2. Для j = 0 до 255:
     a = sum(бітів[2ηj .. 2ηj+η-1])   // підрахунок одиниць у першій групі
     b = sum(бітів[2ηj+η .. 2ηj+2η-1]) // підрахунок одиниць у другій групі
     f[j] = a - b                     // різниця з центром у 0
3. Повернути f

Для \(\eta=2\) коефіцієнти знаходяться в \(\{-2, -1, 0, 1, 2\}\). Для \(\eta=3\) — в \(\{-3, \ldots, 3\}\).

SampleNTT: Рівномірне семплювання

Для генерації публічної матриці \(\mathbf{A}\) потрібні рівномірні коефіцієнти в \(\mathbb{Z}_q\). Використовується семплювання з відхиленням на виході SHAKE128.

Функція SampleNTT(stream)

Вхід: потік байтів з XOF (SHAKE128)
Вихід: поліном з рівномірними коефіцієнтами в [0, q-1]

коефіцієнти = []
поки len(коефіцієнти) < 256:
    // Прочитати 3 байти для генерації 2 значень-кандидатів
    b0, b1, b2 = next_3_bytes(stream)

    // Об'єднати біти для формування двох 12-бітних чисел
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2

    // Прийняти тільки якщо вони < q (3329)
    якщо d1 < q:
        коефіцієнти.append(d1)
    якщо d2 < q і len(коефіцієнти) < 256:
        коефіцієнти.append(d2)

повернути коефіцієнти

Цей метод гарантує ідеальний рівномірний розподіл, відкидаючи значення поза діапазоном.

5.5 Складність: чому MLWE важкий

Редукція найгіршого випадку до середнього

Найважливіша властивість LWE/MLWE — редукція найгіршого випадку до середнього:

Якщо існує ефективний алгоритм, який розв'язує MLWE для незнехтуваної частки випадкових екземплярів, то існує ефективний алгоритм для розв'язання GapSVP (наближеної версії SVP) на будь-якій ґратці в найгіршому випадку.

Ця редукція (Регев 2005, адаптована Пейкертом 2009 і Бракескі та ін. для MLWE) виняткова: більшість криптографічних задач мають лише редукції середнього випадку до середнього.

На практиці: злам MLWE на випадкових екземплярах настільки ж складний, як розв'язання SVP у найгіршому випадку → криптографічні припущення дуже сильні.

Відсутність структури, експлуатованої квантовими комп'ютерами

Алгоритм Шора використовує структуру абелевої групи задач факторизації та дискретного логарифма: існує періодична групова дія, яку QFT може виявити.

MLWE не має цієї структури:

  • Немає періодичності для використання
  • Немає природної абелевої групи для застосування QFT
  • Найкращі квантові алгоритми (засновані на квантових блуканнях або QRAM) дають не більше ніж поліноміальне прискорення, а не експоненційне

5.6 Від MLWE до PKE: конструктивна ідея

Як побудувати систему шифрування з MLWE? Інтуїція елегантна.

Аналогія з Діффі-Геллманом

У DH публічний ключ — \(g^s\): легко обчислити, важко інвертувати.
У MLWE публічний ключ — \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): легко обчислити, важко інвертувати.

Схема шифрування (типу Регева)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Публічний ключ: \((\mathbf{A}, \mathbf{t})\).
Приватний ключ: \(\mathbf{s}\).

Encrypt (повідомлення \(m \in \{0,1\}\), закодоване як \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Шифртекст: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Аналіз:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{малий шум}} + \mu \approx \mu \]

Шум малий → округлення відновлює \(\mu\) і, отже, \(m\).

Поліноміальна версія (реальний MLWE)

У ML-KEM кожен скаляр стає поліномом у \(R_q\), а операції — поліноміальними множеннями. Механізм ідентичний, але множення виконуються в кільці:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

де \(\circ\) — множення в \(R_q\) (поліноміальне, прискорюване NTT).

5.7 Повний числовий приклад

Використовуємо іграшкові параметри: \(n = 4\), \(q = 17\), \(k = 2\), малі коефіцієнти в \(\{-1, 0, 1\}\).

Поліноми знаходяться в \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), тому степеня \(\leq 3\).

Вихідні дані

Публічна матриця \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

з \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Секрет \(\mathbf{s} = (s_0, s_1)^T\) з \(s_0 = 1 - X\), \(s_1 = X^2\).

Помилка \(\mathbf{e} = (e_0, e_1)^T\) з \(e_0 = 1\), \(e_1 = -X\).

Обчислення t = As + e

Компонент t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Зводимо \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Результат: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (другий компонент обчислюється аналогічно).

Ключове спостереження

Противник, який бачить \((\mathbf{A}, \mathbf{t})\), повинен знайти \((\mathbf{s}, \mathbf{e})\). Навіть з цими маленькими числами задача вже нетривіальна: не можна використовувати метод Гауса (помилка порушує лінійність), а простір пошуку експоненційний за реальною розмірністю ML-KEM.

5.8 Чому параметри ML-KEM саме такі

\(n = 256\)

  • Має бути степенем 2 (для ефективного NTT)
  • Поліном \(X^{256}+1\) має бути незвідним над \(\mathbb{Z}_q\): це так, якщо \(q \equiv 1 \pmod{512}\)
  • \(256\) балансує безпеку та продуктивність: \(n = 128\) було б занадто небезпечно, \(n = 512\) занадто повільно

\(q = 3329\)

  • Має бути простим (щоб \(\mathbb{Z}_q\) було полем)
  • Має задовольняти \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Мають існувати корені 256-го степеня з одиниці: гарантується попередньою умовою
  • Має бути якомога меншим (компактні ключі) при збереженні бюджету шуму
  • \(3329\) — це просте число, що задовольняє всі умови з достатнім запасом для шуму

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): рівень NIST 1, еквівалент доквантового AES-128
  • \(k = 3\) (ML-KEM-768): рівень 3, еквівалент AES-192, рекомендується для загального використання
  • \(k = 4\) (ML-KEM-1024): рівень 5, еквівалент AES-256, для систем з високою критичністю

\(\eta_1, \eta_2 \in \{2, 3\}\)

Шум має бути:

  • достатньо великим, щоб задача MLWE була складною
  • достатньо малим, щоб гарантувати, що дешифрування не дає збоїв (бюджет шуму)

Збільшення \(\eta\) підвищує безпеку, але також збільшує ймовірність помилки дешифрування. Значення \(\eta_1 = 2, \eta_2 = 2\) для ML-KEM-768 є оптимальною точкою.
