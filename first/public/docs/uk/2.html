2.1 Проблема обміну ключами

Аліса хоче безпечно спілкуватися з Бобом по відкритому каналу. Для використання AES потрібен спільний ключ. Як вони можуть його встановити, щоб Єва (яка все чує) його не дізналася?

Ця проблема залишалася нерозв'язаною століттями. Рішення прийшло в 1976 році з Діффі та Геллманом, а в 1977 році з Райвестом, Шаміром і Адлеманом (RSA).

Ключова ідея: існують математичні операції, які легкі в один бік і важкі в інший.

Легка операція Важка операція
Помножити два великі прості числа: \(p \cdot q = n\) Розкласти \(n\) на множники, щоб знайти \(p\) та \(q\)
Обчислити \(g^x \bmod p\) Знайти \(x\) за \(g^x \bmod p\) (дискретний логарифм)
Додати точку на еліптичній кривій \(k\) разів: \(kP\) Знайти \(k\) за \(kP\) (ECDLP)

2.2 RSA

Генерація ключів

  1. Обрати два великі прості числа \(p\) та \(q\) (зазвичай по 2048+ біт кожне)
  2. Обчислити \(n = p \cdot q\)
  3. Обчислити \(\phi(n) = (p-1)(q-1)\)
  4. Обрати \(e\) таке, що \(\gcd(e, \phi(n)) = 1\) (зазвичай \(e = 65537\))
  5. Обчислити \(d = e^{-1} \bmod \phi(n)\)

Публічний ключ: \((n, e)\)
Приватний ключ: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) мають бути знищені.

Шифрування та дешифрування

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Чому це працює: за теоремою Ейлера, \(M^{\phi(n)} \equiv 1 \pmod{n}\), тому \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Числовий приклад (з маленькими числами, лише для навчання)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(тому що } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Зашифруємо \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Дешифруємо:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA як KEM

RSA-KEM (спрощено):

  1. Боб випадково генерує \(r \leftarrow \{1, \ldots, n-1\}\)
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (симетричний ключ)
  4. Відправляє \(C\) Алісі
  5. Аліса обчислює \(r = C^d \bmod n\), потім \(K = H(r)\)

2.3 Діффі-Геллман (DH)

Протокол

Публічні параметри: велике просте число \(p\) та генератор \(g\) групи \(\mathbb{Z}_p^*\).

Аліса
  1. Обирає секретне \(a\)
  2. Обчислює \(A = g^a \bmod p\)
A → ← B
Боб
  1. Обирає секретне \(b\)
  2. Обчислює \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Аліса обчислює: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Боб обчислює: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Результат: Обидва мають однаковий секретний ключ \(K\). Єва, яка бачить лише \(A\) та \(B\), не може обчислити \(K\) без розв'язання задачі дискретного логарифма.

2.4 Криптографія на еліптичних кривих (ECDH)

ECDH — це аналог DH на еліптичних кривих. Використовується в TLS 1.3 з кривою X25519.

Аліса
  1. Обирає секретне \(a\)
  2. Обчислює \(A = a \cdot G\)
A → ← B
Боб
  1. Обирає секретне \(b\)
  2. Обчислює \(B = b \cdot G\)
\[ \begin{aligned} \text{Аліса обчислює: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Боб обчислює: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Де \(G\) — генератор кривої. Безпека заснована на складності ECDLP (Elliptic Curve Discrete Logarithm Problem).

2.4 Криптографія на еліптичних кривих (ECC)

Що таке еліптичні криві

Еліптична крива над \(\mathbb{Z}_p\) — це множина точок \((x, y)\), що задовольняють рівняння:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

плюс спеціальна точка \(\mathcal{O}\), яка називається точкою на нескінченності.

На цих точках визначається операція додавання з властивостями групи.

Скалярне множення

Виходячи з додавання точок, визначається скалярне множення:

\(kP = P + P + \cdots + P \quad (k \text{ разів})\)

Обчислити \(kP\) з \(P\) та \(k\) легко (\(O(\log k)\) операцій). Обернена задача — знайти \(k\) за \(P\) та \(kP\) — це Задача дискретного логарифма на еліптичних кривих (ECDLP), обчислювально складна.

Переваги ECC перед RSA/DH

Еквівалентна безпека RSA/DH (біти n/p) ECC (біти ключа)
80 біт 1024 160
128 біт 3072 256
256 біт 15360 512

ECC пропонує набагато менші ключі при тій самій безпеці → більш ефективний.

ECDH (Elliptic Curve Diffie-Hellman)

Аліса Боб | | | обирає секретне a | обирає секретне b | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ спільний ключ K |

ECDH використовується в TLS 1.3 з кривою X25519 (curve25519 Бернштейна).

2.5 Класична безпека та квантові обмеження

Проти класичних комп'ютерів

Задачі, на яких ґрунтуються RSA та ECC, є субекспоненційними (не чисто експоненційними) для класичних комп'ютерів.

Найкращий класичний алгоритм для факторизації — General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

Для \(n\) розміром 2048 біт це потребує астрономічно довгого часу → безпечно на практиці.

Проти квантових комп'ютерів: алгоритм Шора

У 1994 році Пітер Шор показав, що квантовий комп'ютер може:

  • Розкласти на множники \(n\) за час \(O((\log n)^3)\)
  • Розв'язати DLP за час \(O((\log p)^3)\)
  • Розв'язати ECDLP за час \(O((\log p)^3)\)

Квантовий комп'ютер з достатньою кількістю кубітів зламає RSA-2048 за години або дні.

Детальний аналіз алгоритму Шора знаходиться у файлі 03 – Алгоритм Шора.

Відповідь: постквантова криптографія

Щоб продовжувати мати безпечну асиметричну криптографію в квантову еру, потрібні математичні задачі, для яких немає відомих ефективних квантових алгоритмів.

Задачі на ґратках (lattice), на яких заснований ML-KEM, задовольняють цю вимогу: найкращі відомі квантові алгоритми дають не більше ніж скромне прискорення порівняно з класичними алгоритмами.
