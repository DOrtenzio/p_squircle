5.1 От LWE к MLWE: мотивация

Классический LWE и его стоимость

В файле 04 мы видели стандартный LWE: даны \(m\) выборок \((\mathbf{a}_i, b_i)\) с \(\mathbf{a}_i \in \mathbb{Z}_q^n\) и \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), найти \(\mathbf{s}\). Задача трудная, но имеет высокую практическую стоимость:

  • Открытый ключ (матрица \(A \in \mathbb{Z}_q^{m \times n}\)) имеет размер \(O(n^2)\): для \(n = 1024\) и \(q = 3329\) это было бы более 2 МБ.
  • Умножение матрицы на вектор \(A \cdot \mathbf{s}\) стоит \(O(n^2)\) умножений.

RLWE: слишком жёсткий

Ring-LWE переносит операции в кольцо \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). Один полином \(a \in R_q\) заменяет всю матрицу, уменьшая открытый ключ до \(O(n)\).

Но RLWE имеет очень специфическую алгебраическую структуру, которую некоторые исследователи считают потенциально эксплуатируемой (хотя в 2024 году не известно ни одной практической атаки).

MLWE: оптимальный компромисс

Module-LWE обобщает оба подхода, используя матрицу \(k \times k\) полиномов в \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • Для \(k = 1\): сводится к RLWE
  • Для \(k \to \infty\) (полиномы степени 0): сводится к классическому LWE

Параметр \(k\) позволяет калибровать безопасность и производительность независимо от \(n\).

Вариант Открытый ключ Безопасность Гибкость
LWE \(O(n^2)\) высокая низкая
RLWE \(O(n)\) средняя низкая
MLWE \(O(k \cdot n)\) регулируется через \(k\) высокая

5.2 Формальное определение MLWE

Рабочее пространство

Заданы параметры:

  • \(n = 256\): степень циклотомического полинома
  • \(q = 3329\): простой модуль
  • \(k \in \{2, 3, 4\}\): размерность модуля
  • \(\chi\): распределение шума (центрированное биномиальное распределение \(B_\eta\))

Базовое кольцо — \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Распределение MLWE

Пусть \(\mathbf{s} \in R_q^k\) — секретный вектор полиномов, каждый с коэффициентами, выбранными из \(\chi\).

Экземпляр MLWE — это пара:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{где} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

с \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Решающая задача MLWE

Вход: \((\mathbf{A}, \mathbf{t})\) где:

  • либо \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (распределение MLWE), либо
  • \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) равномерное

Цель: различить два случая с непреодолимым преимуществом.

Поисковая задача MLWE

Вход: \((\mathbf{A}, \mathbf{t})\) с \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Цель: найти \(\mathbf{s}\).

Редукция Регева (адаптированная для MLWE) показывает, что поисковая задача вычислительно эквивалентна решающей задаче, и обе по крайней мере так же сложны, как GapSVP на решётках высокой размерности.

5.3 Распределение шума в ML-KEM

Центрированное биномиальное распределение \(B_\eta\)

В ML-KEM шум не гауссовский, а центрированный биномиальный. Для сэмплирования одного коэффициента из \(B_\eta\):

  1. Выбрать \(2\eta\) равномерных битов: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Вернуть \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

Результат — целое число в \([-\eta, \eta]\).

Распределение вероятностей для η = 2:

Значение Вероятность
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Почему не настоящий гауссовский?

Дискретный гауссовский теоретически оптимален, но его сэмплирование за постоянное время (устойчивое к атакам по времени) сложно. Центрированный биномиальный:

  • имеет конечный носитель → нет крайних случаев
  • сэмплируется только с помощью операций над битами → тривиально постоянное время
  • статистически неотличим от гауссовского для известных атак

5.4 Сэмплирование в ML-KEM

CBD: Центрированное биномиальное распределение

ML-KEM использует центрированное биномиальное распределение \(B_\eta\) для генерации малых ошибок и секретов. Это распределение эффективно и не требует сэмплирования с отклонением.

Функция SamplePolyCBD(σ, b, η)

Вход: зерно σ ∈ {0,1}^256, nonce b, параметр η
Выход: полином f ∈ R_q с коэффициентами в [-η, η]

1. байты = PRF(σ, b)       // SHAKE256, генерирует 64·η байт
2. Для j = 0 до 255:
     a = sum(битов[2ηj .. 2ηj+η-1])   // подсчёт единиц в первой группе
     b = sum(битов[2ηj+η .. 2ηj+2η-1]) // подсчёт единиц во второй группе
     f[j] = a - b                     // разность с центром в 0
3. Вернуть f

Для \(\eta=2\) коэффициенты находятся в \(\{-2, -1, 0, 1, 2\}\). Для \(\eta=3\) — в \(\{-3, \ldots, 3\}\).

SampleNTT: Равномерное сэмплирование

Для генерации публичной матрицы \(\mathbf{A}\) требуются равномерные коэффициенты в \(\mathbb{Z}_q\). Используется сэмплирование с отклонением на выходе SHAKE128.

Функция SampleNTT(stream)

Вход: поток байтов из XOF (SHAKE128)
Выход: полином с равномерными коэффициентами в [0, q-1]

коэффициенты = []
пока len(коэффициенты) < 256:
    // Прочитать 3 байта для генерации 2 значений-кандидатов
    b0, b1, b2 = next_3_bytes(stream)

    // Объединить биты для формирования двух 12-битных чисел
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2

    // Принять только если они < q (3329)
    если d1 < q:
        коэффициенты.append(d1)
    если d2 < q и len(коэффициенты) < 256:
        коэффициенты.append(d2)

вернуть коэффициенты

Этот метод гарантирует идеальное равномерное распределение, отбрасывая значения вне диапазона.

5.5 Трудность: почему MLWE сложен

Редукция наихудшего случая к среднему

Важнейшее свойство LWE/MLWE — редукция наихудшего случая к среднему:

Если существует эффективный алгоритм, решающий MLWE для непреодолимой доли случайных экземпляров, то существует эффективный алгоритм для решения GapSVP (приближённой версии SVP) на любой решётке в наихудшем случае.

Эта редукция (Регев 2005, адаптированная Пейкертом 2009 и Бракески и др. для MLWE) исключительна: большинство криптографических задач имеют только редукции среднего случая к среднему.

На практике: взлом MLWE на случайных экземплярах так же труден, как решение SVP в наихудшем случае → криптографические предположения очень сильны.

Отсутствие структуры, эксплуатируемой квантовыми компьютерами

Алгоритм Шора использует структуру абелевой группы задач факторизации и дискретного логарифма: существует периодическое групповое действие, которое QFT может обнаружить.

MLWE не имеет этой структуры:

  • Нет периодичности для использования
  • Нет естественной абелевой группы для применения QFT
  • Лучшие квантовые алгоритмы (основанные на квантовых блужданиях или QRAM) дают не более чем полиномиальное ускорение, а не экспоненциальное

5.6 От MLWE к PKE: конструктивная идея

Как построить систему шифрования из MLWE? Интуиция элегантна.

Аналогия с Диффи-Хеллманом

В DH открытый ключ — \(g^s\): легко вычислить, трудно инвертировать.
В MLWE открытый ключ — \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): легко вычислить, трудно инвертировать.

Схема шифрования (типа Регева)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Открытый ключ: \((\mathbf{A}, \mathbf{t})\).
Закрытый ключ: \(\mathbf{s}\).

Encrypt (сообщение \(m \in \{0,1\}\), закодированное как \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Шифртекст: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Анализ:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{малый шум}} + \mu \approx \mu \]

Шум мал → округление восстанавливает \(\mu\) и, следовательно, \(m\).

Полиномиальная версия (реальный MLWE)

В ML-KEM каждый скаляр становится полиномом в \(R_q\), а операции — полиномиальными умножениями. Механизм идентичен, но умножения выполняются в кольце:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

где \(\circ\) — умножение в \(R_q\) (полиномиальное, ускоряемое NTT).

5.7 Полный числовой пример

Используем игрушечные параметры: \(n = 4\), \(q = 17\), \(k = 2\), малые коэффициенты в \(\{-1, 0, 1\}\).

Полиномы находятся в \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), поэтому степени \(\leq 3\).

Исходные данные

Публичная матрица \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

с \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Секрет \(\mathbf{s} = (s_0, s_1)^T\) с \(s_0 = 1 - X\), \(s_1 = X^2\).

Ошибка \(\mathbf{e} = (e_0, e_1)^T\) с \(e_0 = 1\), \(e_1 = -X\).

Вычисление t = As + e

Компонент t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Приводим \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Результат: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (второй компонент вычисляется аналогично).

Ключевое наблюдение

Противник, видящий \((\mathbf{A}, \mathbf{t})\), должен найти \((\mathbf{s}, \mathbf{e})\). Даже с этими маленькими числами задача уже нетривиальна: нельзя использовать метод Гаусса (ошибка нарушает линейность), а пространство поиска экспоненциально по реальной размерности ML-KEM.

5.8 Почему параметры ML-KEM именно такие

\(n = 256\)

  • Должна быть степенью 2 (для эффективного NTT)
  • Полином \(X^{256}+1\) должен быть неприводимым над \(\mathbb{Z}_q\): это так, если \(q \equiv 1 \pmod{512}\)
  • \(256\) балансирует безопасность и производительность: \(n = 128\) было бы слишком небезопасно, \(n = 512\) слишком медленно

\(q = 3329\)

  • Должно быть простым (чтобы \(\mathbb{Z}_q\) было полем)
  • Должно удовлетворять \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Должно существовать корни 256-й степени из единицы: гарантируется предыдущим условием
  • Должно быть как можно меньше (компактные ключи) при сохранении бюджета шума
  • \(3329\) — это простое число, удовлетворяющее всем условиям с достаточным запасом для шума

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): уровень NIST 1, эквивалент доквантового AES-128
  • \(k = 3\) (ML-KEM-768): уровень 3, эквивалент AES-192, рекомендуется для общего использования
  • \(k = 4\) (ML-KEM-1024): уровень 5, эквивалент AES-256, для систем с высокой критичностью

\(\eta_1, \eta_2 \in \{2, 3\}\)

Шум должен быть:

  • достаточно большим, чтобы задача MLWE была трудной
  • достаточно малым, чтобы гарантировать, что расшифровка не даёт сбоев (бюджет шума)

Увеличение \(\eta\) повышает безопасность, но также увеличивает вероятность ошибки расшифровки. Значения \(\eta_1 = 2, \eta_2 = 2\) для ML-KEM-768 являются оптимальной точкой.
