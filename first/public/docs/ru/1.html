1.1 Что такое симметричная криптография

В системе симметричной криптографии отправитель и получатель используют один и тот же ключ \(K\) для шифрования и дешифрования.

\(\text{Отправитель: } C = \text{Enc}(K, M)\)

\(\text{Получатель: } M = \text{Dec}(K, C)\)

Основное преимущество: эффективность. AES-256 на современном оборудовании достигает десятков ГБ/с.

Недостаток: требуется защищённый канал для обмена \(K\) до начала общения. Это именно та проблема, которую решают KEM.

Безопасность симметричной криптографии против квантовой

Квантовые компьютеры не взламывают AES. Алгоритм Гровера даёт квадратичное ускорение при поиске ключа, но:

  • AES-128: эффективная безопасность со 128 бит падает до ~64 бит → недостаточно
  • AES-256: эффективная безопасность с 256 бит падает до ~128 бит → всё ещё безопасно

Поэтому FIPS 203 (ML-KEM) генерирует 256-битные ключи, предназначенные для использования с AES-256.

1.2 AES: Advanced Encryption Standard

AES — это блочный шифр: он берёт блок из 128 бит и ключ (\(K\)), и выдаёт 128 зашифрованных бит.

Внутренняя структура

AES организует 128 входных бит в матрицу \(4 \times 4\) байтов. Затем применяет \(r\) раундов (10, 12 или 14 в зависимости от размера ключа), каждый из которых состоит из четырёх преобразований:

Преобразование Цель
SubBytes Нелинейная замена через S-Box (устойчивость к дифференциальному криптоанализу)
ShiftRows Циклический сдвиг строк (рассеивание)
MixColumns Линейная комбинация столбцов (рассеивание)
AddRoundKey XOR с подключом текущего раунда

Расписание ключей

Исходный ключ (\(K\) размером 128, 192 или 256 бит) расширяется в \(r+1\) подключей, по одному на каждый раунд.

AES-128: ключ 128 бит, 10 раундов

AES-192: ключ 192 бит, 12 раундов

AES-256: ключ 256 бит, 14 раундов

Безопасность

Лучшая известная атака на AES-128 требует \(2^{126.1}\) операций (Biryukov & Khovratovich, 2009) – по сути полный перебор.

1.3 Режимы работы

AES шифрует блок из 128 бит. Но реальные сообщения длиннее. Режимы работы определяют, как применять AES многократно.

ECB (Electronic Codebook) – не использовать

Каждый блок шифруется независимо. Одинаковые блоки дают одинаковый шифртекст → теряется структура открытого текста.

CBC (Cipher Block Chaining)

Каждый блок открытого текста XORится с шифртекстом предыдущего блока перед шифрованием. Требуется случайный IV (Initialization Vector).

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Безопаснее ECB, но не параллелизуется при шифровании.

CTR (Counter Mode) – рекомендуется

Генерирует ключевой поток путём шифрования инкрементируемого счётчика. Открытый текст XORится с ключевым потоком.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Параллелизуется как при шифровании, так и при дешифровании. Превращает AES в поточный шифр.

GCM (Galois/Counter Mode) – используется в TLS 1.3

Сочетает CTR с MAC на основе полей Галуа. Обеспечивает конфиденциальность и аутентичность.

1.4 Аутентификация и AEAD

Конфиденциальности недостаточно: злоумышленник может изменить шифртекст так, что получатель этого не заметит. Требуется аутентичность.

MAC (Message Authentication Code)

MAC — это функция \(\text{MAC}(K, M) \to \tau\), где \(\tau\) — тег аутентичности. Только тот, кто знает \(K\), может генерировать и проверять \(\tau\).

AEAD (Authenticated Encryption with Associated Data)

Объединяет шифрование и аутентификацию в одном примитиве:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) или \(\perp\) (если тег недействителен)

AAD (Additional Authenticated Data) — это данные, которые аутентифицируются, но не шифруются (например, заголовки пакетов).

AES-256-GCM — это стандартная схема AEAD, используемая в TLS 1.3 и в качестве симметричного шифра после KEM.

1.5 Роль в контексте PQC

Полный ML-KEM в реальном использовании работает так:

Алиса Боб | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Сообщение) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Сообщение = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Защищённая связь |

Ключ \(K\), полученный от ML-KEM (32 байта), не используется напрямую как ключ AES, а выводится с помощью KDF (Key Derivation Function), такой как HKDF, для разделения различных контекстов.

Практические размеры (ML-KEM-768 + AES-256-GCM)

Компонент Размер
Публичный ключ ML-KEM 1184 байт
Шифртекст ML-KEM 1088 байт
Общий секрет → ключ AES 32 байта
Накладные расходы AEAD (тег GCM) 16 байт
