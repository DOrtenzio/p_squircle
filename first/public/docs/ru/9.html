9.1 Модели безопасности

IND-CPA (Неразличимость при атаке на основе выбранного открытого текста)

В этой модели противник:

  1. Получает открытый ключ \(ek\)
  2. Выбирает два сообщения \(m_0, m_1\)
  3. Получает шифртекст одного из них (выбранного случайно)
  4. Должен угадать, какое сообщение было зашифровано

Схема безопасна, если: \(\Pr[\text{угадает}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (базовый компонент шифрования) является IND-CPA при предположении MLWE.

IND-CCA2 (Неразличимость при адаптивной атаке на основе выбранного шифртекста)

Как CPA, но противник также может запрашивать оракул расшифровки на любых шифртекстах (кроме шифртекста-вызова). Эта модель отражает реальные атаки (как Блейхенбахер), где активный противник отправляет специально сконструированные сообщения и наблюдает ответы.

ML-KEM является IND-CCA2. Это уровень, требуемый для безопасного KEM в реальных протоколах, таких как TLS или SSH.

ROM vs. QROM

Доказательства безопасности используют идеализированные модели для хеш-функций:

  • ROM (Random Oracle Model): хеши являются идеальными случайными оракулами.
  • QROM (Quantum Random Oracle Model): квантовый противник может запрашивать оракул в суперпозиции.

Современные доказательства для преобразования FO (Фуджисаки-Окамото), используемого в ML-KEM, гарантируют безопасность в QROM, что необходимо против квантовых противников.

9.2 Как измеряется сложность MLWE

Безопасность как стоимость атаки

Не существует абсолютного доказательства того, что MLWE сложен. Безопасность оценивается путём вычисления стоимости лучшего известного алгоритма атаки. Безопасность в \(\lambda\) бит означает, что атака требует около \(2^\lambda\) операций.

Параметры

Сложность зависит от:

  • \(n = 256\) (размерность полинома, фиксирована)
  • \(k \in \{2, 3, 4\}\) (размерность модуля)
  • \(q = 3329\) (простой модуль)
  • \(\eta \in \{2, 3\}\) (амплитуда шума)

Оценщик решёток

Стандартным инструментом является Lattice Estimator Альбрехта и др. Для ML-KEM-768:

Атака Оценочная стоимость (бит)
Прямая атака (BKZ) ~178 бит
Двойственная атака ~175 бит
Комбинаторная > 200 бит

Запас безопасности велик по сравнению с целью 128 бит классической/квантовой безопасности.

9.3 Основные атаки на решётки

BKZ (Block Korkine-Zolotarev)

Это лучший общий алгоритм для нахождения коротких векторов. Он разбивает решётку на блоки размера \(\beta\) и решает SVP локально. Сложность: \(2^{O(\beta \log \beta)}\). Для ML-KEM-768 \(\beta \approx 430\).

Прямая атака (uSVP)

Сводит MLWE к задаче короткого вектора в расширенной решётке, содержащей открытый ключ и шифртекст. Секретный вектор \((\mathbf{s}, \mathbf{e}, -1)\) становится коротким вектором, который BKZ пытается найти.

Двойственная атака

Использует двойственную решётку для отличия выборок MLWE от равномерных с помощью статистики. Строит много коротких векторов в двойственной решётке для выполнения различителя.

Выбор q = 3329

Будучи простым и лишённым специальной алгебраической структуры, он предотвращает специфические алгебраические атаки. Нет малых множителей или простых соотношений, которые можно было бы использовать.

9.4 Уровни безопасности NIST

NIST определил 5 уровней. ML-KEM охватывает уровни 1, 3 и 5:

Схема Уровень NIST Классическая безопасность Квантовая безопасность
ML-KEM-512 1 (AES-128) ~118 бит ~100 бит
ML-KEM-768 3 (AES-192) ~178 бит ~164 бит
ML-KEM-1024 5 (AES-256) ~230 бит ~218 бит

Рекомендация: ML-KEM-768 предлагает оптимальный баланс безопасности и производительности для большинства применений. ML-KEM-1024 предназначен для систем с очень высокой критичностью.

Сравнение с классической криптографией

Схема Открытый ключ Квантовая безопасность
RSA-3072 384 B ❌ Уязвим
ECDH X25519 32 B ❌ Уязвим

Основная стоимость — больший размер (~37× по сравнению с ECDH), но он остаётся приемлемым для современных рукопожатий TLS.

9.6 Атаки по побочным каналам и безопасные реализации

Правильная реализация может быть уязвима, если она泄露 информацию через время выполнения (атаки по времени) или потребление энергии.

Постоянное время (Constant-Time - CT)

Все операции должны иметь постоянное время, независимо от секретных данных. Критический пример в Decaps:

// НЕбезопасно (переменное время):
if (memcmp(c, c_prime, len) == 0) { 
    K = K_good; 
} else { 
    K = K_reject; 
}

// Безопасно (постоянное время):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF если равны, 0x00 если разные
K = ct_select(mask, K_good, K_reject);     // выбор CT без ветвлений

Критические области для CT в ML-KEM

  • Сэмплирование \(B_\eta\): сложение битов без условных ветвлений.
  • NTT: операции "бабочка" должны всегда выполняться, даже если результат не меняется.
  • Проверка шифртекста: использование ct_memcmp.

Эталонные реализации

  • pqclean: переносимые реализации CT.
  • liboqs: оптимизации AVX2 с проверенными свойствами CT.
