2.1 Проблема обмена ключами

Алиса хочет безопасно общаться с Бобом по открытому каналу. Для использования AES нужен общий ключ. Как они могут его установить, чтобы Ева (которая всё слышит) его не узнала?

Эта проблема оставалась нерешённой веками. Решение пришло в 1976 году с Диффи и Хеллманом, а в 1977 году с Райвестом, Шамиром и Адлеманом (RSA).

Ключевая идея: существуют математические операции, которые легки в одну сторону и трудны в другую.

Лёгкая операция Трудная операция
Умножить два больших простых числа: \(p \cdot q = n\) Факторизовать \(n\), чтобы найти \(p\) и \(q\)
Вычислить \(g^x \bmod p\) Найти \(x\) по \(g^x \bmod p\) (дискретный логарифм)
Сложить точку на эллиптической кривой \(k\) раз: \(kP\) Найти \(k\) по \(kP\) (ECDLP)

2.2 RSA

Генерация ключей

  1. Выбрать два больших простых числа \(p\) и \(q\) (обычно по 2048+ бит каждое)
  2. Вычислить \(n = p \cdot q\)
  3. Вычислить \(\phi(n) = (p-1)(q-1)\)
  4. Выбрать \(e\) такое, что \(\gcd(e, \phi(n)) = 1\) (обычно \(e = 65537\))
  5. Вычислить \(d = e^{-1} \bmod \phi(n)\)

Публичный ключ: \((n, e)\)
Частный ключ: \((n, d)\)
\(p\), \(q\), \(\phi(n)\) должны быть уничтожены.

Шифрование и дешифрование

\[ C = M^e \bmod n \]
\[ M = C^d \bmod n \]

Почему это работает: по теореме Эйлера, \(M^{\phi(n)} \equiv 1 \pmod{n}\), поэтому \(M^{ed} = M^{1 + k\phi(n)} \equiv M \pmod{n}\).

Числовой пример (с маленькими числами, только для обучения)

\(p = 61, \quad q = 53, \quad n = 3233\)

\(\phi(n) = 60 \cdot 52 = 3120\)

\(e = 17, \quad d = 2753 \quad \text{(потому что } 17 \cdot 2753 \equiv 1 \pmod{3120}\text{)}\)

Зашифруем \(M = 65\):

\(C = 65^{17} \bmod 3233 = 2790\)

Дешифруем:

\(M = 2790^{2753} \bmod 3233 = 65 \quad \checkmark\)

RSA как KEM

RSA-KEM (упрощённо):

  1. Боб случайно генерирует \(r \leftarrow \{1, \ldots, n-1\}\)
  2. \(C = r^e \bmod n\)
  3. \(K = H(r)\) (симметричный ключ)
  4. Отправляет \(C\) Алисе
  5. Алиса вычисляет \(r = C^d \bmod n\), затем \(K = H(r)\)

2.3 Диффи-Хеллман (DH)

Протокол

Публичные параметры: большое простое число \(p\) и генератор \(g\) группы \(\mathbb{Z}_p^*\).

Алиса
  1. Выбирает секретное \(a\)
  2. Вычисляет \(A = g^a \bmod p\)
A → ← B
Боб
  1. Выбирает секретное \(b\)
  2. Вычисляет \(B = g^b \bmod p\)
\[ \begin{aligned} \text{Алиса вычисляет: } & K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p \\ \text{Боб вычисляет: } & K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p \end{aligned} \]

Результат: Оба имеют одинаковый секретный ключ \(K\). Ева, которая видит только \(A\) и \(B\), не может вычислить \(K\) без решения задачи дискретного логарифма.

2.4 Криптография на эллиптических кривых (ECDH)

ECDH — это аналог DH на эллиптических кривых. Используется в TLS 1.3 с кривой X25519.

Алиса
  1. Выбирает секретное \(a\)
  2. Вычисляет \(A = a \cdot G\)
A → ← B
Боб
  1. Выбирает секретное \(b\)
  2. Вычисляет \(B = b \cdot G\)
\[ \begin{aligned} \text{Алиса вычисляет: } & K = a \cdot B = a(b \cdot G) = ab \cdot G \\ \text{Боб вычисляет: } & K = b \cdot A = b(a \cdot G) = ba \cdot G \end{aligned} \]

Где \(G\) — генератор кривой. Безопасность основана на сложности ECDLP (Elliptic Curve Discrete Logarithm Problem).

2.4 Криптография на эллиптических кривых (ECC)

Что такое эллиптические кривые

Эллиптическая кривая над \(\mathbb{Z}_p\) — это множество точек \((x, y)\), удовлетворяющих уравнению:

\[ y^2 \equiv x^3 + ax + b \pmod{p} \]

плюс специальная точка \(\mathcal{O}\), называемая точкой на бесконечности.

На этих точках определяется операция сложения со свойствами группы.

Скалярное умножение

Исходя из сложения точек, определяется скалярное умножение:

\(kP = P + P + \cdots + P \quad (k \text{ раз})\)

Вычислить \(kP\) из \(P\) и \(k\) легко (\(O(\log k)\) операций). Обратная задача – найти \(k\) по \(P\) и \(kP\) – это Задача дискретного логарифма на эллиптических кривых (ECDLP), вычислительно сложная.

Преимущества ECC перед RSA/DH

Эквивалентная безопасность RSA/DH (биты n/p) ECC (биты ключа)
80 бит 1024 160
128 бит 3072 256
256 бит 15360 512

ECC предлагает гораздо меньшие ключи при той же безопасности → более эффективен.

ECDH (Elliptic Curve Diffie-Hellman)

Алиса Боб | | | выбирает секретное a | выбирает секретное b | A = aG | B = bG | | | ------------ A ------------->| | | | <------------ B -------------| | | | K = aB = abG | K = bA = abG | | | ✓ общий ключ K |

ECDH используется в TLS 1.3 с кривой X25519 (curve25519 Бернштейна).

2.5 Классическая безопасность и квантовые ограничения

Против классических компьютеров

Задачи, на которых основаны RSA и ECC, являются субэкспоненциальными (не чисто экспоненциальными) для классических компьютеров.

Лучший классический алгоритм для факторизации — General Number Field Sieve (GNFS):

\[ O\!\left(\exp\!\left(\left(\frac{64}{9}\right)^{1/3} (\ln n)^{1/3} (\ln \ln n)^{2/3}\right)\right) \]

Для \(n\) размером 2048 бит это требует астрономически большого времени → безопасно на практике.

Против квантовых компьютеров: алгоритм Шора

В 1994 году Питер Шор показал, что квантовый компьютер может:

  • Факторизовать \(n\) за время \(O((\log n)^3)\)
  • Решить DLP за время \(O((\log p)^3)\)
  • Решить ECDLP за время \(O((\log p)^3)\)

Квантовый компьютер с достаточным количеством кубитов взломает RSA-2048 за часы или дни.

Детальный анализ алгоритма Шора находится в файле 03 – Алгоритм Шора.

Ответ: постквантовая криптография

Чтобы продолжать иметь безопасную асимметричную криптографию в квантовую эру, нужны математические задачи, для которых нет известных эффективных квантовых алгоритмов.

Задачи на решётках (lattice), на которых основан ML-KEM, удовлетворяют этому требованию: лучшие известные квантовые алгоритмы дают не более чем скромное ускорение по сравнению с классическими алгоритмами.
