1.1 대칭키 암호화란 무엇인가?

대칭키 암호화 시스템에서 송신자와 수신자는 암호화와 복호화에 동일한 키 \(K\)를 사용합니다.

\(\text{송신자: } C = \text{Enc}(K, M)\)

\(\text{수신자: } M = \text{Dec}(K, C)\)

주요 장점: 효율성. 최신 하드웨어의 AES-256은 수십 GB/s에 달합니다.

단점: 통신 전에 \(K\)를 교환할 안전한 채널이 필요합니다. 이것이 바로 KEM이 해결하는 문제입니다.

대칭키 암호화의 안전성 vs. 양자

양자 컴퓨터는 AES를 깨지 않습니다. 그로버 알고리즘은 키 검색에서 제곱근 가속을 제공하지만:

  • AES-128: 128비트 보안이 약 64비트로 감소 → 불충분
  • AES-256: 256비트 보안이 약 128비트로 감소 → 여전히 안전

이 때문에 FIPS 203(ML-KEM)은 AES-256과 함께 사용하기 위한 256비트 키를 생성합니다.

1.2 AES: 고급 암호화 표준

AES는 블록 암호입니다: 128비트 블록과 키(\(K\))를 받아 128비트 암호문을 생성합니다.

내부 구조

AES는 128비트 입력을 바이트의 \(4 \times 4\) 행렬로 구성합니다. 그런 다음 키 크기에 따라 \(r\)개의 라운드(10, 12 또는 14)를 적용하며, 각 라운드는 네 가지 변환으로 구성됩니다:

변환 목적
SubBytes S-박스를 통한 비선형 치환 (차분 암호분석 저항성)
ShiftRows 행 순환 이동 (확산)
MixColumns 열 선형 결합 (확산)
AddRoundKey 현재 라운드 서브키와 XOR

키 스케줄

원본 키(\(K\), 128, 192 또는 256비트)는 각 라운드마다 하나씩 \(r+1\)개의 서브키로 확장됩니다.

AES-128: 128비트 키, 10라운드

AES-192: 192비트 키, 12라운드

AES-256: 256비트 키, 14라운드

보안

AES-128에 대해 알려진 최고의 공격은 \(2^{126.1}\) 연산이 필요합니다(Biryukov & Khovratovich, 2009) – 본질적으로 무차별 대입입니다.

1.3 운영 모드

AES는 128비트 블록을 암호화합니다. 하지만 실제 메시지는 더 깁니다. 운영 모드는 AES를 반복적으로 적용하는 방법을 정의합니다.

ECB (전자 코드북) – 사용 금지

각 블록이 독립적으로 암호화됩니다. 동일한 블록은 동일한 암호문을 생성 → 평문 구조를 노출합니다.

CBC (암호 블록 체인)

각 평문 블록은 암호화 전에 이전 블록의 암호문과 XOR됩니다. 무작위 IV(초기화 벡터)가 필요합니다.

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

ECB보다 안전하지만, 암호화 시 병렬화가 불가능합니다.

CTR (카운터 모드) – 권장

증분 카운터를 암호화하여 키 스트림을 생성합니다. 평문은 키 스트림과 XOR됩니다.

\[ C_i = P_i \oplus E_K(\text{논스} \| i) \]

암호화와 복호화 모두 병렬화 가능합니다. AES를 스트림 암호로 변환합니다.

GCM (갈루아/카운터 모드) – TLS 1.3에서 사용

CTR을 갈루아 필드 기반 MAC과 결합합니다. 기밀성 및 무결성을 제공합니다.

1.4 인증 및 AEAD

기밀성만으로는 충분하지 않습니다: 공격자가 수신자 모르게 암호문을 수정할 수 있습니다. 무결성이 필요합니다.

MAC (메시지 인증 코드)

MAC은 \(\text{MAC}(K, M) \to \tau\) 함수로, \(\tau\)는 인증 태그입니다. \(K\)를 아는 사람만 \(\tau\)를 생성하고 검증할 수 있습니다.

AEAD (연관 데이터를 포함한 인증된 암호화)

암호화와 인증을 하나의 프리미티브로 결합합니다:

\(\text{Enc: } (K, \text{논스}, \text{AAD}, \text{평문}) \to (\text{암호문}, \text{태그})\)

\(\text{Dec: } (K, \text{논스}, \text{AAD}, \text{암호문}, \text{태그}) \to \text{평문}\) 또는 \(\perp\) (태그가 유효하지 않은 경우)

AAD(추가 인증 데이터)는 인증되지만 암호화되지 않은 데이터입니다(예: 패킷 헤더).

AES-256-GCM은 TLS 1.3에서 사용되고 KEM 후 대칭 암호로 사용되는 표준 AEAD 방식입니다.

1.5 PQC 맥락에서의 역할

실제 사용에서 완전한 ML-KEM은 다음과 같이 작동합니다:

앨리스 밥 | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, 메시지) | | | | <----- (C, C_data, 논스, 태그) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | 메시지 = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ 안전한 통신 |

ML-KEM(32바이트)이 생성한 키 \(K\)는 AES 키로 직접 사용되지 않고, 다른 컨텍스트를 분리하기 위해 KDF(키 파생 함수)인 HKDF로 파생됩니다.

실제 크기 (ML-KEM-768 + AES-256-GCM)

구성 요소 크기
ML-KEM 공개 키 1184 바이트
ML-KEM 암호문 1088 바이트
공유 비밀 → AES 키 32 바이트
AEAD 오버헤드 (GCM 태그) 16 바이트
