9.1 Veiligheidsmodellen

IND-CPA (Indistinguishability under Chosen Plaintext Attack)

In dit model kan een aanvaller:

  1. De publieke sleutel \(ek\) ontvangen
  2. Twee berichten \(m_0, m_1\) kiezen
  3. De versleuteling van een van beide ontvangen (willekeurig gekozen)
  4. Moet raden welk bericht is versleuteld

Het schema is veilig als: \(\Pr[\text{raadt}] \leq 1/2 + \text{negl}(\lambda)\).

K-PKE (het basisversleutelingscomponent) is IND-CPA onder de MLWE-aanname.

IND-CCA2 (Indistinguishability under Adaptive Chosen Ciphertext Attack)

Zoals CPA, maar de aanvaller kan ook een ontsleutelingsorakel raadplegen over elke versleutelde tekst (behalve de uitdaging). Dit model vangt echte aanvallen (zoals Bleichenbacher) waarbij een actieve aanvaller speciaal geconstrueerde berichten stuurt en de antwoorden observeert.

ML-KEM is IND-CCA2. Dit is het vereiste niveau voor een veilige KEM in echte protocollen zoals TLS of SSH.

ROM vs. QROM

Veiligheidsbewijzen gebruiken geïdealiseerde modellen voor hashfuncties:

  • ROM (Random Oracle Model): hashes zijn perfecte willekeurige orakels.
  • QROM (Quantum Random Oracle Model): de kwantumaanvaller kan het orakel in superpositie raadplegen.

Moderne bewijzen voor de FO-transformatie (Fujisaki-Okamoto) die in ML-KEM wordt gebruikt, garanderen veiligheid in het QROM, essentieel tegen kwantumaanvallers.

9.2 Hoe de moeilijkheid van MLWE wordt gemeten

Veiligheid als kosten van de aanval

Er is geen absoluut bewijs dat MLWE moeilijk is. De veiligheid wordt geschat door de kosten van het beste bekende aanvalsalgoritme te berekenen. Een veiligheid van \(\lambda\) bits betekent dat de aanval ongeveer \(2^\lambda\) bewerkingen vereist.

De parameters

De moeilijkheid hangt af van:

  • \(n = 256\) (polynoomgrootte, vast)
  • \(k \in \{2, 3, 4\}\) (module-dimensie)
  • \(q = 3329\) (priemmodulus)
  • \(\eta \in \{2, 3\}\) (ruisamplitude)

Lattice Estimator

Het standaardhulpmiddel is de Lattice Estimator van Albrecht et al. Voor ML-KEM-768:

Aanval Geschatte kosten (bits)
Primal attack (BKZ) ~178 bits
Dual attack ~175 bits
Combinatorisch > 200 bits

De veiligheidsmarge is ruim in vergelijking met het doel van 128 bits klassiek/kwantum.

9.3 Belangrijkste aanvallen op roosters

BKZ (Block Korkine-Zolotarev)

Dit is het beste algemene algoritme voor het vinden van korte vectoren. Het verdeelt het rooster in blokken van grootte \(\beta\) en lost lokaal SVP op. Complexiteit: \(2^{O(\beta \log \beta)}\). Voor ML-KEM-768 is \(\beta \approx 430\).

Primal attack (uSVP)

Reduceert MLWE tot een kort-vectorprobleem in een uitgebreid rooster dat de publieke sleutel en de versleutelde tekst bevat. De geheime vector \((\mathbf{s}, \mathbf{e}, -1)\) wordt een korte vector die BKZ probeert te vinden.

Dual attack

Maakt gebruik van het duale rooster om MLWE-monsters te onderscheiden van uniforme monsters via statistieken. Het construeert veel korte vectoren in het duale rooster om de onderscheider uit te voeren.

Keuze van q = 3329

Omdat het priem is en geen speciale algebraïsche structuur heeft, voorkomt het specifieke algebraïsche aanvallen. Er zijn geen kleine factoren of eenvoudige relaties die kunnen worden misbruikt.

9.4 NIST-veiligheidsniveaus

NIST heeft 5 niveaus gedefinieerd. ML-KEM bestrijkt de niveaus 1, 3 en 5:

Schema NIST-niveau Klassieke veiligheid Kwantumveiligheid
ML-KEM-512 1 (AES-128) ~118 bits ~100 bits
ML-KEM-768 3 (AES-192) ~178 bits ~164 bits
ML-KEM-1024 5 (AES-256) ~230 bits ~218 bits

Aanbeveling: ML-KEM-768 biedt de optimale balans tussen veiligheid en prestaties voor de meeste toepassingen. ML-KEM-1024 is gereserveerd voor systemen met een zeer hoge kritikaliteit.

Vergelijking met Klassieke Cryptografie

Schema Publieke sleutel Kwantumveiligheid
RSA-3072 384 B ❌ Kwetsbaar

ML-KEM-768 1184 B ✅ 164+ bits

De belangrijkste kostenpost is de grotere omvang (~37× vergeleken met ECDH), maar dit blijft aanvaardbaar voor moderne TLS-handshakes.

9.6 Nevenkanalen en veilige implementaties

Een correcte implementatie kan kwetsbaar zijn als deze informatie lekt via de uitvoeringstijd (timingaanvallen) of het energieverbruik.

Tijdconstant (CT)

Alle bewerkingen moeten een constante tijd hebben, onafhankelijk van de geheime gegevens. Kritiek voorbeeld in Decaps:

// ONVEILIG (variabele tijd):
if (memcmp(c, c_prime, len) == 0) {
    K = K_good;
} else {
    K = K_reject;
}

// Veilig (constante tijd):
uint8_t mask = ct_memcmp(c, c_prime, len); // 0xFF als gelijk, 0x00 als verschillend
K = ct_select(mask, K_good, K_reject);     // CT-selectie zonder vertakkingen

Kritieke gebieden voor CT in ML-KEM

  • \(B_\eta\)-bemonstering: sommen van bits zonder conditionele vertakkingen.
  • NTT: vlinderoperaties moeten altijd worden uitgevoerd, zelfs als het resultaat niet verandert.
  • Verificatie van versleutelde tekst: gebruik van ct_memcmp.

Referentie-implementaties

  • pqclean: draagbare CT-implementaties.
  • liboqs: AVX2-optimalisaties met geverifieerde CT-eigenschappen.
