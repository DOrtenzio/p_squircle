1.1 Wat is symmetrische cryptografie?

In een symmetrisch cryptosysteem gebruiken de zender en de ontvanger de zelfde sleutel \(K\) om te versleutelen en te ontsleutelen.

\(\text{Zender: } C = \text{Enc}(K, M)\)

\(\text{Ontvanger: } M = \text{Dec}(K, C)\)

Belangrijkste voordeel: efficiëntie. AES-256 op moderne hardware haalt tientallen GB/s.

Nadeel: er is een veilig kanaal nodig om \(K\) vooraf uit te wisselen. Dit is precies het probleem dat KEM's oplossen.

Veiligheid van symmetrische cryptografie versus kwantum

Kwantumcomputers breken AES niet. Het algoritme van Grover biedt een kwadratische versnelling bij het zoeken naar de sleutel, maar:

  • AES-128: effectieve veiligheid van 128 bits daalt naar ~64 bits → onvoldoende
  • AES-256: effectieve veiligheid van 256 bits daalt naar ~128 bits → nog steeds veilig

Daarom produceert FIPS 203 (ML-KEM) sleutels van 256 bits, bedoeld voor gebruik met AES-256.

1.2 AES: Advanced Encryption Standard

AES is een blokversleuteling: het neemt een blok van 128 bits en een sleutel (\(K\)), en produceert 128 bits aan versleutelde tekst.

Interne structuur

AES organiseert de 128 ingangsbits als een \(4 \times 4\) matrix van bytes. Vervolgens past het \(r\) rondes toe (10, 12 of 14, afhankelijk van de sleutelgrootte), elk bestaande uit vier transformaties:

Transformatie Doel
SubBytes Niet-lineaire substitutie via S-Box (bestand tegen differentiële cryptanalyse)
ShiftRows Cyclische rotatie van rijen (diffusie)
MixColumns Lineaire combinatie van kolommen (diffusie)
AddRoundKey XOR met de subsleutel van de huidige ronde

Key schedule

De oorspronkelijke sleutel (\(K\) van 128, 192 of 256 bits) wordt uitgebreid tot \(r+1\) subsleutels, één voor elke ronde.

AES-128: sleutel 128 bits, 10 rondes

AES-192: sleutel 192 bits, 12 rondes

AES-256: sleutel 256 bits, 14 rondes

Veiligheid

De beste bekende aanval op AES-128 vereist \(2^{126.1}\) bewerkingen (Biryukov & Khovratovich, 2009) – in wezen brute kracht.

1.3 Modussen van operatie

AES versleutelt een blok van 128 bits. Maar echte berichten zijn langer. De modussen van operatie bepalen hoe AES herhaaldelijk wordt toegepast.

ECB (Electronic Codebook) – niet gebruiken

Elk blok wordt onafhankelijk versleuteld. Identieke blokken produceren identieke versleutelde tekst → de structuur van de platte tekst gaat verloren.

CBC (Cipher Block Chaining)

Elk platte-tekstblok wordt ge-XORd met de versleutelde tekst van het vorige blok voordat het wordt versleuteld. Vereist een willekeurige IV (Initialization Vector).

\[ C_i = E_K(P_i \oplus C_{i-1}) \]

Veiliger dan ECB, maar niet paralleliseerbaar bij versleuteling.

CTR (Counter Mode) – aanbevolen

Genereert een sleutelstroom door een oplopende teller te versleutelen. De platte tekst wordt ge-XORd met de sleutelstroom.

\[ C_i = P_i \oplus E_K(\text{nonce} \| i) \]

Paralleliseerbaar bij zowel versleuteling als ontsleuteling. Maakt van AES een stroomversleuteling.

GCM (Galois/Counter Mode) – gebruikt in TLS 1.3

Combineert CTR met een MAC gebaseerd op Galois-velden. Biedt zowel vertrouwelijkheid als authenticiteit.

1.4 Authenticatie en AEAD

Vertrouwelijkheid is niet voldoende: een aanvaller zou de versleutelde tekst kunnen wijzigen zonder dat de ontvanger het merkt. Er is authenticiteit nodig.

MAC (Message Authentication Code)

Een MAC is een functie \(\text{MAC}(K, M) \to \tau\) waarbij \(\tau\) de authenticiteitstag is. Alleen wie \(K\) kent, kan \(\tau\) genereren en verifiëren.

AEAD (Authenticated Encryption with Associated Data)

Combineert versleuteling en authenticatie in één primitief:

\(\text{Enc: } (K, \text{nonce}, \text{AAD}, \text{plaintext}) \to (\text{ciphertext}, \text{tag})\)

\(\text{Dec: } (K, \text{nonce}, \text{AAD}, \text{ciphertext}, \text{tag}) \to \text{plaintext}\) of \(\perp\) (als de tag ongeldig is)

AAD (Additional Authenticated Data) zijn gegevens die worden geverifieerd maar niet versleuteld (bijv. pakketheaders).

AES-256-GCM is de standaard AEAD-versleuteling die wordt gebruikt in TLS 1.3 en als symmetrische versleuteling na een KEM.

1.5 Rol in de PQC-context

Een volledige ML-KEM in de praktijk werkt als volgt:

Alice Bob | | | KeyGen() → (pk, sk) | | | | ------------ pk ----------------->| | | | Encaps(pk) → (K, C) | | | | K_enc = HKDF(K, "enc") | | K_mac = HKDF(K, "mac") | | C_data = AES-256-GCM(K_enc, Bericht) | | | | <----- (C, C_data, nonce, tag) --| | | | Decaps(sk, C) → K | | K_enc = HKDF(K, "enc") | | Bericht = AES-256-GCM-Dec(K_enc, C_data) | | | | ✓ Veilige communicatie |

De door ML-KEM geproduceerde sleutel \(K\) (32 bytes) wordt niet rechtstreeks als AES-sleutel gebruikt, maar wordt afgeleid met een KDF (Key Derivation Function) zoals HKDF om verschillende contexten te scheiden.

Praktische afmetingen (ML-KEM-768 + AES-256-GCM)

Component Grootte
ML-KEM publieke sleutel 1184 bytes
ML-KEM versleutelde tekst 1088 bytes
Gedeeld geheim → AES-sleutel 32 bytes
AEAD-overhead (GCM-tag) 16 bytes
