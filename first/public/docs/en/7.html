The engine that makes ML-KEM practically usable

7.1 The problem: multiplying polynomials

In ML-KEM, the fundamental operations involve polynomial multiplications in the ring \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

Naïve multiplication

Two polynomials of degree \(n-1\) are multiplied using the schoolbook algorithm with complexity \(O(n^2)\).

  • For \(n = 256\): about \(256^2 = 65536\) multiplications per single product.
  • In ML-KEM-768 (\(k=3\)), a single Encaps operation requires dozens of polynomial products → millions of multiplications with the naïve method.

With NTT

Complexity drops to \(O(n \log n)\):

\[ 256 \cdot 8 = 2048 \text{ operations per product} \]

Speedup: ~32×. On optimized hardware, ML-KEM-768 takes less than 1 ms.

7.2 Fourier transforms and DFT

The convolution theorem

The Fourier transform turns a convolution (like polynomial multiplication) into a pointwise product:

\[ f * g \;\longleftrightarrow\; \hat{f} \cdot \hat{g} \]

Procedure:

  1. Compute \(\hat{f} = \text{DFT}(f)\) and \(\hat{g} = \text{DFT}(g)\)
  2. Multiply pointwise: \(\hat{h}_i = \hat{f}_i \cdot \hat{g}_i\)
  3. Inverse transform: \(h = \text{DFT}^{-1}(\hat{h})\)

If DFT and DFT-1 cost \(O(n \log n)\) (via FFT), the entire multiplication costs \(O(n \log n)\).

Fast Fourier Transform (FFT)

The Cooley-Tukey algorithm (1965) computes the DFT using a recursive structure:

\[ \text{DFT}[f] = \left(\text{DFT}[f_{\text{even}}], \; \text{DFT}[f_{\text{odd}}]\right) \text{ combined with twiddle factors} \]

The problem: Standard FFT uses complex numbers (floating point), which introduce rounding errors and non-constant timing, making them unsuitable for cryptography.

7.3 NTT: DFT in the modular world

The idea

The NTT (Number Theoretic Transform) is the DFT applied over \(\mathbb{Z}_q\) instead of \(\mathbb{C}\). Instead of using complex roots of unity \(e^{2\pi i k/n}\), it uses primitive roots of unity in \(\mathbb{Z}_q\).

Primitive roots of unity modulo q

An element \(\omega \in \mathbb{Z}_q\) is a primitive \(n\)-th root of unity if:

\[ \omega^n \equiv 1 \pmod{q} \quad \text{and} \quad \omega^k \not\equiv 1 \pmod{q} \text{ for } 0 < k < n \]

Necessary condition: \(n \mid (q-1)\) (i.e., \(n\) must divide \(q-1\)).

In ML-KEM:

  • \(q = 3329\), \(n = 256\)
  • Verification: \(3329 - 1 = 3328 = 256 \cdot 13\) \(\checkmark\)
  • Therefore, 256-th roots of unity modulo 3329 exist.
  • The primitive root used in FIPS 203: \(\omega = 17\) (since \(17^{128} \equiv -1 \pmod{3329}\), the root used for negacyclic NTT is \(\zeta = 17\)).

NTT definition

\[ \hat{f}_i = \text{NTT}(f)_i = \sum_{j=0}^{n-1} f_j \cdot \omega^{ij} \pmod{q} \]

Inverse NTT:

\[ f_j = \text{NTT}^{-1}(\hat{f})_j = n^{-1} \sum_{i=0}^{n-1} \hat{f}_i \cdot \omega^{-ij} \pmod{q} \]

where \(n^{-1} = 256^{-1} \bmod 3329 = 3303\).

Key properties

  • Exact: no rounding errors, everything in \(\mathbb{Z}_q\)
  • Efficient: \(O(n \log n)\) like FFT
  • Constant-time: implementable without branching on secret data (side-channel safe)

7.4 NTT in ML-KEM

Negacyclic NTT

In ML-KEM, the reduction is not modulo \(X^n - 1\) (cyclic), but modulo \(X^n + 1\) (negacyclic). In negacyclic convolution, the "wrapped" terms change sign. This requires a variant of the classical NTT with adjusted twiddle factors.

The NTT in FIPS 203 applies a pre-twisting with powers of \(\zeta = 17\):

\[ \tilde{f}_j = f_j \cdot \zeta^j \bmod q \quad \text{before classical NTT} \]

ML-KEM operations in the NTT domain

Once transformed, polynomials live in the NTT domain. Operations become elementary:

Operation In the NTT domain
Multiplication \(f \cdot g\) \(\hat{f}_i \cdot \hat{g}_i\) for each \(i\)
Sum \(f + g\) \(\hat{f}_i + \hat{g}_i\) for each \(i\)
Matrix-vector product \(A \cdot s\) \(k^2\) products and \(k^2\) pointwise sums

The public key \(A\) is generated and stored already in the NTT domain, avoiding recomputing the NTT each time.

Complete KeyGen flow

seed 
  │
  ├──► SHAKE128 ──► A_hat (already in NTT)
  │
  └──► Binomial sampling ──► s, e
         │              │
         ▼              ▼
     s_hat = NTT(s)   e_hat = NTT(e)
         │              │
         └──────┬───────┘
                ▼
     t_hat = A_hat * s_hat + e_hat
                │
                ▼
          Public Key (t_hat)

The output t_hat is the public key (already in NTT). The NTT-1 for \(t\) is avoided.

7.5 Simplified numerical example

Use \(n = 4\), \(q = 5\), \(\omega = 2\) (4-th root of 1 modulo 5: \(2^4 = 16 \equiv 1 \pmod 5\)).

Polynomials:

\[ f = 1 + 2X + 3X^2 + 4X^3 \quad \Rightarrow \quad \mathbf{f} = (1, 2, 3, 4) \]
\[ g = 1 + X + X^2 + X^3 \quad \Rightarrow \quad \mathbf{g} = (1, 1, 1, 1) \]

NTT of f:

  • \(\hat{f}_0 = 1 + 2 + 3 + 4 = 10 \equiv 0\)
  • \(\hat{f}_1 = 1 + 2 \cdot 2 + 3 \cdot 4 + 4 \cdot 8 = 49 \equiv 4\)
  • \(\hat{f}_2 = 1 + 2 \cdot 4 + 3 \cdot 16 + 4 \cdot 64 = 313 \equiv 3\)
  • \(\hat{f}_3 = 1 + 2 \cdot 8 + 3 \cdot 64 + 4 \cdot 512 = 2257 \equiv 2\)

NTT of g: \(\hat{g}_i = \sum_j \omega^{ij} \pmod 5\). For \(i=0\): \(4 \equiv 4\); for \(i \neq 0\): sum of roots \(= 0\).

Pointwise product: \(\hat{h}_i = \hat{f}_i \cdot \hat{g}_i \pmod 5\).

INTT of \(\hat{h}\): gives the product \(f \cdot g \bmod (X^4-1, 5)\).

Note: this example uses reduction modulo \(X^4-1\) (cyclic). ML-KEM uses \(X^n+1\) (negacyclic) with the variant described in section 7.4.

7.6 Implementation

Cooley-Tukey pseudocode for NTT

def ntt(f, q, omega):
    """
    Iterative in-place NTT (Cooley-Tukey).
    f: list of n coefficients in Z_q
    q: prime modulus
    omega: primitive n-th root of unity mod q
    """
    n = len(f)
    # bit-reversal permutation
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            f[i], f[j] = f[j], f[i]

    # butterfly operations
    length = 2
    while length <= n:
        w = pow(omega, n // length, q)
        for i in range(0, n, length):
            wn = 1
            for k in range(length // 2):
                u = f[i + k]
                v = f[i + k + length // 2] * wn % q
                f[i + k] = (u + v) % q
                f[i + k + length // 2] = (u - v) % q
                wn = wn * w % q
        length <<= 1
    return f

Reference implementation

FIPS 203 specifies the exact NTT implementation and the table of precomputed roots \(\zeta^{br(i)}\) (where \(br\) is the bit-reversal permutation).

Optimized implementations in assembly/SIMD are available in:

  • liboqs (C with AVX2)
  • pqclean (portable C)
  • kyber reference implementation (C)
