5.1 From LWE to MLWE: the motivation

Classical LWE and its cost

In 04 we saw standard LWE: given \(m\) samples \((\mathbf{a}_i, b_i)\) with \(\mathbf{a}_i \in \mathbb{Z}_q^n\) and \(b_i = \langle \mathbf{a}_i, \mathbf{s} \rangle + e_i\), find \(\mathbf{s}\). The problem is hard, but it has a high practical cost:

  • The public key (the matrix \(A \in \mathbb{Z}_q^{m \times n}\)) has size \(O(n^2)\): for \(n = 1024\) and \(q = 3329\) it would be over 2 MB.
  • The matrix-vector multiplication \(A \cdot \mathbf{s}\) costs \(O(n^2)\) multiplications.

RLWE: too rigid

Ring-LWE moves operations to the ring \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\). A single polynomial \(a \in R_q\) replaces the entire matrix, reducing the public key to \(O(n)\).

But RLWE has a very specific algebraic structure that some researchers consider potentially exploitable (although no practical attack is known as of 2024).

MLWE: the optimal compromise

Module-LWE generalizes both by using a \(k \times k\) matrix of polynomials in \(R_q\):

\[ \mathbf{A} \in R_q^{k \times k} \]
  • For \(k = 1\): reduces to RLWE
  • For \(k \to \infty\) (polynomials of degree 0): reduces to classical LWE

The parameter \(k\) allows calibrating security and performance independently of \(n\).

Variant Public key Security Flexibility
LWE \(O(n^2)\) high low
RLWE \(O(n)\) medium low
MLWE \(O(k \cdot n)\) adjustable with \(k\) high

5.2 Formal definition of MLWE

Working space

Fix the parameters:

  • \(n = 256\): degree of the cyclotomic polynomial
  • \(q = 3329\): prime modulus
  • \(k \in \{2, 3, 4\}\): module dimension
  • \(\chi\): noise distribution (centered binomial distribution \(B_\eta\))

The base ring is \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\).

MLWE distribution

Let \(\mathbf{s} \in R_q^k\) be a secret vector of polynomials, each with coefficients sampled from \(\chi\).

An MLWE instance is a pair:

\[ (\mathbf{A},\; \mathbf{t}) \quad \text{where} \quad \mathbf{A} \stackrel{\$}{\leftarrow} R_q^{k \times k},\quad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e} \]

with \(\mathbf{s}, \mathbf{e} \stackrel{\$}{\leftarrow} \chi^k\).

Decision MLWE problem

Input: \((\mathbf{A}, \mathbf{t})\) where:

  • either \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\) (MLWE distribution), or
  • either \(\mathbf{t} \stackrel{\$}{\leftarrow} R_q^k\) uniform

Goal: distinguish the two cases with non-negligible advantage.

Search MLWE problem

Input: \((\mathbf{A}, \mathbf{t})\) with \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Goal: find \(\mathbf{s}\).

Regev's reduction (adapted to MLWE) demonstrates that the search problem is computationally equivalent to the decision problem, and that both are at least as hard as GapSVP on high-dimensional lattices.

5.3 The noise distribution in ML-KEM

Centered binomial distribution \(B_\eta\)

In ML-KEM the noise is not Gaussian but centered binomial. To sample a single coefficient from \(B_\eta\):

  1. Sample \(2\eta\) uniform bits: \(a_1, \ldots, a_\eta, b_1, \ldots, b_\eta \in \{0,1\}\)
  2. Return \(\sum_{i=1}^{\eta} a_i - \sum_{i=1}^{\eta} b_i\)

The result is an integer in \([-\eta, \eta]\).

Probability distribution for η = 2:

Value Probability
\(-2\) \(1/16\)
\(-1\) \(4/16\)
\(0\) \(6/16\)
\(+1\) \(4/16\)
\(+2\) \(1/16\)

Why not true Gaussian?

Discrete Gaussian is theoretically optimal, but sampling it in constant-time (resistant to timing attacks) is complex. Centered binomial:

  • has finite support → no extreme cases
  • is sampled with only bit operations → trivially constant-time
  • is statistically indistinguishable from Gaussian for known attacks

Sampling in ML-KEM (the SamplePolyCBD function)

CBD_η(σ, b): Input: seed σ ∈ {0,1}^256, nonce b ∈ {0,1}^8 Output: polynomial f ∈ R_q with coefficients in [-η, η] bytes = PRF(σ, b) // SHAKE256, generates 64η bytes for j = 0..255: a = sum of bits in bytes at positions [2ηj .. 2ηj+η-1] b = sum of bits in bytes at positions [2ηj+η .. 2ηj+2η-1] f[j] = a - b return f

Each polynomial \(\mathbf{s}[i]\) and \(\mathbf{e}[i]\) is sampled with a different nonce, ensuring statistical independence.

5.4 Sampling in ML-KEM

CBD: Centered Binomial Distribution

ML-KEM uses a centered binomial distribution \(B_\eta\) to generate small errors and secrets. This distribution is efficient and does not require rejection sampling.

Function SamplePolyCBD(σ, b, η)

Input: seed σ ∈ {0,1}^256, nonce b, parameter η
Output: polynomial f ∈ R_q with coeff. in [-η, η]

1. bytes = PRF(σ, b)       // SHAKE256, generates 64·η bytes
2. For j = 0 to 255:
     a = sum(bits[2ηj .. 2ηj+η-1])   // count the 1s in the first group
     b = sum(bits[2ηj+η .. 2ηj+2η-1]) // count the 1s in the second group
     f[j] = a - b                     // difference centered on 0
3. Return f

For \(\eta=2\), coefficients are in \(\{-2, -1, 0, 1, 2\}\). For \(\eta=3\), in \(\{-3, \ldots, 3\}\).

SampleNTT: Uniform Sampling

To generate the public matrix \(\mathbf{A}\), uniform coefficients in \(\mathbb{Z}_q\) are needed. Rejection sampling is used on the output of SHAKE128.

Function SampleNTT(stream)

Input: byte stream from XOF (SHAKE128)
Output: polynomial with uniform coeff. in [0, q-1]

coefficients = []
while len(coefficients) < 256:
    // Read 3 bytes to generate 2 candidate values
    b0, b1, b2 = next_3_bytes(stream)
    
    // Combine bits to form two 12-bit numbers
    d1 = b0 + 256 * (b1 mod 16)
    d2 = floor(b1 / 16) + 16 * b2
    
    // Accept only if < q (3329)
    if d1 < q:
        coefficients.append(d1)
    if d2 < q and len(coefficients) < 256:
        coefficients.append(d2)

return coefficients

This method guarantees a perfect uniform distribution, discarding out-of-range values.

5.5 Hardness: why MLWE is difficult

Worst-case to average-case reduction

The most important property of LWE/MLWE is the worst-case to average-case reduction:

If there exists an efficient algorithm that solves MLWE for a non-negligible fraction of random instances, then there exists an efficient algorithm to solve GapSVP (the approximate version of SVP) on any lattice, in the worst case.

This reduction (Regev 2005, adapted by Peikert 2009 and Brakerski et al. for MLWE) is exceptional: most cryptographic problems only have average-case to average-case reductions.

In practice: breaking MLWE on random instances is as hard as solving SVP in the worst case → the cryptographic assumptions are extremely solid.

Absence of structure exploitable by quantum computers

Shor's algorithm exploits the abelian group structure of factorization and discrete logarithm problems: there is a periodic group action that the QFT can detect.

MLWE does not have this structure:

  • There is no periodicity to exploit
  • There is no natural abelian group on which to apply the QFT
  • The best quantum algorithms (based on quantum walks or QRAM) offer at most polynomial speedups, not exponential ones

5.6 From MLWE to a PKE: the constructive idea

How do you build an encryption system from MLWE? The intuition is elegant.

Analogy with Diffie-Hellman

In DH, the public key is \(g^s\): easy to compute, hard to invert.
In MLWE, the public key is \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\): easy to compute, hard to invert.

Encryption scheme (Regev-like)

KeyGen: \(\mathbf{s}, \mathbf{e} \leftarrow \chi^k \qquad \mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)

Public key: \((\mathbf{A}, \mathbf{t})\).
Private key: \(\mathbf{s}\).

Encrypt (message \(m \in \{0,1\}\), encoded as \(\mu = m \cdot \lfloor q/2 \rfloor\)):

\[ \mathbf{r}, \mathbf{e}_1 \leftarrow \chi^k, \quad e_2 \leftarrow \chi \]
\[ \mathbf{u} = \mathbf{A}^T\mathbf{r} + \mathbf{e}_1 \qquad v = \mathbf{t}^T\mathbf{r} + e_2 + \mu \]

Ciphertext: \((\mathbf{u}, v)\).

Decrypt: \(w = v - \mathbf{s}^T\mathbf{u}\)

Analysis:

\[ w = \mathbf{t}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T\mathbf{u} \]
\[ = (\mathbf{A}\mathbf{s})^T\mathbf{r} + \mathbf{e}^T\mathbf{r} + e_2 + \mu - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1) \]
\[ = \underbrace{\mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{A}^T\mathbf{r}}_{= 0} + \underbrace{\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1}_{\text{small noise}} + \mu \approx \mu \]

The noise is small → rounding recovers \(\mu\) and thus \(m\).

The polynomial version (real MLWE)

In ML-KEM, every scalar becomes a polynomial in \(R_q\), and operations are polynomial products. The mechanism is identical, but multiplications happen in the ring:

\[ \mathbf{t} = \mathbf{A} \circ \mathbf{s} + \mathbf{e} \in R_q^k \]

where \(\circ\) is multiplication in \(R_q\) (polynomial, accelerated by NTT).

5.7 Complete numerical example

We use toy parameters: \(n = 4\), \(q = 17\), \(k = 2\), small coefficients in \(\{-1, 0, 1\}\).

Polynomials are in \(R_{17} = \mathbb{Z}_{17}[X]/(X^4+1)\), so degree \(\leq 3\).

Starting data

Public matrix \(\mathbf{A} \in R_{17}^{2 \times 2}\):

\[ \mathbf{A} = \begin{pmatrix} a_{00} & a_{01} \\ a_{10} & a_{11} \end{pmatrix} \]

with \(a_{00} = 1 + 2X + 3X^2 + 4X^3\), \(a_{01} = 5 + X + 2X^2\), \(a_{10} = 3 + X^3\), \(a_{11} = 1 + X + X^2 + X^3\)

Secret \(\mathbf{s} = (s_0, s_1)^T\) with \(s_0 = 1 - X\), \(s_1 = X^2\).

Error \(\mathbf{e} = (e_0, e_1)^T\) with \(e_0 = 1\), \(e_1 = -X\).

Calculation of t = As + e

Component t0 = a00 s0 + a01 s1 + e0:

\[ a_{00} \cdot s_0 = (1 + 2X + 3X^2 + 4X^3)(1 - X) \]
\[ = 1 - X + 2X - 2X^2 + 3X^2 - 3X^3 + 4X^3 - 4X^4 \]

Reduce \(X^4 \equiv -1 \pmod{X^4+1}\):

\[ = 1 + X + X^2 + X^3 + 4 = 5 + X + X^2 + X^3 \pmod{17} \]
\[ a_{01} \cdot s_1 = (5 + X + 2X^2)(X^2) = 5X^2 + X^3 + 2X^4 \]
\[ \equiv 5X^2 + X^3 - 2 = -2 + 5X^2 + X^3 \equiv 15 + 5X^2 + X^3 \pmod{17} \]
\[ t_0 = (5 + X + X^2 + X^3) + (15 + 5X^2 + X^3) + 1 \]
\[ = 21 + X + 6X^2 + 2X^3 \equiv 4 + X + 6X^2 + 2X^3 \pmod{17} \]

Result: \(\mathbf{t} = (4 + X + 6X^2 + 2X^3,\ \ldots)^T\) (the second component is computed similarly).

Key observation

An adversary seeing \((\mathbf{A}, \mathbf{t})\) must find \((\mathbf{s}, \mathbf{e})\). Even with these small numbers, the problem is already non-trivial: they cannot use Gaussian elimination (the error breaks linearity) and the search space is exponential in ML-KEM's real dimension.

5.8 Why ML-KEM's parameters are what they are

\(n = 256\)

  • Must be a power of 2 (for efficient NTT)
  • The polynomial \(X^{256}+1\) must be irreducible over \(\mathbb{Z}_q\): it is if \(q \equiv 1 \pmod{512}\)
  • \(256\) balances security and performance: \(n = 128\) would be too insecure, \(n = 512\) too slow

\(q = 3329\)

  • Must be prime (for \(\mathbb{Z}_q\) field)
  • Must satisfy \(q \equiv 1 \pmod{256}\): \(3329 = 13 \cdot 256 + 1\) ✓
  • Must be such that 256th roots of unity exist: guaranteed by the condition above
  • Must be as small as possible (compact keys) while being compatible with the noise budget
  • \(3329\) is the first prime satisfying all conditions with enough margin for the noise

\(k \in \{2, 3, 4\}\)

  • \(k = 2\) (ML-KEM-512): NIST level 1, equivalent to pre-quantum AES-128
  • \(k = 3\) (ML-KEM-768): level 3, equivalent to AES-192, recommended for general use
  • \(k = 4\) (ML-KEM-1024): level 5, equivalent to AES-256, for high-criticality systems

\(\eta_1, \eta_2 \in \{2, 3\}\)

The noise must be:

  • large enough to make the MLWE problem hard
  • small enough to ensure that decryption does not fail (noise budget)

Increasing \(\eta\) increases security but also the probability of decryption error. The values \(\eta_1 = 2, \eta_2 = 2\) for ML-KEM-768 are the optimal point.
